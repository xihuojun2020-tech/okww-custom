# GameFrame v1.97.69 复核

本轮完成原生游戏包的配置维护、独立只读执行/耗时总览和当前Windows用户的系统定时界面。复用原备份、账号事务与任务计时，不把注册条目视为业务完成。未启动游戏、模拟器、真实系统计划任务或访问NAS。

## 修复与依据

| 实际路径 | 修复 | 依据与验证 |
|---|---|---|
| ConfigBackupService构造会恢复目录交换journal | prepare_data在共享锁前用独占锁完成恢复；共享owner不得恢复pending事务 | 真实EX/SH竞争、pending事务与序列预览变更检查 |
| 完整配置维护与配置子进程、账号/序列编辑及完成页账号读取并行 | 冻结管理写入口，检查在途操作，确认配置child退出后执行EX维护 | 停止失败不执行；在途拒绝；实际恢复后runtime/两个账号页重绑，复用完成页 |
| BackgroundOperation先发busy=False再回调 | 维护协调保持pending直到结果处理完成；关闭期间不重新启动配置child | 维护中关闭的真实Qt检查 |
| 磁盘恢复成功后runtime重载失败 | MaintenanceCommittedError保留committed事实，停用旧账号写入口并明确要求重开窗口 | 实际重载故障注入，不伪报回滚 |
| 配置进程started并不代表schema已加载，初次启动错误可在ctor内同步发生 | schema_changed仅真实成功get-schema发出；首次start排入下一Qt事件，生命周期失败明确通知 | 真实QProcess首次失败、版本不符、普通保存失败和成功重启 |
| 多worker共享数据目录 | 每PROCESS_SESSION独立状态文件，真实PID/create_time验证活性，用户明确选择worker | 多真实fixture进程；损坏状态JSON不得保留旧running假成功 |
| 总览退出仍有异步账号读取 | 停止刷新源并在leases内等待本进程Qt读取池实际结束 | 源码和安装payload的阻塞读取/早到stdin停止检查 |
| 定时页给backend传Manifest对象；已安装payload不包含核心 | 传包路径，工作目录使用实际gameframe核心目录 | 真实安装管理窗及Windows参数往返 |
| 共享安装的计划归属未包含Windows用户 | 前缀包含包、数据和用户；删除需确认准确计划，创建/更新显示结果 | 模拟COM和跨用户归属检查 |

## 修改范围与保护分支

新增检查对应外部JSON/ZIP状态、真实跨进程身份、磁盘事务确认、Windows计划任务归属或当前在途操作。内部对象继续依赖已有接口。备份清理如实返回完成与未完成；没有增加扫描、重试、自动网络操作或故障总次数关闭战斗。

Live观察失败只报告且清理自己的陈旧状态，原事件仍送达；每次服务重试绑定新context，关闭时清理自己的writer。全局暂停、服务偏好和单一输入owner规则保持现有合同。
