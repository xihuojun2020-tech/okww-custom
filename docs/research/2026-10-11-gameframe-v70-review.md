# GameFrame v1.97.70 代码复核

本阶段交付原生用户任务编辑、目录发现、配置与计划身份、实际执行和明确重载。脚本包导入导出与角色编辑继续迁移，不把此阶段视为总目标完成。

主代理核对源码存储、独立验证、核心定义解析、真实 Runtime 到包/Host 调用链、配置 JSONL 和 Qt 生命周期。运行 owner 代理独立复核管理页接线并修复请求 pending 与关闭协调；核心代理复核目录和执行定义契约。已有业务、设备与框架全量盘点和前两轮报告仍适用，本报告只记录新增边界。

## 已修复根因

- 用户目录默认配置经 Runtime 合并后进入 Host.after_init，覆盖用户已保存设置。通用目录 default_config 改为空，真实默认值保留在元数据和任务 Config；明确运行覆盖仍生效。没有修改其他游戏包依赖的通用默认值合并规则。
- 源码哈希相同但导出类改变时，只有 source_revision 无法识别执行定义变化。目录 revision 覆盖源码、导出类、能力和元数据；核心把本次解析的定义传给 context，实际包在输入前核对。
- 稳定 ID 与旧任务实例混用会让删除、改类名后的请求、延迟启用与实时状态指向旧对象。注册表和队列按稳定 ID 重新解析，配置名固定 UUID；删除保留配置和历史源码。
- 管理窗口可能在配置子进程仍写入时关闭或恢复数据。pending 纳入维护和退出等待，关闭时阻止新写；真实生命周期故障清除 pending 并报告错误。
- 磁盘发布成功而 owner 重载失败不能报告为未保存。响应分别保留 catalog_revision、applied=false 和旧 applied_revision，编辑页明确提示。
- 切换游戏包时，外部损坏目录会被解析器拒绝。启动器先清理上个包的任务选择，再显示错误并禁止启动，避免残留任务被误用于新包。

## 新增分支依据

源码/导出类/JSON 元数据、能力列表、相对目录路径、重复任务 ID 和历史源码完整性是外部输入边界；revision 冲突保护并发编辑和执行定义；无设备验证隔离现有配置写入。重载先构造候选再发布是保留运行注册表的要求。暂停/停止、服务偏好和输入释放沿用既有 owner 边界，没有增加无限自动扫描或无依据重试。

用户 Python 仍是可信代码，独立验证不是权限沙箱。普通任务错误或删除服务不调用 disable 保存关闭；内置自动战斗偏好保持。检查通过与真实游戏运行成功仍分别记录。
