# 每日任务中的周本（1.97.63）

自 1.43.01 起，手动“周本挑战”入口位于“任务”页。每日与多账号仍使用账号配置中的独立目标。

在“账号配置”中分别为每个账号选择“每周周本”；“无”关闭。旧账号缺少该字段时默认关闭，打开编辑草稿可选择十一个周本之一，保存走现有账号事务。使用稳定 Boss ID 和账号 UUID，改名、移动序列不清除进度。

1.88.02 增加限时提前开放的定序诸理之律。自动模式读取当前游戏列表首项，指定模式按名称寻找该目标；入口消失时保留待补检状态，不切换为其他周本。点击直接挑战后，只有匹配剧情提前到达提示才点击确认；按钮未识别时不点击背景列表，确认后验证所选周本详情，再沿用单人挑战和队伍入场流程。稳定确认剩余0/3时不进入挑战。

## 周期与体力

简体中文服务器按 UTC+8 每日 04:00 计算游戏日期，周一04:00开始新周。周一开始检查，未确认完成或因错误跳过后，周二至周六每次启动该账号每日任务继续补检，确认本周完成后不再重复。周日使用独立复检记录，即使此前完成仍重新读取游戏次数，仅查询，不补打。稳定识别0/3才通过；剩余1至3次或无法可靠读取时明确警示并停止当前前台任务，多账号停止整轮，不退登切下一个、不失败补跑。下次手动启动仍须复核，下一周自然进入新周期。跨刷新完成不记录成功，下次重新读取次数。

周本在清体力阶段优先于无音区、凝素领域和模拟领域。检查后刷新每日活跃度，普通体力任务重新读取余额。仅使用当前体力，不自动使用体力药或购买体力；余额不足时保留补检资格，其他每日任务继续。

## 结果与多账号

周一至周六以稳定读取游戏剩余0/3，或当前账号当前周三个真实确认领奖事件为完成依据，写入 `Weekly Boss Monday Check`；周日必须独立读取0/3，写入 `Weekly Boss Sunday Check`。初始已为零也写记录。战斗胜利、点击领奖、跨周累计和人工校正数都不作为本周完成证据。失败、部分领奖、未知结果都不写完成，未核验领取继续阻断。账号配置显示两个检查状态与最近结果，运行时复用现有账号UUID、完整性服务运行状态及领奖账本。

新版“刷取任务”有限周本目标按顺序满足材料累计需求；全部目标达标且游戏仍有本周次数时，继续领取游戏周本列表首项，不是用户的优先级1目标。保底领取保存在现有账号账本，不增加无关有限任务的计数。旧版“创建的周本目标已达标”完成记录升级后重新核验，保留账号配置及所有累计数据。明确关闭周本的账号继续关闭。

多账号与每日复用同一周本判断，包含新版刷取队列及队列修改：每日未完成跑完整流程；每日已完成但周本待检，仅通过 DailyTask 公共入口补检周本；两者完成才跳过。每账号每轮最多尝试一次，下次启动才再试。周中周本非致命失败不撤销每日完成，摘要列出周本待补检账号；周日失败立即终止，不修改此前已完成账号的记录。

用户停止、账号完整性异常交给原有中断流程。周中游戏进程或截图丢失交给原有恢复流程，普通周本异常只有恢复到大世界后才允许继续每日任务。周日无法完成查询直接停止，失败截图不可用也不能把停止信号转为补跑；不关闭自动战斗偏好。

## 实现接口与验证

`WeeklyBossTask.run_for_target(target_key)` 和独立任务共用执行包装，保留语言、分辨率校验与 finally 按键释放。账号传入目标不改写独立周本配置。`DailyTask.run_weekly_boss_only()` 仍经由完整账号绑定和输入保护。

回归覆盖刷新边界、周一补检／周日独立复检、零次与部分领奖、用户停止、跨刷新拒绝记录、多账号目标隔离、已完成日常仍补检、配置兼容。实机验收需在用户开启账号周本后完成；离线测试不能替代实际游戏验收。

2026-09-09：323 项聚焦回归通过，含 12 项新增集成测试；之后增加未来时间戳拒绝条件，12 项集成回归再次通过。五个语言目录的 PO 检查与 MO 编译通过。测试未操作实际游戏或消耗账号体力。
