# 每日任务中的周本（1.43.00）

自 1.43.01 起，手动“周本挑战”入口位于“任务”页。每日与多账号仍使用账号配置中的独立目标。

在“账号配置”中分别为每个账号选择“每周周本”；“无”关闭。旧账号缺少该字段时默认关闭，打开编辑草稿可选择十个周本之一，保存走现有账号事务。使用稳定 Boss ID 和账号 UUID，改名、移动序列不清除进度。

## 周期与体力

简体中文服务器按 UTC+8 每日 04:00 计算游戏日期。周一开始检查，周二至周六补检直至确认剩余 0/3。周日使用独立复检记录，即使周一已完成仍读取游戏次数。周日失败在当天后续启动时补检，下一周自然进入新周期。跨刷新完成不记录成功，下次重新读取次数。

周本在清体力阶段优先于无音区、凝素领域和模拟领域。检查后刷新每日活跃度，普通体力任务重新读取余额。仅使用当前体力，不自动使用体力药或购买体力；余额不足时保留补检资格，其他每日任务继续。

## 结果与多账号

只有游戏次数确认耗尽才写入 `Weekly Boss Monday Check` 或 `Weekly Boss Sunday Check`。初始已为零也写记录。失败、部分领奖、未知结果都不写完成。账号配置显示两个检查状态与最近结果，运行时保存至现有完整性服务的运行状态。

多账号把“每日已完成”和“周本待检”分别判断：每日未完成跑完整流程；每日已完成但周本待检，仅通过 DailyTask 公共入口补检周本；两者完成才跳过。每账号每轮最多尝试一次，下次启动才再试。周本非致命失败不撤销每日完成，摘要列出周本待补检账号。

用户停止、账号完整性异常、游戏进程或截图丢失交给原有中断／恢复流程。普通周本异常只有恢复到大世界后才允许继续每日任务。

## 实现接口与验证

`WeeklyBossTask.run_for_target(target_key)` 和独立任务共用执行包装，保留语言、分辨率校验与 finally 按键释放。账号传入目标不改写独立周本配置。`DailyTask.run_weekly_boss_only()` 仍经由完整账号绑定和输入保护。

回归覆盖刷新边界、周一补检／周日独立复检、零次与部分领奖、用户停止、跨刷新拒绝记录、多账号目标隔离、已完成日常仍补检、配置兼容。实机验收需在用户开启账号周本后完成；离线测试不能替代实际游戏验收。

2026-09-09：323 项聚焦回归通过，含 12 项新增集成测试；之后增加未来时间戳拒绝条件，12 项集成回归再次通过。五个语言目录的 PO 检查与 MO 编译通过。测试未操作实际游戏或消耗账号体力。
