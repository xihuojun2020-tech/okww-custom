# 自动战斗仅允许用户手动关闭：修改方案

日期：2026-09-30
状态：已实施于1.89.00，定向回归通过；真实游戏续战待使用端验收。详见 [实施记录](../reviews/2026-09-30-auto-combat-persistence.md)。

## 长期约束

自动战斗是程序的底层核心功能。用户开启后，普通异常、连续异常、其他任务失败、切号、切换任务、角色识别失败均不得自动取消开启状态。只有用户主动关闭自动战斗开关才能将该偏好设为关闭。程序重启恢复该偏好；禁止以异常为由保存关闭值。

开关开启表示持续提供自动战斗能力。地图、登录、过图、结算、无有效截图或输入窗口不可用时保持等待，恢复可战斗画面后自动续战。用户主动全局暂停与退出程序停止实际执行，保持自动战斗偏好；恢复程序后无需重新勾选。

## 已查明的现有行为

- src/task/AutoCombatTask.py 的 handle_execution_error 在 manual_keep_enabled 为 False 时返回 False，首次异常交由执行器关闭。
- set_enabled_from_ui 只有在此前自动关闭后重启时才激活 manual_keep_enabled；启动恢复及普通开启均不提供该保护。
- custom_ok/ok/task/TaskExecutor.py 在恢复钩子报错或未处理时调用 task.disable。
- BaseCombatTask.combat_once 被每日及副本任务直接调用，不能仅修改后台 AutoCombatTask 就宣称所有入口已覆盖。
- 当前执行器优先运行前台一次性任务；战斗输入必须由当前任务拥有，避免后台与每日、群声等任务同时发送按键。

这些是源码检查结论，不是本次上传日志的故障结论。本轮未审阅诊断 ZIP。

## 实施步骤

### 1. 开启偏好与运行状态分开

修改 AutoCombatTask 的启停入口，删除首次错误自动关闭、异常后重启才保护的分支。沿用已有配置 _enabled 表示用户偏好，异常恢复不改写该值。保留启用线程代次校验，用户关闭后旧线程不得重新开启。

审查框架 enable/disable、配置恢复、重置设置、停止当前任务的所有入口。内部结束一次运行仅释放输入和清理运行状态；显式用户关闭才保存关闭偏好。旧版本已经保存为关闭的值不能判断是否来自用户，因此迁移保留现有关闭值，用户开启后适用新规则。

### 2. 恢复常态化，执行器提供兜底

修改 AutoCombatTask.handle_execution_error 与执行器错误分支。普通异常默认进入恢复，恢复钩子自身失败仍不能自动关闭该任务。状态同步、日志和截图失败各自隔离，不能反过来关闭战斗。框架级截图或调度错误也纳入检查，防止错误发生在钩子覆盖范围外导致执行线程退出。

沿用任务持有输入追踪、原输入后端释放、单调时钟及非阻塞重试。短暂识别失败先快速复核，持续截图/窗口故障逐步增加等待间隔并设上限，永远不因达到重试次数上限关闭。释放失败时保留待释放记录，窗口恢复后继续释放，再恢复新动作。

### 3. 覆盖共用战斗循环

修改 BaseCombatTask.combat_once 的可恢复异常处理，并检查单账号每日、多账号每日、深塔、海墟、周本及群声调用路径。确认仍在同一场战斗时，清理错误角色缓存、重新识别队伍和当前角色，恢复轮转；正常结算后退出本次战斗，不把等待或异常标为胜利。

战斗外的导航、登录、领奖失败继续交给所属任务处理，保留自动战斗偏好。所有角色死亡进入原复苏/失败处理，不能对死亡画面持续发送技能。手动停止前台任务释放其输入，后台自动战斗在获得执行权后继续监测。

### 4. 保持唯一输入执行者

沿用当前单执行器结构。每日、副本运行时由其共用战斗循环执行；后台自动战斗不抢前台任务的输入。群声保持其专用场景判断和用户暂停行为；退出专用场景后清理活动状态，避免污染普通三人队。

不以本次保活修改重写角色技能轮转。连续角色动作异常必须显示故障并重建识别，不能伪装成正常持续普攻。

### 5. 状态、证据与维护规则

界面显示“已开启，等待战斗”“自动战斗中”“异常恢复中”“等待游戏窗口/截图恢复”“已手动关闭”。显示最近异常、恢复次数及等待原因；恢复成功清除连续异常计数。

首次或不同异常保存日志和可用截图，重复异常合并限频。证据统一写入 okww监控室；无法截图时保留文本证据，截图保存失败不打断恢复。

同步更新 docs/references/auto-combat-recovery.md、程序结构说明与项目 AGENTS.md，记录仅用户手动关闭的长期约束，替换旧的首次异常自动关闭规则。

## 验收要求

- 启动恢复开启、普通手动开启后首次异常均保持开启；连续异常超过旧上限仍继续恢复。
- 恢复函数、日志、状态同步、截图保存各自失败不关闭开关、不终止执行器。
- 窗口消失、无截图、过图后条件恢复能自动续战，等待时无盲目输入。
- 手动关闭立即生效，延迟启用线程及延迟恢复不得重新开启；重启保留用户偏好。
- 单账号每日、多账号每日及副本的共用战斗循环恢复一致；结算不误判、死亡不忙循环。
- 活动与普通战斗不并发输入；三人队恢复后核对角色轮转、技能与大招使用。
- 全局暂停和程序退出停止实际输入，恢复后保持原开关偏好。

定向更新 TestAutoCombatRecovery、执行器测试、TestFlatUI 和共用战斗循环相关测试。离线注入异常验证后，再用真实三人队测试临时失去窗口、恢复、手动关闭及任务切换；实机未完成时在报告中明确记录。
