# 自动冥歌海墟：使用与实现（1.85.01）

## 使用范围

入口在每周任务中，名称为「自动冥歌海墟」。正确名称是**冥歌海墟**，不是溟歌海墟。

先手动进入再生海域第7—11层中任一层，或「无尽湍渊」的「海墟详情」页，关闭预设侧栏与信物页，再启动任务。程序读取当前关卡，从当前关卡依次挑战至无尽湍渊；不从F2或海域地图导航，不强制回第7层。不刷分、不领奖，也不保证满星。需要简体中文、16:9、至少1280×720画面。出口沿用周本后台寻路，不需要物理鼠标转镜头。

提前在游戏中保存至少两支三人预设，尽量不重人。程序不改成员、不调顺序、不替换角色。不要求是完整的标准攻略配队，但不支持缺少角色的空槽编队。三名角色必须都能识别；空位、重复或未识别角色会跳过该预设。卜灵（`char_douling`）等已注册角色，即使缺少专门机制规则也能参与：从角色工厂读取定位和属性，保守计分，不抹掉其他队友的已知收益。

出口保留已成功的周本式后台移动；1.82.01在海墟调用侧补充顶部识别、分段纠偏和有限脱困，不改变共用寻路函数。1.85.00加入无尽关卡流程，1.85.01依据真实页面将名称校正为「无尽湍渊」。代码、截图回放和模拟流程验证仍需用户手动实机验收，不能视为整轮验收。

## 执行计划与落地

初版工作分解见[原实现计划](../superpowers/plans/2026-09-18-sea-ruins.md)。1.81.00增量按用户确认的库存扫描与暂停恢复方案执行：

| 文件 | 责任 |
| --- | --- |
| `src/task/sea_ruins.py` | 周期属性、角色机制标签、整队与信物组合评分 |
| `src/task/sea_ruins_vision.py` | 卡片定位、头像裁剪、锁与出口标记、F交互校验 |
| `src/task/AutoSeaRuinsTask.py` | 页面操作、列表扫描、自动战斗、上下半转场、结算循环 |
| `src/task/sea_ruins_tokens.py` | 静态信物效果、品质、来源与截断名称匹配 |
| `src/task/sea_ruins_recovery.py` | 阶段检查点、人工暂停与恢复核对 |

### 1. 导航与关卡确认

启动时要求「海墟详情」标题，并识别左上角7—11层数字或“无尽湍渊”名称；连续两帧一致后保存本轮起始关卡。第11层和第7层的图片模板兜底还需挑战按钮或关卡名称联合确认；不以“怪物特性无”判断敌人抗性。当前页或关卡无法确认则暂停，不按F2、不点击地图；人工回到详情页并点击继续后重新读取。周期过期仍暂停，继续不能绕过规则检查。

下一关不是靠地图固定坐标猜测。结算页必须出现下一层的“第N层”，或第11层后的“无尽”文字；点击「继续挑战」之后，再核对预期关卡的详情页。两个证据不一致就暂停。

1.82.01允许最多3次点击，间隔至少5秒；每次必须用新截图重新确认结算页、预告的下一关名称和按钮位置稳定。加载/未知页面不重复点击，到达预期详情页立即结束；120秒是总上限，不取消点击额度上限。无尽湍渊结算后停止，不继续点击。

### 2. 预设选择

先滚动回顶部，再逐屏扫描预设卡片，以局部放大OCR读取编号，以既有角色特征识别三个头像。海墟使用独立1440p参考特征再统一尺度匹配，避免共享720p缩略图丢失细节造成守岸人误识别；不改变公共战斗/深塔识别器。按编号去重，跨页成员不一致就暂停；只把完整且已知的预设加入候选。

上下半的候选是同时枚举的，不会先把最佳队给上半、再让下半被迫使用重人队。评分由元素适配、开局资源偏好、信物收益构成。按选定编号重新找到预设，再核对成员后点击头像范围；应用后核对右侧头像及顺序。进入场内还会重新读取角色并核验一次。

页面滚动停止采用连续两次画面稳定检测，最多扫描32屏预设、24屏信物。这是有界启发式，不等价于已证明滚动条到底；如果客户端吞掉滚轮，可能提前结束扫描，实机需要验证。

### 3. 顺逆属性与角色机制

规则在代码中维护，不开放GUI编辑。当前规则窗口为2026-08-31（含）至2026-09-28（不含）；窗口外暂停，必须重新核实后更新版本，点击继续不能绕过失效规则。运行中使用本机日期，设备日期需要正确。

| 层号 | 上半逆属性 | 下半逆属性 |
| --- | --- | --- |
| 7 | 无（沿用现有规则） | 无（沿用现有规则） |
| 8 | 热熔 | 衍射 |
| 9 | 气动 | 气动 |
| 10 | 导电 | 导电 |
| 11 | 衍射 | 衍射 |
| 无尽湍渊 | 未核实，不加元素偏好 | 未核实，不加元素偏好 |

第8层按用户2026-09-20提供的信息修正：上半热熔逆属性、下半衍射逆属性，无顺属性。9—11层按用户2026-09-22确认的当前周期规则校正；第7层沿用原规则。“怪物特性无”不等于敌人没有固有抗性。无尽湍渊未提供怪物详情，元素评分不加顺逆属性偏好。上述规则仍需随周期更新，本轮没有确认额外元素顺属性。

评分不是伤害模拟：按角色输出权重计入元素收益/惩罚，主输出影响大，治疗影响小；顺属性每权重+25，逆属性每权重-55。宁可使用次优但无重人的队伍，也不拆改预设。

机制按普攻、重击、共鸣技能、共鸣解放、声骸、集谐、异常等标签计算。爱弥斯、达妮娅等无法从头像确认模态的角色，不推断其专属触发。漂泊者头像不能证明当前属性，元素按未知处理；其实际战斗仍复用现有角色工厂支持的实现，其他属性的漂泊者需要另行适配。

没有专门机制规则的已注册角色按主C1.0、副C0.35、治疗0.1参与基础属性评分，不虚构普攻/重击/异常等标签。缺少标签只影响该角色可证明的特殊收益；其他队友标签正常计算。深塔的候选生成本来就按角色工厂定位允许非推荐角色替补，本版增加卜灵/渊武组合回归，不放开硬禁属性、不取消未知输出属性保护，也不改动深塔配队生产代码。

### 4. Buff（信物）选择

效果预先保存在代码，详见[信物资料与来源](sea-ruins-tokens.md)。运行时逐屏截图，只读金、紫、蓝每一种信物的截断名称、品质、锁定状态与剩余次数，不逐个点击读取效果；绿色不参与选择。无限符号单独模板匹配，避免OCR将「∞」读成8或00。未知身份/数量和跨页库存矛盾暂停，不猜测。

| 信物类型 | 决策原则 |
| --- | --- |
| 那丈量心… | 确认集谐触发后，按集谐/气动贡献评分 |
| 那映照虚… | 只计自身具备护盾条件的角色，不推断护盾可转移 |
| 那凝望深… | 确认霜渐条件后计算冷凝收益 |
| 镌刻者 | 只计可确认的通用部分，不从头像推断震谐模态 |
| 希冀者 | 通用部分加集谐触发收益 |
| 编造者、慰藉者 | 通用部分加可证明的声骸/异常收益 |
| 审判、狂欢者 | 已知通用备选 |
| 布道、游猎 | 分别按普攻、重击贡献评分 |
| 眷属 | 保守的通用召唤备选 |
| 其他 | 不在静态目录的新信物暂停，需维护资料 |

有限次数信物在前层扣保留分，优先留给后层；第10层起和无尽湍渊不扣保留分。但只有有限信物可用时仍允许选取，不因保留分把所有合法组合淘汰。这是逐层贪心保留策略，不是整期最优规划。两队若选同一有限信物，扫描时剩余至少为2；第二次携带前重新读取可用状态。

每关都重新扫描库存、重新选择两队及信物，不信任上一层残留头像。携带时滚动定位，只点击选定目标，核对右侧完整名称和携带按钮，再返回详情核对槽图案。已经正确携带的目标不重复点击；开战前再次检查两队和两信物。

### 5. 开战、出口与下半

地图加载并确认队伍后，每次仅向前0.20秒，再读新截图。只有目标「开启挑战/开始挑战」和同一行F标记同时成立才按F；按一次后最多等25秒确认战斗，不连按。最多45次短步，找不到即停止。

上半战后以左侧「前往下半海域」及「上半得分」共同确认。无敌人、血条消失、波间空档均不能单独认定完成。战斗帧观察连续两次看到明确结束界面才结束该半场，单半场上限10分钟。

寻找出口的实现：

1. 释放移动及鼠标按键，中键一次回正视角。
2. 只在场景区域匹配出口白色图标，排除左侧任务图标和右侧角色栏。
3. 海墟按最长1秒的段落调用周本共用后台 `walk_to_box`；段落间释放输入并重新判断，清除只对中一次后不再横向纠偏的状态。不修改共用函数。
4. 识别区域包含顶部和偏下出口图标：2048×1152归一画面中从y=90到1000，x=400到1800；仍排除左侧任务栏、右侧角色栏及底部HUD。
5. 图标短暂丢失立即停步，最多重查10次；恢复后重启寻路，不沿用旧目标或方向键状态。
6. 出现同一行「F + 进入下半海域」才停止移动并按F；之后等待地图可操作、上半任务及旧交互消失，再核对下半角色。

出口总搜索上限60秒，丢失重试和脱困共用此预算。图标位置与两侧场景连续约4秒无明显变化时，短暂后退后侧移，每步最多0.25秒、每步重查阶段/图标/F提示；最多3轮，左右交替，图标重识别不重置轮数。到达提示立即停步，异常/取消释放输入。仍无进展则暂停给用户接手。

左侧提醒证明流程阶段，场景图标指示方向，F提示证明已到交互距离，三者用途不同。脱困是画面变化启发式，不是路径地图或完整避障；环境动画可能影响无进展判断，宽障碍仍可能无法绕开，不能保证每个出生位置都成功。

下半同样短步找F开战并自动战斗。结算必须识别「挑战结束」「返回海墟」，读上下半与总分且满足相加一致才继续；不把分数不足自动解释为满星完成。

## 暂停与继续

已知「解锁信物 / 点击空白处关闭」弹窗自动关闭，最多3次；不识别任意暗屏为弹窗。未能处理的异常释放输入、截图留证，显示当前层与未完成环节，使用原任务卡的暂停/继续功能。暂停期间关闭战斗睡眠回调，保留当前前台任务，后台触发任务不取得执行权。

用户接手后点击继续：先刷新截图和战斗缓存，再核对阶段。已应用的编队/信物不重复应用；上半已结束则去出口；手动进入下半后通过海墟HUD和下半角色确认，直接接续下半；已到结算则读取结算；下一关详情只在待进入下一关的阶段且名称一致时承认，包括第11层后的无尽湍渊。回到当前关卡编队页会按需要重扫库存与计划。未知界面再次暂停，不自动从7层重开。

人工暂停时间不沿用旧操作超时；继续后重试环节建立新的有限预算。主动停止仍立即终止，不转成暂停。仅支持同一程序进程内的恢复，关闭/重启程序后不保留检查点。**程序暂停不会暂停在线游戏世界，战斗中需及时接手。**

仍需实机验证：库存扫描全过程、滚轮到底、所有信物携带槽图案、人工接管后恢复、复杂遮挡/绕障、第11层转无尽湍渊的结算页文字位置、实际怪物抗性、整轮通关。测试截图下半识别为 `yangyang_sp / char_rover / char_sanhua`，不把漂泊者误标为相里要。

维护时更新周期日期、`SEASON_RULES`、角色`PROFILES`和信物评分，并补对应截图/规则测试；遵循仓库版本及发布要求。不得只延长日期而不核对新周期。
