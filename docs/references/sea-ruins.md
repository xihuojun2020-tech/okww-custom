# 自动冥歌海墟：使用与实现（1.80.00）

## 使用范围

入口在每周任务中，名称为「自动冥歌海墟」。正确名称是**冥歌海墟**，不是溟歌海墟。

首版从周期挑战的再生海域第7层开始，依次挑战至第11层，每层一次。不刷分、不打无尽、不领奖，也不保证满星。需要简体中文、16:9、至少1280×720画面，以及已解锁第7层。出口转镜头时游戏必须在前台；切到其他窗口会安全停止。

提前在游戏中保存至少两支三人预设，尽量不重人。程序不改成员、不调顺序、不替换角色。不要求是完整的标准攻略配队，但不支持缺少角色的空槽编队。三名角色必须都能识别；未知角色会跳过该预设。

本次完成的是代码、截图回放和模拟流程验证，**尚未完成真实游戏7—11层整轮验收**。建议首次运行有人观察，尤其是滚动到底、信物携带反馈及出口移动。

## 执行计划与落地

详细工作分解见[实现计划](../superpowers/plans/2026-09-18-sea-ruins.md)，约束见[设计](../superpowers/specs/2026-09-18-sea-ruins-design.md)。实现分为三个文件：

| 文件 | 责任 |
| --- | --- |
| `src/task/sea_ruins.py` | 周期属性、角色机制标签、整队与信物组合评分 |
| `src/task/sea_ruins_vision.py` | 卡片定位、头像裁剪、锁与出口标记、F交互校验 |
| `src/task/AutoSeaRuinsTask.py` | 页面操作、列表扫描、自动战斗、上下半转场、结算循环 |

### 1. 导航与关卡确认

F2打开指南，复用深塔的周期挑战入口模板；识别「冥歌海墟」，只点击「再生海域」旁对应的「前往」。进入地图后关联「7」和「险滩」定位右侧船体，不把层号文字本身当作唯一点击目标。进入详情后再次核对层号。

下一层不是靠地图固定坐标猜测。结算页必须出现「即将前往…第N层」，点击「继续挑战」之后，再核对详情页的N。两个证据不一致就停止。

### 2. 预设选择

先滚动回顶部，再逐屏扫描预设卡片，以局部放大OCR读取编号，以既有角色特征识别三个头像。按编号去重，跨页成员不一致就停止；只把完整且已知的预设加入候选。

上下半的候选是同时枚举的，不会先把最佳队给上半、再让下半被迫使用重人队。评分由元素适配、开局资源偏好、信物收益构成。按选定编号重新找到预设，再核对成员后点击头像范围；应用后核对右侧头像及顺序。进入场内还会重新读取角色并核验一次。

页面滚动停止采用连续两次画面稳定检测，最多扫描32屏预设、24屏信物。这是有界启发式，不等价于已证明滚动条到底；如果客户端吞掉滚轮，可能提前结束扫描，实机需要验证。

### 3. 顺逆属性与角色机制

规则在代码中维护，不开放GUI编辑。当前规则窗口为2026-08-31（含）至2026-09-28（不含）；窗口外直接停止，必须重新核实后更新版本。运行中使用本机日期，设备日期需要正确。

| 层号 | 上半逆属性 | 下半逆属性 |
| --- | --- | --- |
| 7、8 | 无 | 无 |
| 9 | 气动 | 气动、热熔 |
| 10 | 导电 | 导电、冷凝 |
| 11 | 衍射 | 衍射、湮灭 |

7、8层的无怪物特性由用户截图确认。9—11层沿用本轮调研的[Game8海墟资料](https://game8.co/games/Wuthering-Waves/archives/499663)，属于敌人抗性规避偏好，**不是宣称所有敌人具有同一场地抗性**；用户未提供对应关卡怪物详情截图，仍需实机复核。本轮没有确认额外元素顺属性，顺属性列表为空，代码保留同一评分接口。

评分不是伤害模拟：按角色输出权重计入元素收益/惩罚，主输出影响大，治疗影响小；顺属性每权重+25，逆属性每权重-55。宁可使用次优但无重人的队伍，也不拆改预设。

机制按普攻、重击、共鸣技能、共鸣解放、声骸、集谐、异常等标签计算。爱弥斯、达妮娅等无法从头像确认模态的角色，不推断其专属触发。漂泊者头像不能证明当前属性，元素按未知处理；其实际战斗仍复用现有角色工厂支持的实现，其他属性的漂泊者需要另行适配。

### 4. Buff（信物）选择

程序逐个点击可见信物，等待右侧完整名称连续稳定，再读取效果。名称可见不代表已解锁，必须同时检查锁和剩余次数；未知次数不使用。无限符号单独模板匹配，避免OCR将「∞」读成8或00。

| 信物类型 | 决策原则 |
| --- | --- |
| 那丈量心… | 确认集谐触发后，按集谐/气动贡献评分 |
| 那映照虚… | 只计自身具备护盾条件的角色，不推断护盾可转移 |
| 那凝望深… | 确认霜渐条件后计算冷凝收益 |
| 镌刻者 | 只计可确认的通用部分，不从头像推断震谐模态 |
| 希冀者 | 按集谐触发及贡献评分 |
| 编造者、慰藉者 | 通用部分加可证明的声骸/异常收益 |
| 审判、狂欢者 | 已知通用备选 |
| 其他 | 仅接受可解释的简单增伤描述；未知复杂条件不猜 |

有限次数信物在前层扣保留分，优先留给后层；但只有有限信物可用时仍允许选取，不因保留分把所有合法组合淘汰。这是逐层贪心保留策略，不是整期最优规划。两队若选同一有限信物，扫描时剩余至少为2；第二次携带前重新读取可用状态。

每关都重新扫描、重新选择两队及信物，不信任上一层残留头像。携带后返回详情并比对信物槽图案；不确认就不开始挑战。

### 5. 开战、出口与下半

地图加载并确认队伍后，每次仅向前0.20秒，再读新截图。只有目标「开启挑战/开始挑战」和同一行F标记同时成立才按F；按一次后最多等25秒确认战斗，不连按。最多45次短步，找不到即停止。

上半战后以左侧「前往下半海域」及「上半得分」共同确认。无敌人、血条消失、波间空档均不能单独认定完成。战斗帧观察连续两次看到明确结束界面才结束该半场，单半场上限10分钟。

寻找出口的实现：

1. 释放移动及鼠标按键，中键一次回正视角。
2. 只在场景区域匹配出口白色图标，排除左侧任务图标和右侧角色栏。
3. 计算图标横坐标与屏幕中心的差。偏差大于4.5%就转镜头，不前进；图标未找到时小幅水平搜索。
4. 转镜头使用相对鼠标输入，仅在游戏处于前台时发送；每次转动后读取新画面。
5. 对准后只向前0.25秒，重新判断。目标是横向正中，不要求图标一定贴着屏幕顶部，因为走近时高度会变。
6. 出现同一行「F + 进入下半海域」才停止移动并按F；之后等待地图可操作、上半任务及旧交互消失，再核对下半角色。

出口总搜索上限60秒。左侧提醒用来证明流程阶段，场景图标用来定方向，F提示用来证明已到交互距离，三者用途不同。没有路径地图或复杂绕障；直线受阻最终超时停止。

下半同样短步找F开战并自动战斗。结算必须识别「挑战结束」「返回海墟」，读上下半与总分且满足相加一致才继续；不把分数不足自动解释为满星完成。

## 验证与已知限制

最终合并执行198项测试全部通过，其中新增海墟21项（17项规则/模拟流程、4项真实OCR截图），其余177项为相关回归。图片资产由9张用户截图生成，已遮去顶部状态和底部账号区域。测试在现有工作区运行；退出时框架报告51个未回收对象的ResourceWarning，但退出码为0。没有隔离验证用户尚未提交的基类改动，也没有将其纳入发布。

可复现命令：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.TestSeaRuins tests.TestSeaRuinsFlow tests.TestSeaRuinsImages -q
.\.venv\Scripts\python.exe -m unittest tests.TestAutoAbyssTask tests.TestAbyssTeamPlanner tests.TestEchoesContinuation tests.TestWeeklyNavigation tests.TestWeeklyTransitions tests.TestNavigationSections tests.TestTaskNavigationClassification -q
```

未验证：真实客户端完整导航、滚轮到底、所有信物携带槽图案、物理转镜头灵敏度、复杂遮挡/绕障、9—11层实际怪物抗性、整轮通关。测试截图下半识别为 `yangyang_sp / char_rover / char_sanhua`，不把漂泊者误标为相里要。

任务出错保存`sea_ruins_failed`，各层结算保存`sea_ruins_floor_N_result`；这些是运行截图。任务已映射到海墟证据项目，但没有新增「整期奖励全部完成」自动判定，原手动留证能力不变。

维护时更新周期日期、`SEASON_RULES`、角色`PROFILES`和信物评分，并补对应截图/规则测试；遵循仓库版本及发布要求。不得只延长日期而不核对新周期。
