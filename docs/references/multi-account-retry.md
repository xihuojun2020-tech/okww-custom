# 多账号失败恢复与队尾补跑

适用版本：1.51.00。

## 执行规则

以 A1、A2、A3、A4 为例，A3 每日任务失败且能够安全继续时，先完成 A4，再重新登录 A3，从每日任务入口补跑一次。若补跑仍失败，保留失败原因并报告部分失败，不无限循环，也不返回 A1。

每次明确启动提供一次正常执行和最多一次自动补跑。暂停后继续沿用当前额度；手动停止不会自动重启。重新启动时读取当天失败记录，从 A3 开始并成功后，不再在队尾重复 A3；从 A4 开始则仍会处理未完成的 A3。多账号失败时，补跑按所选序列原顺序，而非失败发生顺序。

## 持久化与完成判定

恢复时无需新增开关或修改账号配置。“补跑一次”是每个失败账号、每次启动的自动补跑上限，不保证游戏任务必然成功。

- A3 失败后从 A3 重新启动：成功才解除失败，本次队尾不重复 A3。
- A3 失败后从 A4 重新启动：先处理 A4，仍会继续处理未完成的 A3。
- A3 自动补跑仍失败：保留失败记录并报告部分失败；手动重新启动可获得新的执行额度。
- 补跑中暂停后继续：不重置额度；手动停止不会触发自动重启。

- 使用稳定 UUID，不以显示昵称或手机号作为生产记录键；改名和调整显示不丢失记录。
- 保存失败阶段、原因、时间、尝试次数、pending/resolved 状态及此前失败历史。
- 成功先保存完成进度，再解除失败。重启发现晚于失败时间的当天每日完成记录时，可自动解除遗留失败。
- 同日但早于或等于失败时间的完成记录不算恢复成功。旧版缺少失败时间的记录保守重跑。
- 仅调度当前序列，其他序列记录保留；不同日期不混用。跨过本机午夜后，在下一次账号执行入口或目标选择检查时停止，并非午夜立即中断当前操作；重新启动建立新日进度。
- 写入失败和身份/配置安全错误阻断执行，不按普通账号错误跳过。

## 从头重跑的含义

重新登录并校验身份、绑定该账号配置，再次进入 DailyTask。临时执行状态由既有入口重新初始化，不删除周本、乐园、奖励、体力等真实记录，不强制重复领奖。已有每日完成、仅周本补检异常时仍走周本单独检查入口。

界面状态区显示“正常执行”或“失败补跑 1/1”；失败列表在恢复成功后更新，最终明确完成或部分失败。账号继续使用既有组合名称显示规则。
