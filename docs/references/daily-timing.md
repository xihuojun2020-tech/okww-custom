# 每日任务耗时记录

## 计时口径

- 已确认并登录的第一个账号：从点击开始，到现有流程开始切换下一个账号。
- 后续账号：从上一个账号开始转往本账号，到开始转往再下一个账号。切入本账号的退登、选号、登录、加载时间归本账号。
- 最后一个账号：计到现有任务收尾结束。单独执行每日任务也从点击开始计到结束。
- 时间是实际经过时间，包括暂停、加载、等待和异常恢复；使用单调时钟计算耗时，北京时间记录起止时间。

## 首次、补跑与累计

每次执行独立保存开始、结束、耗时、轮次、结果和错误原因。首次失败不会被补跑成功覆盖。账号当日累计为各次已结束记录之和，等待其他账号执行的间隔不计入该账号。手动再次启动形成新批次，当日执行次数和累计耗时继续计算。

游戏日沿用凌晨4点划分，整轮归启动时所属游戏日。整轮总耗时另行记录，包含整个多账号任务从开始到结束的时间。

停止记录为“已停止”；切号失败记录阶段为“切入账号”。异常退出后没有可靠结束时间的记录显示“中断（结束时间未知）”，不把关机期间推算成任务耗时，也不计入已记录累计。

## 查看与保存

账号页面顶部的“每日耗时记录”打开只读历史窗口，按日期显示当前所选账号的首次、补跑、再次执行和累计时间。任务运行信息显示本轮各账号时间及整轮耗时。

记录复用完成检查的 `CompletionEvidence/index.sqlite3` 存储位置，使用独立的 `daily_timings` 表，不替换截图或原每日运行记录。开始、结果、交接和结束时保存；界面刷新只读内存和历史记录，不逐秒写盘。

账号结束时，主日志写入账号简称、轮次、起止时间、本次和当日累计耗时、阶段及错误原因；整轮结束时写入总耗时。这些日志随现有自动/手动诊断上传流程上传NAS，不增加上传任务。

## 流程约束与验证

计时是观察记录，不参与账号选择、登录、恢复、补跑预算和完成登记。多账号每日任务的执行顺序、返回值和异常传播保持原状。被多账号调用的每日子任务不重复计时；多账号每周乐园和单独周本、首领材料入口不写每日计时记录。写入失败报告日志，原任务继续按原流程处理。

离线验证覆盖时间交接、失败与补跑累计、手动第二轮、点击后的准备时间、父子不重复计时、保存故障隔离、停止、中断及只读界面；现有多账号流程回归验证切号和恢复的调用顺序。实际游戏运行尚待更新后验收。
