# 1.60.06 手动人数与归一化固定位置

在角色试用配置中选择“试用人数”：5人（默认）或6人。升级不会自动判断人数，请按本期实际活动选择。

五个位置X为0.324、0.410、0.495、0.581、0.650，Y为0.905，均相对游戏画面宽高，支持16:9的1920×1080和2560×1440，不包含窗口边框。拖拽从(0.665,0.905)到(0.286,0.905)，反向用于返回列表左端。

按1—5顺序点击固定位置；选择6人时，第五人处理完成后拖到末端，再点击第五位置。返回活动页及最终状态复核时重新建立所需端点。点击后稳定识别奖励状态：已完成跳过、领取直接领奖、进行中进入试用。状态无法确认仍停止，不默认完成。

本版取消头像匹配、名称OCR及两端名单拼接。人数正确性由用户配置保证；固定槽位不能独立证明选中的是不同角色。拖拽没有响应或布局改变时可能选到错误槽位，因此第一次运行必须确认第五/第六位置实际选中目标，不将配置人数当作自动发现的完整名单。

26项专项和4项实图测试通过；包含两种分辨率坐标、人数配置、未知状态拒绝及停止释放鼠标。真实输入效果未实测。

## 1.60.02 响应观察机制（本版保留）

修复针对初露峥嵘角色试用的头像扫描。滚动前在已识别头像中心悬停0.15秒，发送一格滚轮后观察响应1.5秒；每次稳定视图读取另有2秒上限。稳定旧位置不会立即结束等待。每方向最多三次尝试，扫描整体90秒上限（正在进行的取帧或OCR结束后检查）。

确认位移后继续原来的左右边界扫描、唯一重叠合并和逐角色选择。仍有截断头像且滚动无响应时仍然停止，不能把报错消失当成完整扫描，也不会以固定头像数量伪造成功。角色选择使用相同的滚动观察逻辑。

日志可检索“头像滚动观察”和“头像滚动已确认”，包括方向、尝试、位置及位移。最终异常继续走现有角色试用故障截图流程。本版没有更换PostMessage输入后端，也没有加入未经实机验证的拖动降级。
