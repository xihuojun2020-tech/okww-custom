# 自动战斗异常恢复（1.89.00）

## 已定位故障

2026-09-09 的 NAS 上传会话 `20260909-200505-3498bad879ca` 中，自动战斗在 21:43:36、21:44:03、21:44:16、21:44:33、21:44:40、21:44:51 共异常停止六次。主日志和错误日志为同一事件的双份记录，按时间去重。21:44:00 的重新启用记录与 21:44:03 的异常仅相隔约三秒。

共同异常为 `AttributeError: 'HavocRover' object has no attribute 'use_skyfall_severance'`。调用链为自动战斗、角色 perform、漂泊者气动流程。HavocRover 是漂泊者多形态共用实现，名称并不代表当时必须为湮灭形态。

队伍显示调用 `ensure_display_form()`，提前识别气动并写入 ring_index。原 `init()` 仅在 ring_index 未识别时调用 init_wind，导致队伍配合属性未初始化；框架捕获普通异常后 disable，因此每次重新启用仍会触发相同代码。修复为构造时提供默认值，并在每次气动初始化时重新计算队伍配合，不依赖形态识别发生的先后顺序。

## 使用规则（1.89.00 起）

1. 开启后从首次异常开始持续恢复，普通开启和启动恢复均适用。异常不能取消开启状态；仅用户主动关闭开关或停止当前自动战斗才保存关闭值。
2. 异常后释放本任务持有的输入并清理错误角色状态，按 2、4、8、16、30 秒间隔复核；最长等待30秒，无总重试次数关闭限制。
3. 窗口、截图或输入暂时不可用时保持开启等待。释放失败记录原输入后端，成功释放之前不发送新动作。过图、菜单和结算画面不持续盲目输入。
4. 每日及副本通过共用战斗循环恢复角色动作和战斗探测异常；仍在战斗时重新识别队伍及当前角色，调用原角色脚本。手动停止、死亡及明确结果交接不被恢复吞掉；未确认正常结束不能标记胜利。
5. 一次性任务运行时保持前台输入独占，后台自动战斗在任务退出后继续调度。活动专用流程仍由活动拥有，不能同时抢输入。
6. 首次及变化异常保留日志和已有画面证据，重复异常限频合并；状态同步、日志及截图失败均不能终止恢复。证据使用既有 okww监控室通路。
7. 开关偏好持久保存；重置战斗设置保留该偏好。旧关闭值保持关闭，因为无法可靠区分历史自动关闭与用户关闭。
8. 用户全局暂停和程序退出停止实际执行并保留开关偏好。恢复后无需重新勾选；手动关闭优先于待启用线程和延迟恢复。

## 开发维护

- `AutoCombatTask`：常态恢复、用户启停入口、启用代次校验、设备准备失败重试及恢复状态。
- `BaseCombatTask`：独立命名的战斗输入记录、原后端释放、动作/探测重试及限频证据。避免与活动任务的自有输入记录重名。
- `TaskExecutor`：恢复钩子失败兜底、截图为空等待、场景复位错误覆盖、其他任务诊断失败隔离；控制异常仍优先处理。
- `TaskCard`：用户开关专用入口、信号屏蔽刷新、重置配置时保留开启偏好。
- `AGENTS.md`：仅用户手动关闭的长期约束。升级 ok-script 时核对生产覆盖文件；不能仅修改虚拟环境副本。
