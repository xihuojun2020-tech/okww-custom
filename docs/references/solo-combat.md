# 单人输出支持与使用说明（1.70.00）

## 使用方式

仅编入一名角色，按原方式开启自动战斗即可，不需要额外打开单人模式。程序先识别队伍与敌人，再根据真实成员数和角色定位选择单人分支。

覆盖当前注册表的 **43 个主/副输出条目（包含主角，头像变体合并计数）**，以及开启“Chisa DPS／千咲输出”配置的千咲。治疗定位且未开启输出配置的角色保留原流程；“三人队伍中只剩一人存活”不等于本功能的单人编队。

大招必须同时满足能量、冷却和“使用大招”设置。单人状态不会伪造变奏、队友增益或协奏数值；对仅用于提前切人的协奏门槛作局部处理，椿强化技能等真实依赖协奏的机制仍保留。

## 实现方式

BaseChar.perform 统一进入 perform_solo。可独立运行的专用技能轴由默认 perform_solo 复用，避免复制几十份相同入口；依赖队伍起手或有明显单人停手条件的角色使用专项分支/修正。共有入口不是所有角色共用一套技能顺序。

只有原本使用 BaseChar 的基础角色或明确标记的未知阶段使用基础技能流程。该流程尝试声骸、就绪大招、技能和短普攻，不代表已经实现这些角色的全部精细连招。

## 漂泊者形态

男女头像共用形态分流，依照已有协奏环元素识别选择：

| 形态 | 单人流程 |
|---|---|
| 衍射 | 保留衍射重击、技能与解放流程 |
| 湮灭 | 保留回路重击、技能与解放；普攻时长不再依赖不存在的切人时间 |
| 气动 | 保留空中/落地、技能与解放流程；不伪造队友组合触发的特殊条件 |
| 导电、热熔、冷凝元素值或未识别形态 | 明确使用现有基础技能回退；没有这些形态的专用机制资料或样本，不能称为专用连招支持 |

后三种元素值的回退覆盖是为了避免未知形态不能行动，并不表示游戏已经开放这些主角形态。当前源码已有的三种专用形态均进入独立单人分支。

## 验证范围

新增测试枚举注册表所有输出头像条目及千咲输出配置，确认单人/多人路由分离，单人清除残留变奏状态；专项测试覆盖爱弥斯、今汐、椿、绯雪、洛瑟菈、丹瑾、安可、达妮娅、琳奈、忌炎、相里要，以及主角所有元素值/未知形态分流。

已存在的真实单人截图继续用于 2K 和 1080P 缩放图像回归。自动测试的角色动作使用受控假对象验证控制流，不等于每个角色都完成过游戏内战斗；没有对所有角色/形态提供原生 1080P 或实际连续输出实测。已有头像、能量、回路和技能图标识别的限制仍然存在。

## 使用端验收

1. 正常退出主程序，从局域网更新到 1.70.00 并重启；确认版本。
2. 仅编入目标角色，锁定敌人。检查技能就绪时释放、解放就绪且允许时释放、冷却时继续攻击。
3. 优先检查爱弥斯、今汐、椿、绯雪、洛瑟菈，再验证主角衍射/湮灭/气动与其他常用输出。
4. 检查协奏满后没有停手；战斗结束不会重复向自己发切人键。
5. 回归正常双人/三人队伍；1080P 和 2K 分别验收。

若失败，保留角色/主角形态、版本、分辨率、自动战斗设置、完整游戏截图和同时间日志。区分“队伍未识别”“没进入战斗”“进入后未释放技能”“技能已尝试但输入未生效”。手动上传诊断时仅使用当前 .173 NAS。

第三方 custom_chars 脚本若只重写 do_perform，加载器会保留该自定义实现作为单人入口；显式提供 perform_solo 时优先使用自定义单人实现。自行重写 perform 的脚本仍掌握自己的调度。本清单对应内置注册表与本仓库实现，自定义脚本需要另行验收。
