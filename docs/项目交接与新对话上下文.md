## 4. 深塔 1.38.00 的最终规则

角色定位来自 `CharFactory` / `CharType`，不采用用户早期参考名单覆盖定位。弗洛洛、秧秧SP是主C；琳奈元数据为衍射，秧秧SP为湮灭。漂泊者按识别形态区分，头像别名合并体力账本。

左右塔分别设置一个顺属性和一个逆属性；中塔1—2层、3—4层各自设置两个同级顺属性及两个分级逆属性，共12项下拉。配置通过框架Config长期保存，运行开始冻结，清理扫描结果和切换账号不重置。

- 中塔一级逆属性禁止主C和副C；纯治疗按OK-WW定位允许。
- 中塔二级逆属性尽量避开主C，副C允许。
- 左右塔依次优先无逆属性输出、逆属性副C、必要时逆属性主C。
- 顺属性收益按主C判断，双主C均检查，治疗不能为队伍制造顺属性收益。
- 先生成预设及同定位替补候选，再共享同一角色体力安排各层；中塔优先同时预留两个半区，且保持用户设置的整塔执行顺序。
- 左右每层每人消耗1/2/3/4，中塔每层5；跳过一层后不安排该塔后续层。
- 中塔换半区仅在相同队伍仍合法且被选中时直接继续，否则返回重扫重组；从第三层恢复使用后半区规则。
- 中塔无法安全分配时停止整个任务。大仓库使用有界搜索，日志明确标注裁剪，不保证数学上的全局最优。

实现位于 `src/task/abyss_allocation.py`、`abyss_team_planner.py` 和 `AutoAbyssTask.py`。仍沿用单页或两页角色识别，未识别角色不参与规划。50名角色、7938候选、12层无属性约束的离线测量约1.6秒，不代表游戏通关耗时。尚待用户手动验证真实选人、半区切换、兜底和硬禁停止。

## 5. 打包版退出故障与 1.38.01 修复

9月8日11:23主程序退出日志出现终止启动器“拒绝访问”；11:24启动器更新到1.38.00时，将后台上传PID也列入“应用仍在运行”，阻止更新。PID32504被核对为计划任务启动的诊断上传进程；当时主程序退出后它仍使用安装目录内Python。权限报错不等于已证明权限等级不一致。

修复包括：

- `diagnostic_runtime.py` 在安装盘外层独立目录准备不可变Python/诊断代码快照，只带必要标准库、Pillow和Windows凭据模块；自检导入路径后使用。
- `source.json` 保留原来源路径和安装身份；原日志队列、设备标识、Windows凭据不搬迁、不重置。
- 主程序唤醒、计划任务及上传/清理子进程使用独立环境，忽略继承的Python环境变量。
- `MainWindow.closeEvent` 不再同步等待PID方式强杀启动器；执行器或app清理异常也继续退出Qt，关闭到托盘行为保留。
- `main._exit_cleanup` 保留已有祖先进程身份检查，并跳过经来源绑定核验的独立上传进程。
- `scripts/repair_diagnostic_runtime.py` 可从新源码修复旧安装，无需旧安装先完成升级；`--apply` 才迁移任务，失败恢复XML备份。
