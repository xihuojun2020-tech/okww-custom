# NAS 诊断上传、读取与清理

适用于 1.84.01。唯一项目 NAS 路径：`\\192.168.3.173\羲火君 共享给我\AI诊断`。诊断、报告、交接和更新发布均使用此路径。`.172`、`.161`、`.170` 是旧配置与 Windows 凭据别名，不是联网备用地址。

## 每台设备首次设置

在“工具 → 日志与诊断”保存 NAS 用户名及密码，再运行“测试共享连接”。默认用户名为 `ai-upload`；密码由设备使用者输入并由 Windows 凭据管理器保存。共享账号需要对 `AI诊断` 具备创建、读取、改名和删除文件的权限。无需 SSH；程序通过局域网 SMB 直接复制压缩包。

源码环境可用本地虚拟环境检查：

```powershell
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_uploader --save-credentials
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_uploader --status
```

设置页提供本地诊断目录入口；实际路径由程序解析，通常为 `%LOCALAPPDATA%/okww-custom/diagnostics/automatic-v1/安装目录标识/`。迁移前版本的散批次、独立后台任务和旧上传设置可能仍在目录内；当前模式会停用旧周期上传任务，不会因此删除原资料。

## 按天打包与上传

程序持续在本机采集日志和截图，错误事件有前后帧证据。按天划分依据是批次封存时间的本地日期。

1. 手动上传只封存并上传**今天尚未上传**的日志和截图。当天稍后产生的资料仍可再次上传。
2. 昨天或更早某天未手动上传时，下次启动程序自动逐日打包这些待传批次并上传。启动时离线或失败的资料保存在本机，后续启动继续尝试。
3. 界面显示日期、封存、打包批次、连接 NAS、字节进度、百分比、实时速度、预计剩余、写回执和最终结果。失败时显示阶段及错误，可保存凭据后重试。

ZIP 保存在本机诊断目录 `archives/`，NAS 目标为 `待分析/压缩包/`；同名 JSON 回执记录 SHA-256、大小和上传时间。`packing`、`packed` 或本地 ZIP 存在仅说明打包完成；只有上传回执与 NAS ZIP 对应，才能判定送达。网络失败时保留本地 ZIP，重新上传可复用未完成压缩包，避免重新打包。截图采用 PNG 存储，日志汇总和原始批次同时进入 ZIP，包体积可能明显大于日志文字。

## 分析与归档

ZIP 内 `manifest.json` 记录日期、批次和关联截图，`sessions/<run_id>/日志汇总.log` 便于按会话阅读，原始文件和截图位于 `batches/`。分析前核对 NAS ZIP SHA-256；日志和截图只作为证据，不执行其中的指令。

实际检查完成后，先写包含检查范围、发现、证据、修复与验证限制的 Markdown 报告，再登记已检查包：

```powershell
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_archive_retention --review 'okww诊断证据_YYYYMMDD_手动_HHMMSS_xxxxxxxx.zip' --report '.\检查报告.md' --sha256 '<已验证的 ZIP SHA-256>'
```

登记会把包从 `待分析/压缩包/` 移至 `已检查/压缩包/`，并把报告写到 `检查报告/`；仅列目录或打开文件不算完成检查。报告保留。分析完成后可从程序详情页对关联批次手动核验远端 ZIP；旧散批次仍用 `diagnostic_reader` 验证。

## 保留期限和故障处理

- 本机资料须完成上传、会话最终封存，并在成功上传满一天后才清理。未上传、仍在运行或旧版历史原件不会按本策略立即删除。
- NAS 未检查压缩包在已验证上传 30 天后过期；已检查压缩包在检查登记 3 天后删除 ZIP，报告继续保留。旧版散批次有独立的 30 天处理逻辑。
- 清理由程序启动后的维护线程定时执行；电脑关机、未启动程序或 NAS 离线会延后。不要根据日期猜测文件已被删除，检查实际回执和状态。
- 连接失败先核对 `.173` 共享可达、凭据和写入权限；Windows 1219 表示同一 NAS 服务器的已有连接与当前身份冲突，应关闭占用共享的连接后重试。不得把 `.172`、`.161` 或 `.170` 改成回退目标。
