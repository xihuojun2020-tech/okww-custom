# 给另一台电脑 AI：更新后配置日志与错误截图自动发送

功能自 1.54.00 起提供；更新时使用 1.54.02 或后续成功发布的正式版本。1.54.00 和 1.54.01 的安装包未生成；源码标签存在不代表安装包已发布。设备分工已按用户最新要求修正。

**主体程序由用户当前电脑完成开发、测试和 GitHub 发布。你所在的另一台电脑仅负责更新程序、配置发送端、实机验收和回传结果，不负责再次开发这项功能。**

## 1. 目标与已交付能力

你所在电脑为发送端 S，运行 okww-custom；用户当前电脑为接收端 R。两台电脑在同一局域网。

- 新增日志自动发送，不需要点击发送按钮。
- ERROR/CRITICAL、主线程/工作线程未处理异常触发错误截图。
- 每秒缓存一张游戏画面，保留错误前 10 秒，并记录当时与后 5 秒的画面；稳定采样下单次约 16 张。
- 截图和日志通过设备、安装实例、运行和错误事件关联。
- 网络不可用时本地保留待传批次，恢复后重试。
- “工具 → 日志与诊断”提供“测试共享连接”和“测试错误截图”。测试截图只触发诊断采集，不故意破坏游戏任务。

正常运行只滚动缓存画面，不持续上传全部画面。截图仅来自游戏捕获器，可能包含 UID、昵称等；文本日志有脱敏，图片不保证自动打码。

## 2. 更新并核实实际运行版本

记录实际安装路径、当前版本和启动方式；不要假定安装目录等于源码目录。检查是否有任务在运行、是否有用户未保存设置。

通过程序现有更新机制或 [GitHub 正式 Release](https://github.com/xihuojun2020-tech/okww-custom/releases) 更新至 1.54.02 或包含本功能的后续正式版本。

更新后关闭旧进程并重新启动，在“关于”确认版本。检查“日志与诊断”确实有两个测试按钮。缺少按钮时先确认启动的是否仍是旧安装，不要用 Git 拉取成功代替实际运行版本验证。

若正式安装包仍未构建完成，报告“安装包待发布”，不要安装来源不明的软件包。源码运行环境应核对发布标签和源码版本，不自行修改代码或重新打标签。

## 3. 接收端需要提供的配置

| 信息 | 要求 |
| --- | --- |
| 接收端共享路径 | 必须是实际可用的 UNC 路径，例如 \\<接收端IP>\OKWW-Diagnostics |
| 共享账号 | 接收电脑允许访问共享的 Windows 账号，例如 接收电脑名\用户名 |
| 密码 | 用户在发送端密码框直接填写，不写进聊天、配置 JSON 或报告 |
| 验收时段 | 接收电脑开机、共享可用，发送端游戏可获取画面 |

接收端源码检查时 WLAN IPv4 为 192.168.3.134；这是当时观测值，DHCP 可能改变。以当前电脑最终交接的地址为准，不能把项目原来的 NAS 地址当作接收电脑。

接收共享尚未准备时，先完成版本更新和本地诊断检查，再报告缺少的地址/账号信息；不要扫描整个局域网寻找凭据，也不要要求回传明文密码。

## 4. 配置发送目标

1. 打开“工具 → 日志与诊断”，记录原上传目录供回退。
2. “上传目录”填写接收端提供的 UNC 路径，不能填写接收端本地盘符路径。
3. 填写接收端共享账号；请用户在密码框输入密码。
4. 点击“保存设置”。密码保存在发送端当前用户的 Windows 凭据管理器；留空表示不修改已保存凭据。
5. 点击“测试共享连接”，最长约 30 秒；成功应显示写入、读取、重命名、删除均通过。
6. 共享测试通过后进入截图测试。探针只使用临时唯一小目录，不修改已有诊断文件。

排障：地址不可达先检查接收端是否开机、IP 是否改变；凭据错误要确认是接收端 Windows 账号密码，Windows Hello PIN 通常不能代替 SMB 密码。Windows 1219 表示可能已有其他凭据的会话，不执行全局 `net use * /delete`。共享与 NTFS 权限均需允许读写、改名、删除；不关闭整机防火墙或建立匿名全盘共享。

## 5. 游戏画面与错误截图测试

1. 启动游戏，让程序成功连接游戏窗口并保持可捕获画面至少 12 秒。
2. 确认“已缓存 N 张报错前画面”开始增加；若提示等待画面或画面未更新，先解决捕获问题。
3. 点击一次“测试错误截图”，保持画面可获取至少 5 秒，再等待约 10 秒供封装和上传。
4. 检查“最后成功”、上传错误、采集状态和待传批次。共享连接通过不代表截图已经完整。
5. 接收端检查已完成批次与图片；稳定采样目标约前 10 张、当时 1 张、后 5 张，按实际捕获时间判断。
6. 记录 incident_id、run_id、程序版本、触发时间和接收目录。不用文件写入时间冒充截图时间，不为验收故意触发破坏性游戏任务故障。

当时帧可能是最近的有效捕获帧，存在亚秒时间差，应查看 captured_at 和 relative_seconds。缺帧不会凭空补造。

## 6. 接收端查看关联信息

```text
<共享目录>/待分析/日志/okww-custom/<日期>/<运行>/<批次>/
<共享目录>/待分析/截图/okww-custom/<日期>/<运行>/<批次>/
```

日志批次中的 `incident.json` 包含触发记录、截图清单及跨批次图片引用。只有带 `_UPLOAD_COMPLETE` 且通过摘要校验的批次才可视为上传完成，不把 `.uploading.*` 当正式资料。

接收端如果有对应源码和 Python，在源码根目录运行下面命令验证并生成聚合索引，替换真实本地接收目录：

```powershell
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_reader 'E:\OKWW-Diagnostics'
```

索引位于 `事件索引/<device_id>/<run_id>/<incident_id>.json`，重复运行可补齐乱序到达的图片。

- `state=complete`：采集完整；`incomplete`：查看 incomplete_reasons。
- `delivery_state=verified`：引用图片均已验证；`waiting_for_frames`：尚有图片未到或未通过校验。
- `analysis_state=needs_analysis`：资料待分析，不代表 AI 已查明根因。

接收共享本身不要求 Python；命令用于进一步汇总验证。命令行连接测试可选：

```powershell
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_uploader --probe --target '\\接收电脑\OKWW-Diagnostics'
.\.venv\Scripts\python.exe -m src.runtime.diagnostic_uploader --status
```

## 7. 断线与重启验收

在独立测试流程中暂时使接收端不可达，触发一次截图测试，确认程序可继续使用且待传状态可见。恢复共享后观察自动重试；必要时点击“重试上传”，并区分记录自动/手动结果。

长期离线后退避最长约 15 分钟加调度间隔，不能一恢复连接就认定失败。有待传资料时正常退出并重启，确认已落盘批次继续上传。后台任务需要当前 Windows 用户已登录；关机、休眠、注销期间不保证采集/上传。

不要删除诊断目录清空错误状态，不中断别人的共享连接或关闭整个网络。

## 8. 必须如实记录的限制

- 启动不足 10 秒，没有完整前帧，标记 warmup。
- 游戏最小化、无画面或画面未刷新时标记 stale_frame/frame_unavailable 等，不拿旧图凑数量。
- 强制终止、断电后无法取得未来画面，只恢复已落盘资料。
- 连续错误合并，单窗口最多 30 秒后分段关联。
- 截图有内存、单图、事件和磁盘限制，达到限制可能缺图并记录原因。
- 每周清理已上传超过 7 天的日志及事件摘要副本，保留截图和图片关联；不因此删除待传资料。
- 仅写在外部日志文件而未经过程序日志/异常钩子的错误会同步日志，但不保证触发前后截图。

## 9. 回传验收报告

请回传 Markdown 报告：实际运行路径、显示版本、更新来源与重启结果；脱敏后的共享路径和账号类型（无密码）；连接测试结果；至少一个实机事件 ID、触发时间、前/当时/后帧数量与时间序列；聚合索引的采集/传输状态和缺失原因；在线时延、断线/重启补传及是否手动重试；未完成项。

发现程序缺陷时保留资料，把复现步骤、事件 ID、证据路径交回当前电脑修复。不要在异机重新实现模块、改版本号或单独发布同一功能。
