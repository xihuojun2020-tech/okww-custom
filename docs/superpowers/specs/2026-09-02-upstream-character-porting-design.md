# 上游角色半自动语义迁移设计

## 背景与目标

当前定制版 OKWW 与 `ok-oldking/ok-wuthering-waves` 上游已经在账号切换、自动深渊、资源分类 ID 和公共战斗行为上产生明显分歧。直接合并上游分支、覆盖角色资源或 cherry-pick 整个角色提交，可能破坏现有功能。与此同时，预计约每 40 天迁移两个角色，即每年约 18 个角色，逐次手工完成来源定位、依赖检索、COCO 重编号、注册、翻译、打包和测试会产生大量重复劳动。

本设计建立一套轻量的“AI 语义判断 + 确定性脚本审计”流程，并以清宵作为第一套基准案例。目标是让以后用户只需提供角色名，以及上游缺少时的少量实机截图，AI即可完成迁移、离线验证、版本发布和来源追踪。

当前修改前基线已经备份至 GitHub：`v1.25.00`，提交 `74e38bae9828069307c42edfd145d327fe370ede`。

## 设计原则

1. 上游只作为只读来源，不自动合并分支，不覆盖当前仓库文件。
2. 脚本只负责可确定的机械工作；公共战斗行为、跨角色优先级和兼容逻辑由AI进行语义审查。
3. 所有上游读取都固定到明确提交，迁移结果必须可追溯和可重复。
4. 默认运行模式只生成报告和候选资源，不修改生产代码。
5. 角色仍以 `CharFactory.char_names` 为唯一角色库；自动深渊不维护第二份名单。
6. 不提交包含UID、性能监控层或其他个人信息的完整用户截图，只提交裁剪后的最小模板资源。
7. 不启动或操控游戏进行自动测试；只使用已有截图、提取模板、伪帧和单元测试。

## 方案边界

### 纳入本次实现

- 扩展仓库内 `ok-ww-characters` 技能，加入上游角色语义迁移工作流。
- 新增一个不引入新依赖、复用项目现有 OpenCV 的角色迁移审计脚本。
- 新增机器可读的迁移来源记录。
- 自动发现角色类、标签引用、跨文件角色引用和本地缺失的基础API。
- 从上游COCO中定位角色相关分类、标注和源图片，检测本地ID冲突。
- 生成重新编号后的角色模板候选资源和审计报告，不自动覆盖主COCO。
- 以清宵完成首次迁移：角色类、注册、标签、资源、翻译、联动、自动深渊识别和离线测试。
- 同步版本、About、更新日志、更新包、注释标签和GitHub分支。

### 不纳入本次实现

- 自动合并上游分支或自动 cherry-pick。
- 自动接受 `BaseChar`、`Healer`、`BaseCombatTask` 的整体改动。
- 自动决定复杂的角色切换优先级。
- 持续后台同步或定时检查上游。
- 新增第二套角色注册表或独立的自动深渊角色数据库。
- 将用户完整截图作为测试夹具提交到仓库。

## 组件设计

### 1. 仓库内AI迁移规范

扩展 `.agents/skills/ok-ww-characters/SKILL.md` 和其参考文档，增加以下固定流程：

1. 确认当前仓库、分支、干净工作树和已推送备份版本。
2. 确认上游远端及目标提交，不使用浮动网页内容作为最终来源。
3. 检查角色文件首次引入提交、后续修复提交和目标提交的最终文件。
4. 扫描角色引用的 `Labels.*`、基类API和其他角色名。
5. 在上游全仓搜索角色标签和类名，发现队友联动及公共逻辑变化。
6. 将差异分成安全机械项、角色局部语义项和公共高风险项。
7. 只移植目标角色所需资源，并重新分配本地COCO ID。
8. 完成注册、翻译、打包、截图识别和回归测试。
9. 记录来源提交、本地版本、标签和本地定制说明。

该规范负责约束AI行为，不承担资源解析或ID计算。

### 2. 角色迁移审计脚本

新增 `scripts/port_upstream_character.py`。推荐调用方式：

```powershell
.\.venv\Scripts\python.exe scripts\port_upstream_character.py Qingxiao --ref a24c30f2ec90e56e40287bb76caf7c3a52266d77
```

脚本通过本地 Git 对象读取固定提交，要求AI预先配置并抓取只读 `upstream` 远端。脚本不得隐式执行网络访问、修改远端或切换工作树。

默认输出到 `build/character_ports/<角色名>/`：

- `report.md`：来源、依赖、冲突和人工审查项。
- `report.json`：供AI和测试稳定读取的结构化结果。
- `templates.png`：仅包含目标角色模板的3840×2160黑底画布，模板保持上游HUD原始坐标。
- `coco_fragment.json`：使用新本地ID的候选分类、图片和标注片段。

脚本执行以下确定性检查：

- 定位 `src/char/<角色名>.py`。
- 使用Python AST收集导入、`Labels.*` 和基类方法调用。
- 在目标提交的上游源码中搜索角色类名和 `char_<name>` 标签。
- 对照本地 `BaseChar`、`Healer` 和 `BaseCombatTask` 方法集合，报告缺失API。
- 读取上游及本地 `assets/coco_annotations.json`，查找相关分类和标注。
- 根据本地实时最大图片、分类和标注ID重新编号，禁止使用缓存的固定起始值。
- 从上游源图片裁出最小模板，粘贴到3840×2160黑底独立画布的原始HUD坐标，并生成与新画布一致的标注。
- 报告本地同名标签、同ID异名、缺少图片和空标注等错误。

脚本不直接修改 `src/`、`assets/coco_annotations.json`、翻译文件或版本文件。AI审核报告后，使用普通补丁将候选结果合入生产代码。

### 3. 迁移来源记录

新增 `config/upstream_characters.json`，每个角色记录：

```json
{
  "Qingxiao": {
    "upstream_repository": "ok-oldking/ok-wuthering-waves",
    "upstream_commit": "a24c30f2ec90e56e40287bb76caf7c3a52266d77",
    "source_path": "src/char/Qingxiao.py",
    "local_release": "1.26.00",
    "labels": ["char_qingxiao", "qingxiao_e", "qingxiao_h1", "qingxiao_h2"],
    "local_customizations": [
      "preserve_local_denia_default_no",
      "minimal_healer_switch_lock_port"
    ]
  }
}
```

该文件只保存来源和迁移元数据，不参与运行时角色加载。

## 清宵基准迁移

清宵采用上游目标提交中的修复后实现，并完成以下局部接入：

- 新增 `src/char/Qingxiao.py`。
- 在 `Labels.py` 添加 `char_qingxiao`、`qingxiao_e`、`qingxiao_h1`、`qingxiao_h2`。
- 在 `CharFactory.py` 注册为 `MainDps`、气动属性。
- 向达妮娅加入清宵必要联动。
- 向莫宁加入 `char_qingxiao` 兼容。
- 以最小字段和过滤逻辑同步治疗角色满协奏切出后的16秒锁定，不整体覆盖上游公共函数。
- 不引入达妮娅对所有其他主输出统一返回 `SwitchPriority.NO + 1` 的上游全局行为。
- gettext 增加 `Qingxiao` 到“清宵”的翻译。
- 清宵注册后自动进入 `char_names`，供战斗识别和自动深渊复用。

资源采用独立文件 `assets/images/characters/qingxiao_templates.png`。上游分类ID不得照搬；合入时必须以当前本地最大ID为基准重新计算。用户提供的2560×1440截图用于离线验证：快速编队未选中态、选中态、体力10/等级90和战斗HUD头像。截图原件不提交，只允许将不含UID和性能覆盖层的最小角色卡或头像裁剪保存为测试夹具。

## 数据流

```text
角色名 + 固定上游提交
  -> Git只读提取角色源码、COCO和源图片
  -> AST与全仓引用扫描
  -> 本地API/标签/ID冲突检查
  -> build/character_ports/<角色>/候选结果
  -> AI语义审查和最小补丁
  -> 角色类、注册、标签、资源、翻译和联动
  -> 离线测试与截图识别
  -> 来源记录、版本发布和GitHub推送
```

## 错误处理

- 上游提交不存在或未抓取：明确失败，提示AI抓取对应ref，不回退到浮动主分支。
- 角色文件不存在：列出尝试路径并停止，不创建空角色类。
- 上游引用本地缺失API：报告为高风险项，不生成虚假的兼容实现。
- 找不到标签标注或图片：保留源码审计结果，但资源阶段失败并阻止声称迁移完成。
- 本地COCO存在重复ID或同名冲突：停止资源生成，不自动修复无关历史数据。
- 目标输出目录已存在：默认拒绝覆盖；显式清理或指定新输出目录后重试。
- 用户截图包含隐私信息：只在本机读取并裁剪必要区域，完整图片不加入Git。
- 任一离线回归失败：不创建正式版本标签，不推送发布。

## 测试策略

### 审计脚本测试

- 使用临时最小Git仓库或固定测试夹具验证角色文件、标签和依赖发现。
- 验证缺失提交、缺失角色、缺失API和COCO冲突能稳定失败。
- 验证每次根据本地最大ID生成连续且不冲突的新ID。
- 验证默认模式不修改生产源码和主COCO。
- 验证重复输入产生一致的结构化报告和资源片段。

### 清宵测试

- 角色模块可以导入，循环有超时或帧推进，最终能切人。
- `Labels` 和 `CharFactory` 注册完整，属性与定位正确。
- 四个模板均可由 `FeatureSet` 加载。
- 2560×1440快速编队截图能将第一行第一位识别为清宵、体力10、等级90。
- 选中态和未选中态都不会因金色边框或编号产生错误角色。
- 离线测试从隐私安全的最小裁剪构造合成帧，不依赖用户机器上的绝对截图路径。
- 1080P与1440P通过现有相对坐标和按高度缩放逻辑工作；若离线缩放测试显示阈值不足，再增加分辨率变体，不预先维护重复模板。
- 自动深渊继续从 `char_names`读取角色，不新增名单。
- 现有角色、自动战斗、自动深渊、FeatureSet和发布完整测试全部通过。

## 打包与发布

- 将角色资源目录加入更新包同步范围；若打包器已递归包含该目录，只增加对应测试，不重复列举每个未来角色文件。
- 本次属于中等改动，目标版本为 `1.26.00`。
- 同步 `config.py`、About显示、更新日志和产品可见版本文本。
- 生成新的本地更新包并执行包内容冒烟检查。
- 提交实现，创建注释标签 `v1.26.00`，推送当前发布分支和标签至 `origin`。
- 全程不覆盖用户账号配置，不启动或操控游戏。

## 后续角色的标准输入与完成标准

以后用户最少只需提供角色名。若上游资源齐全，AI直接使用固定提交完成迁移；若上游缺少适用于当前界面的模板，AI只请求该角色快速编队头像或特殊战斗状态截图。

一次角色迁移只有在以下条件全部满足后才算完成：来源提交已记录、角色类已注册、全部标签有真实资源、必要联动已审查、自动深渊可见、离线测试通过、版本文本一致、更新包验证通过、提交和注释标签已推送。
