# 完成检查模块设计

日期：2026-09-10。状态：聊天方案已确认，本文待用户审阅；尚未实现。

## 1. 目标与边界

新增与“任务、账号、自动辅助”同级的“完成检查”，按账号展示各项目的完成状态、图片、时间、来源和历史。用户所称“人物”在首版指账号，不是队伍中的游戏角色。

本模块是证据看板，不是新的自动任务调度器。查看账号不会切换游戏账号；手动确认不会修改 DailyTask、MultiAccountDailyTask 或周本的完成记录。图片、运行时长和正常退出本身均不能证明任务完成。

首版本地可用，不依赖 NAS，不自动上传截图、不自动删除历史，不修改已有账号顺序、UUID、配置键及日常跨日逻辑。沿用现有浅色主题、中文界面、账号组合名称和公共控件，不引入 Web 页面或独立数据库服务。

## 2. 界面与交互

主导航上部依次为任务、账号、完成检查、自动辅助；工具与设置留在底部。现有五页导航变为六页，需要同步清单、路由、布局测试和渲染脚本。

左侧为账号列表：支持序列筛选、编号/昵称搜索，沿用 account_option_labels 的组合名称和稳定 UUID，保持序列顺序，记住最近选择。只读列表不触发登录。长名称省略时提供完整提示，键盘可切换账号。账号摘要仅统计明确周期的待核验项目，不将不同周期合成误导性完成率。

右侧顶部显示选中账号、当前周期/历史筛选、仅看待检查项及“保存当前画面”。主体为缩略图卡片网格，常规宽度三列、较窄宽度两列，极窄时允许一列以避免横向溢出。主区域单一纵向滚动，账号列表仅在溢出时独立滚动；卡片和详情不嵌套多层滚动容器。

卡片显示项目名、等比缩略图、完成状态、图片情况、记录时间、来源和周期。缩略图不裁掉关键文字。默认只呈现摘要；点击打开详情，包含原图、判定依据、目标明细、备注及历史。图片支持放大、适应窗口和关闭，操作有文字或可访问名称。

默认展示已配置、已接入或已有证据的项目；“全部项目”可显示未接入项目，其状态为“尚未接入自动采集”，不是“未完成”。账号无证据、筛选无结果、原图缺失和加载失败均有独立提示。

## 3. 状态模型

以下维度独立保存，禁止仅凭颜色或一枚完成标记表达全部信息。

| 维度 | 值与含义 |
| --- | --- |
| 完成状态 | completed 已完成；partial 部分完成；incomplete 有明确未完成依据；unknown 无法确认；not_applicable 不适用 |
| 图片状态 | available 图片完整；record_only 仅有完成记录；capture_failed 截图失败；missing 文件缺失 |
| 来源 | automatic 程序判定；manual_capture 手动截图；manual_confirmation 用户确认；legacy_record 旧完成记录 |
| 周期 | 当前周期、历史周期、周期未知，由项目规则计算 |

没有记录属于页面空状态，不伪造一条“未完成”证据。手动截图默认 unknown，用户主动确认后可为 completed，但仍显示“手动确认”。“尽力完成”属于结束原因，进度不满时仍为 partial。

同周期后续补跑成功可成为当前摘要，之前失败和部分完成记录不覆盖删除。单纯新增 unknown 截图不抹去已有可靠完成证据；不同来源发生矛盾时展示冲突和时间，不能静默把任一来源当作绝对真值。自动结论与人工结论在详情中分别保留。

证据保存失败不撤销实际任务完成，也不触发额外战斗或体力消费；看板显示“已完成，截图保存失败”。证据仓库错误不得被误写成任务成功证据。

## 4. 首批项目与判定

采用固定项目注册表，首版无需插件框架。每个项目定义稳定 ID、中文名称、目标结构、周期类型和当前自动采集能力。

| 项目 ID | 页面与证据 | 完成边界 |
| --- | --- | --- |
| daily_activity | 活跃度/每日奖励页 | 达标与领奖分别记录；不能从每日任务运行结束推断 |
| nightmare_nest | 聚落目标结果或可验证的完成页 | 按本次选中目标集合统计，区分逐目标完成与全部完成 |
| weekly_garden | 周常目标及奖励页 | 完成与领奖分别展示 |
| weekly_boss | 奖励剩余次数及挑战结算页 | 打过一次、奖励次数耗尽、体力不足和无法识别分别展示 |
| battle_pass | 战令任务/奖励页 | 只声明本次可领取奖励是否处理，不声明整期战令毕业 |
| adversity_tower | 总览、分塔/关卡结果 | 记录已识别星数/关卡、剩余目标和停止原因，不从任务返回推断满星 |
| piano_activity | 明确结果页或手动截图 | 当前高亮按键逻辑不能确认活动完成，首版手动留证 |
| second_sol | 明确活动结果页或手动截图 | 连续按 F 不构成完成证据，首版手动留证 |

海墟、矩阵及其他尚未实现模块可通过注册项目先提供手动留证。新增未知项目不得擅自设置刷新规则或完成判定。自动适配器必须找到可测试的明确结果信号后才启用 automatic；否则保留手动能力并标注未接入。

## 5. 自动采集流程

1. 在可信的完成判定点，固定 profile_id、项目/目标、周期、run_id、判定依据和采集时间。
2. 复制实际用于判定的游戏帧；若需要新截图，验证其时间和画面上下文，不能用旧缓存或加载画面代替结果页。
3. 提交到有界后台保存队列；生产者不等待图像编码，不访问 Qt 控件。
4. 原图、缩略图落盘成功后提交索引，并通过信号刷新对应账号/项目。

后台工作只能使用提交时的不可变上下文，不重新读取当前 UI 账号或当前游戏账号。A3 的保存工作即使在切到 A4 后完成，仍属于 A3。队列满时明确记录采集失败，不无界占用内存，也不因此重复执行任务。

同一判定事件以账号、项目、目标、run_id 和事件标识去重，不通过比较图片是否相似来合并不同结果。同一项目允许多张目标证据，摘要引用对应记录。

自动采集不主动导航到额外页面；优先利用任务已经打开的结果页面。必须改变游戏导航才可取得的新证据应单独评估其任务风险，不在保存回调中偷偷执行。

## 6. 手动截图

入口一：任务卡片操作菜单中的“保存当前画面为证据”。复用现有任务操作入口，不挤占右侧开始按钮。入口二：完成检查页的“保存当前画面”。两者共用采集服务和确认对话框。

截图仅针对游戏窗口，展示预览、账号、项目、目标、状态和备注。运行中的可信账号绑定优先，显示绑定来源；无绑定时用户显式确认所属账号，左侧选中项仅作为候选，不能作为自动身份验证。预览形成后锁定图片及归属候选，切换任务或账号不能更改正在确认的证据。

采集请求经执行器安全采集边界处理，避免 UI 线程与任务线程并发操作截图设备；不发送键鼠、不跳转游戏页面。采集失败、窗口丢失、帧过期或账号绑定发生冲突时取消请求并提示，不保存旧帧。取消对话框不创建有效证据。

默认状态为 unknown。用户明确选择“手动确认完成”才记录人工结论，不调用任何生产 completion/progress 写入接口。修改备注或人工结论保留原始采集信息和变更历史；自动判定原记录不可直接篡改。

## 7. 周期与时间

时间存储使用带时区时间，展示本地化时间。国服游戏日以 Asia/Shanghai 04:00 为边界，游戏周从周一 04:00 开始。周本现有 weekly_check_window 另含周一/周日补检槽位：证据的同一游戏周不能因此拆成两个不同周，槽位可作为额外元数据保留。

深塔、战令、活动使用可确认的结算期/活动期 ID；不能确认时记录周期未知，不猜测其过期日。战令同时保留“本次奖励领取检查”时间，防止一次领取被当作整期完成。聚落按实际玩法及目标规则适配，在规则未核实时只记录本次执行结果。

现有多账号调度仍保持其既有日期规则，本模块不顺带修改；旧完成记录来自哪种周期规则必须可追溯，不能直接按新周期搬运后宣称当前完成。

## 8. 存储与恢复

使用标准库 SQLite 索引及独立图片文件，不引入外部数据库。首版在本地应用数据目录建立“完成证据”仓库，记录中仅保存仓库相对路径；NAS 与远端同步不作为依赖。图片目录按 UUID/项目/周期/证据 ID 组织，文件名不含手机号。

记录字段：schema_version、evidence_id、profile_id、project_id、target_id、run_id、event_id、captured_at、period_id、period_rule、completion_status、asset_status、source、identity_source、progress、reason、note、image_path、thumbnail_path、image_hash、created_at。周期 ID 不明确时允许为空并显式展示 unknown。

SQLite 按账号/项目/周期/时间建立索引；一个专用工作线程负责写入，读取分页，缩略图按可见范围懒加载。界面不逐张读取原图，不扫描所有目录建立每次页面内容。

写入顺序为临时图片编码、原子重命名、索引事务提交。中断后对临时文件、孤立原图、缺图索引进行恢复检查；缺图索引显示 missing，不伪装 available。孤立文件进入待整理状态，不自动猜测归属或直接删除。索引损坏时提示修复并保留原图，不空库覆盖。

首版不自动清理；显示占用空间，人工清理须预览目标与确认，并使用可恢复方式。收藏证据不进入默认清理候选。账号删除不级联删除图片，历史记录以停用账号展示，是否清理另行确认。备份应包含索引与图片的一致性快照，未来同步时不得复制活动中的 SQLite 文件作为完整备份。

## 9. 旧数据与隐私

旧完成时间可作为 legacy_record 展示“有完成记录，无图片”，保留原时间及原规则，不伪造截图。旧图片和录像只有用户确认关联，或文件本身已有可靠 UUID/项目元数据时才能关联，不能仅从模糊文件名自动判断。

保留现有日常结束录像。新仓库不复用会自动上传的诊断路径，避免未经确认上传游戏 UID 等图片信息；分享/上传功能将来单独提供预览及脱敏选项。开发测试、提交及离线渲染只使用合成账号和合成图片，不纳入真实证据。

## 11. 分阶段交付

### 阶段一：看板与手动留证

完成第六页、账号列表、项目卡片、图片预览、索引/图片保存、历史及人工确认。所有首批项目可手动留证；未接入自动采集的项目明确标注。提供模拟截图边界，确保单元及 UI 测试不访问真实游戏。

验收：账号切换只改变展示；截图与 UUID 绑定正确；人工确认不修改日常断点；取消不保存；图片缺失/写入失败有提示；布局没有内层卡片滚动条。

### 阶段二：已有任务自动采集

依次接入活跃度、周常乐园、周本、战令、残像聚落、深塔。每个适配器先核实成功信号、周期和目标集合，再编写结果帧夹具及异常测试。无法明确识别的项目保持手动，不阻塞已完成适配器交付。

验收：成功/部分完成/无法识别不混淆；奖励与战斗次数区分；A3 切到 A4 后异步保存不串号；A3 补跑成功更新摘要并保留历史；采集故障不触发重复消费。

### 阶段三：活动与扩展

在存在可验证结果识别后接入弹琴、第二索拉等自动证据；此前保持手动。海墟、矩阵等项目通过同一注册机制扩展。NAS 汇总、自动打开页面复查与远端设备同步均属独立后续需求，不属于首版验收前提。

## 12. 必须覆盖的测试

1. 六页导航顺序、默认任务页、旧路由、无重复任务入口。
2. 不同窗口宽度、长账号名、键盘操作、原图预览关闭及空状态。
3. 自动/人工/旧记录状态矩阵、冲突展示、未知截图不覆盖可靠完成摘要。
4. 游戏日 03:59/04:00、周一边界、周日补检槽位、周期未知、历史不冒充当前。
5. 不可变 UUID：改名、改序、账号删除、采集中切号、后台保存时 UI 换账号。
6. 手动截图取消、过期帧、无窗口、身份冲突，以及生产 progress/completion 零写入断言。
7. 写入前后故障注入、磁盘满、索引事务失败、孤立文件、缺失原图与损坏索引。
8. 队列满、重复事件、分页懒加载、退出时有界收尾，不能让主界面因图片编码卡顿。
9. 各自动采集点的结果图夹具和多账号失败补跑，保留原奖励/体力记录。
10. 本地仓库与诊断上传隔离，测试不读取或提交真实账号证据。
