# 每日任务优先级与有限材料目标设计

日期：2026-10-05。状态：需求已由用户逐项澄清，供实现方案和代码审阅使用。

## 目标与边界

每日任务按已核验账号的配置执行：战歌重奏 → 已选残像/梦魇聚落 → 讨伐强敌 → 凝素领域 → 无音区。当天实际活跃度达到 100 是完成判据，材料刷取服从当天体力与活跃度约束。程序不把“未选择聚落”或“程序没有打聚落”推断成活跃度不足；任务结束时以游戏页面读数为准。所有已选流程完成后若仍不足 100，领取已达成奖励并报错，不临时调用其他模块。

## 已确认的用户规则

1. 每个账号单独保存选择和进度。旧账号保存的聚落目标、周本和体力用途继续保留，不清空或重置。
2. 周本只在游戏时间的周一、周日自动检查。周一优先用本周三次领取额度，周日独立复核并补刷；周二至周六不调用。未选择周本则跳过。按北京时间 04:00 换日。
3. 聚落只由目标勾选列表触发，不再依赖“自动刷取所选目标”或“每日刷取梦魇声骸”总开关；勾选的残像聚落和梦魇聚落都要打完，列表为空就跳过。游戏进度已完成的目标无需重复战斗。
4. 讨伐强敌只在配置目标时执行，跨天累计已核实的成功领奖次数；整组目标达标后自动取消启用。下次重新设置次数是新一轮追加目标，界面不能要求用户手工计算历史累计上限。
5. 凝素目标由用户输入“还需刷出”的金、紫、蓝、绿数量，不扫描现有背包或游戏培养目标。绿色当量为 `27*金 + 9*紫 + 3*蓝 + 绿`。80 体力领取按 50 当量、40 体力领取按 25 当量估算；优先 80，目标余量不足 50 或当前体力不足 80 时选择 40。仅确认实际体力扣除后累计对应当量；目标 1 完成后进入目标 2，全部完成后自动转该账号配置的无音区。若旧账号仅选择凝素而尚未填新目标，沿用原来的不限次数刷法。原“读取培养目标/仓库”的材料规划不再由每日流程调用。
6. 无音区是凝素有限目标完成后的长期去处，也可按旧账号体力用途直接执行；有当前体力就持续刷，直到用户修改配置。没有可用体力时正常结束体力阶段。
7. 开头只访问一次活跃度页，可领取已完成的小任务积分以获得准确读数；最终宝箱留到全部耗体力任务结束后领取。任务中不为普通调度反复访问活跃度页。若需要转换备用体力，允许每次转换前做一次活跃度复核，且仅在未满 100、账号策略允许、读数新鲜、数量和余额都已核验时转换。不得使用星声或结晶溶剂。
8. 收尾在同一次活跃度页面访问中领取小任务积分、可领取宝箱并核验实际总分。达到 100 才记录该账号“每日任务完成”；不足或读数未知则保留待处理，不启动未选模块。

## 推荐结构

沿用现有 `DailyTask` 作为唯一编排入口、`NightmareNestTask` 的已选目标进度核验、`WorldBossMaterialTask` 的成功领奖日志、`DomainTask` 的体力扣除核验和 `TacetTask` 的持续刷取。增加一个很小的凝素限额计划与持久化日志，使用现有 `ConfigIntegrityService` 的账号运行状态；不复用会扫描背包的 `MaterialPlannerTask`。现有 `Which to Farm` 兼容旧账号：无音区照常持续刷；凝素无新目标时照旧持续刷，有新目标时变为“两个有限目标 → 无音区”；模拟领域沿用旧行为。增加明确的“无体力用途”选项供以后关闭，旧值不迁移成“无”。

程序应区分三个状态：**选中/未选中**、**有限目标进度**、**当天实际活跃度**。任何本地进度记录都不能替代游戏里真实活跃度读数；任何未经核实的领奖不能计入有限目标。配置修改或账号切换时，下一次点击消费前必须重新核对账号身份和当前计划。

现有体力可以按已选顺序继续使用；备用体力只用于活跃度未满时的已选体力任务，优先根据开头读到的 180 体力任务缺口设额度。进入转换前重新领取可领取的小任务积分并复核实际分数：若此时已达 100，备用转换额度归零；若未满且安全策略允许，仅补下一次领奖所需的数量。当前体力不足以执行前一项时，允许尝试耗体力更少的后一项；未完成的有限目标留到下次。

## 失败与恢复

- 周本、首领或凝素领奖状态不明：保存待核验事件，不自动重试消费；人工核对后继续。
- 聚落部分目标失败：保留未完成目标和截图，继续安全的已选流程，最终不能把该聚落模块标记完成；不能用一次声骸获取替代“全部已选聚落完成”。
- 当前体力不足：有限目标进度跨天保存；若可安全转换备用体力则先复核活跃度，否则留到下次。不因体力不足清除目标。
- 活跃度不足 100：领取已经达成的奖励后报错；不临时补刷未选模块。活跃度无法识别也不能标记完成。
- 旧账号数据迁移只新增可选字段和显示状态；旧目标名单、`Which to Farm` 与历史领奖日志原样保留。

## 非目标

不实现材料掉落 OCR、背包扫描、培养目标识别、自动推算实际库存，也不改变账号身份核验或多账号切换算法。旧“材料规划”类可留作历史代码，但每日流程不再调用。
