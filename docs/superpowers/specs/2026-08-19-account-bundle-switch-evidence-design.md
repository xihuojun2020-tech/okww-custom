# 账号配置包、序列恢复与切换证据设计

日期：2026-08-19

状态：已完成分段确认，待用户审核规格
目标版本：1.08.00

## 1. 背景与已确认根因

账号总配置上线后，账号任务意图改由 `account_master_config.json` 提供，
`daily_profiles.json` 仅作为兼容工作副本。但现有账号导出、导入、自动备份和旧版本序列
迁移仍以旧文件为中心，尚未适配新的权威边界。

运行端的只读检查已经确认：

- `account_master_config.json` 和 `daily_profiles.json` 都保留了 12 个账号；
- 总配置的 `sequences` 是空对象；
- `MultiAccountDailyTask.json` 仍保存序列一 4 个账号、序列二 8 个账号；
- 首次锚定只读取 `daily_profiles.json` 顶层的 `sequences`，没有读取旧多账号任务文件。

因此，问题不是账号方案被删除，而是首次锚定遗漏了序列归属。总配置成为唯一可信来源后，
旧任务文件中仍存在的序列二不再参与 UI 和任务执行，表现为“序列二配置消失”。

账号切换测试已经成功，并且当前测试会调用 `MultiAccountDailyTask` 的底层选号和登录方法；
正式任务的 `_select_and_login_account` 仍单独编排相同步骤，存在测试路径成功但正式编排以后
再次漂移的风险。

现有 `self.screenshot('multi')` 会把单张当前帧写入普通截图目录。截图不会在 OCR 后立即
删除，通常在程序启动时删除 7 天前的文件；目录超过框架上限时还可能整目录清空。截图
没有持久的实际点击点、目标 OCR 框或重试上下文，不能有效审核点击是否命中。

## 2. 目标

1. 使账号导出、导入和备份遵守“总配置唯一权威、工作副本只作兼容”的边界。
2. 在首次锚定、旧导出导入和已经产生空序列总配置的场景中可靠恢复全部序列。
3. 使用稳定 UUID 保存序列和运行进度，避免显示名、备用名变化造成错配。
4. 导入和恢复均先预检、再确认、后事务写入，任一步失败可以字节级回滚。
5. 正式多账号每日任务与账号切换测试使用同一个公开切换入口。
6. 成功时不持久化大量切换截图；失败时保留最近一段时间的可审核证据。
7. 对失败证据和备份实施按事件、时间和容量的可预测清理，不再突然清空整个目录。
8. 为以后增加账号专属配置、运行状态和 UI 偏好保留版本化扩展空间。

## 3. 非目标

- 不在本版本制作可写的总配置编辑器；总配置仍由程序外部工具或 AI 编辑。
- 不允许普通任务配置保存路径反向写入总配置。
- 不自动合并两份都非空且内容不同的序列，以免猜错用户意图。
- 不把成功切换过程的全部视频长期写入磁盘。
- 不建立数据库或完整的不可变配置历史库。
- 不改变账号身份匹配规则的安全原则：身份歧义必须停止，不能猜测登录。

## 4. 权威数据与兼容数据

### 4.1 权威数据

`account_master_config.json` 继续唯一记录：

- 稳定 `profile_id`；
- 显示名称和备用识别名称；
- 账号专属任务设置；
- 计划字段和扩展字段；
- 序列名称、成员 UUID 及成员顺序。

程序运行期间只能通过已经明确批准的锚定、受控导入、备份恢复或遗漏序列修复事务修改
总配置。普通 UI 配置保存、每日任务完成记录和账号切换不得写入它。

### 4.2 兼容工作副本

`daily_profiles.json` 由总配置生成。导入、恢复或序列修复完成后必须重新生成兼容投影，
并立即执行规范化比较。工作副本不能作为后续更改总配置的来源。

### 4.3 运行数据

`account_runtime_state.json` 和 `multi_account_progress.json` 保存完成记录、断点、当前游标
和已接受总配置指纹。导出时它们进入独立的 `runtime_data` 分区，不能混入账号任务意图。

### 4.4 非权威任务偏好

`MultiAccountDailyTask.json` 中“当前序列”等 UI 偏好可以导出，但序列成员字段仅作为旧版
迁移来源，不再是权威数据。过期的“当前执行账号”不跨设备恢复，避免导入后错误旋转序列。

## 5. 序列迁移与遗漏修复

### 5.1 统一迁移输入

首次锚定和旧格式导入都构造两个候选来源：

1. `daily_profiles.json` 或旧导出文件顶层的 `sequences`；
2. `MultiAccountDailyTask.json` 中明确存在的 `序列 N 账号` 字段。

旧任务键转换为规范序列名时去掉键名中仅用于 UI 的空格，但保留原序号、成员顺序和空序列。
成员通过以下信息映射到唯一 `profile_id`：

- 已有 UUID；
- 完整方案键或显示名称；
- 精确短名，例如 A1 与 A10 不得相互命中；
- 备用识别名称；
- 唯一匹配的掩码手机号身份。

未知成员或一个身份命中多个账号时，迁移失败并生成可读错误，不删除原文件。

### 5.2 来源选择规则

- 只有一方包含序列：使用该方；
- 两方规范化后完全一致：使用任一方并记录双源一致；
- 两方都为空：允许生成空序列总配置；
- 两方都非空且不同：阻止锚定或导入，展示按序列和成员位置组织的差异，由用户选择来源；
- 不进行并集、交集或按序列名静默拼接。

### 5.3 已锚定空序列的修复

启动完整性检查通过后，如果同时满足下列条件，显示一次“恢复旧版遗漏序列”提示：

- 当前总配置合法且 `sequences` 为空；
- 旧多账号任务文件至少有一个明确的序列字段；
- 至少一个旧序列包含账号，或旧文件明确选择了一个需要保留的空序列；
- 所有旧成员都能唯一映射到现有总配置账号。

用户确认后执行三文件事务：备份总配置、工作副本和运行状态，写入 UUID 序列，重建工作
副本，更新已接受指纹并完整复检。失败时按原始字节回滚。总配置已有非空序列时绝不从
旧任务文件自动覆盖。

修复完成后写入一次性迁移标记，避免每次启动重复询问。用户拒绝时不修改数据，并保留
以后从设置页再次发起修复的入口。

## 6. 账号配置包 v2

### 6.1 文件形式

使用一个 UTF-8 JSON 文件，继续采用用户和外部 AI 容易读取、比较和编辑的形式。顶层结构：

```json
{
  "type": "okww_account_bundle",
  "bundle_version": 2,
  "manifest": {},
  "master_config": {},
  "runtime_data": {},
  "preferences": {},
  "extensions": {}
}
```

`manifest` 至少包含程序版本、导出时间、配置 ID、各分区 SHA-256 和导出能力标记。
未知的命名空间扩展在程序支持的情况下原样保留。

### 6.2 导出

默认导出：

- 完整总配置，包括所有账号和所有序列；
- 按稳定 UUID 组织的完成记录和多账号断点；
- 当前序列等非权威偏好；
- 清单和校验值。

导出只读取已经通过完整性检查的冻结快照，不从可能过期的工作副本拼装权威内容。导出
完成日志报告账号数、序列数、运行记录数和文件位置，不输出完整敏感身份。

### 6.3 导入预检

导入在内存中完成以下步骤，预检通过前不写文件：

1. 检查文件类型、格式版本、JSON 结构和支持的能力；
2. 校验清单哈希；
3. 验证账号 UUID、显示名、别名唯一性和序列引用；
4. 与当前总配置比较，生成账号、任务字段、序列和运行记录的增删改摘要；
5. 验证工作副本能由候选总配置无损生成；
6. 显示将保留、替换和忽略的非权威字段。

SHA-256 不匹配视为“文件在导出后被修改”，默认不直接导入。只要结构、身份和语义验证
全部通过，用户可以再次明确选择“信任此外部修改并导入”。该选择和新指纹写入事务日志。

### 6.4 导入事务

导入采用完整替换账号总配置，不自动做部分账号半合并。执行顺序：

1. 获取配置事务锁并暂停账号自动任务；
2. 创建导入前快照和清单；
3. 写入候选总配置临时文件并重新读取验证；
4. 从候选总配置生成兼容工作副本；
5. 按 `profile_id` 恢复包内运行记录；包内无对应账号的记录不误配；
6. 恢复允许的非权威偏好；
7. 原子替换正式文件；
8. 更新已接受总配置指纹；
9. 重新执行完整性检查和引用检查；
10. 全部通过后恢复任务可用状态并记录成功。

任一步失败，恢复事务前涉及文件的原始字节并再次验证。回滚失败时进入安全模式并保留
全部证据，禁止继续账号任务。

### 6.5 旧格式兼容

旧 `okww_account_config` v1 文件先在内存中升级为 v2 候选。旧 `profiles`、`sequences`、
`active_profile` 和嵌在方案中的完成记录分别进入新结构。缺失序列时允许用户选择同目录或
当前工作目录中的旧 `MultiAccountDailyTask.json` 作为补充来源；冲突遵守第 5.2 节。

## 7. 可验证备份与恢复

### 7.1 每日快照

每日首次启动复制整个 `configs` 到独立快照目录，并额外写入清单：程序版本、文件相对路径、
长度、修改时间和 SHA-256。快照使用临时目录生成，清单校验通过后再原子改名为完成状态，
避免把半份备份标记为可恢复。

默认保留最近 30 个完整每日快照，总备份容量不超过 2GB；达到限制时按快照整体从旧到新
清理，不删除单个快照内部文件。

### 7.2 事务快照

每次导入、备份恢复和遗漏序列修复之前创建事务快照，默认保留最近 20 个。事务快照和每日
快照分目录存放，避免每日清理误删刚生成的回滚点；两类快照共同受 2GB 总量限制，但优先
删除最旧每日快照，再删除超过 20 个的旧事务快照。

### 7.3 验证与恢复

设置页提供：

- 验证选定备份；
- 查看文件缺失、额外文件和哈希差异；
- 预览恢复后的总配置和序列摘要；
- 经确认后执行事务恢复。

恢复不能直接复制覆盖正在使用的文件，必须复用第 6.4 节的锁、预检、原子替换、复检和
回滚流程。

## 8. 唯一账号切换入口

新增一个生产级公开入口，语义为“从当前可恢复状态切换并登录唯一目标账号”。该入口完整
负责：

1. 完整性复检和停止状态检查；
2. 等待登录界面稳定；
3. 展开账号列表；
4. OCR 身份映射和目标框选择；
5. PostMessage 点击及必要时的系统鼠标降级；
6. 连续确认下拉列表收起且显示账号与目标一致；
7. 登录前再次核对目标；
8. 点击登录并确认登录界面开始转换；
9. 等待游戏主界面。

正式多账号任务只计算下一个目标，然后调用该入口。测试任务的单账号模式和 A1、A3、A4
连续模式也调用同一入口。连续测试只在相邻目标之间调用生产退登方法，不写每日任务完成
记录。

旧 `_select_and_login_account` 仅保留“选择下一个目标”的职责，不能再复制点击、确认、登录
和 `ensure_main` 编排。测试通过因此直接覆盖正式任务使用的切换链路。

精确短名、备用名、掩码手机号、身份歧义检查、每阶段独立重试预算和停止信号传播仍在生产
实现中统一维护。账号显示与目标不一致时重新选择；只有用尽该阶段预算后才安全停止。

## 9. 账号切换失败证据

### 9.1 内存环形缓冲区

每次账号转换开始时创建一个独立证据会话。会话在内存中保存最近 60 秒关键帧，普通采样
最多 30 帧；每次实际点击、重试模式变化、账号识别变化和界面阶段变化都强制记录，不受
普通采样间隔限制。帧使用有界压缩数据，不能无限占用内存。

切换成功后立即丢弃该会话，不把常规识别帧写入磁盘。停止信号同样能中断采样，证据模块
不得抢占窗口、发送输入或阻碍任务停止。

### 9.2 失败事件目录

失败或安全停止时，把当前会话一次性写入：

`screenshots/account_switch_failures/<时间>_<事件ID>_<阶段>/`

每个事件至少包含：

- 最近关键帧的标注图片；
- `event.json`，记录目标账号、当时识别账号、阶段、尝试次数、交互模式和时间线；
- OCR 目标框；
- 窗口客户区坐标、换算后的屏幕坐标和实际投递坐标；
- 与该会话相关的结构化诊断消息。

图片先走现有隐私模糊处理。红色矩形表示目标 OCR 框，红色圆圈和十字表示实际点击点，
文字同时标出目标框中心、实际投递点、PostMessage 或系统鼠标方式及重试编号。这样可以
区分 OCR 选错、坐标换算错误、窗口句柄变化和游戏未接收点击。

### 9.3 清理规则

失败证据采用用户确认的三重限制：

- 只保留 7 天；
- 最多 20 个完整失败事件；
- 总容量最多 500MB。

超过任一限制时按事件整体删除最旧目录。程序启动后立即清理，运行期间每 6 小时清理一次，
创建新事件前再做一次轻量检查。清理只作用于专用失败证据目录，不再因普通截图目录超过
框架阈值而删除这些证据。

## 10. UI 与用户报告

- 导出按钮说明改为“从已验证总配置导出账号配置包 v2”；
- 导入按钮在总配置模式下可用，但必须经过预检、摘要和二次确认；
- 增加“验证/恢复备份”和“恢复旧版遗漏序列”入口；
- 发现空总配置序列且旧文件可恢复时，启动提示明确显示将恢复的序列数量和账号数量；
- 失败通知显示证据目录、失败阶段和最后识别账号；
- 所有确认按钮均使用正常可点击的明确操作，不依赖禁用控件表达选择；
- 总配置仍在 UI 中只读，普通方案编辑控件不得因此重新获得写权限。

## 11. 错误处理

- 序列来源冲突：不自动合并，保存差异并等待用户选择；
- 序列成员未知或歧义：阻止迁移并列出对应序列和成员位置；
- 导出时完整性失效：拒绝导出过期或污染数据；
- 导入包格式过新：报告所需最低程序版本，不降级猜测；
- 导入后复检失败：字节级回滚并进入安全模式；
- 运行状态中包含包内不存在的 UUID：隔离为未恢复记录，不分配给名称相似账号；
- 失败证据写盘失败：不得掩盖原始切换异常，日志记录证据保存失败；
- 磁盘空间不足：先执行证据和备份清理；仍不足时停止写入并保留原配置；
- 用户点击停止：`TaskDisabledException` 原样传播，切换与证据写入不得继续点击或抢前台。

## 12. 测试与验收

### 12.1 配置与迁移

- 旧工作副本无序列、旧多账号文件含序列一和序列二时，首次锚定完整保留两者及顺序；
- 已锚定空序列时能在确认后恢复，拒绝时零写入；
- 双源一致正常迁移，双源冲突阻止并报告；
- 短名 A1/A10、备用名和掩码身份唯一映射，歧义时阻止；
- 迁移事务任一步失败时相关文件字节完全恢复。

### 12.2 导出、导入与备份

- v2 导出只取总配置权威快照，包含所有序列和独立运行数据；
- v1 文件可升级，非法、空、过新和哈希变化文件走正确分支；
- 导入预检不写文件；确认后原子替换并重建兼容副本；
- 运行记录只按 UUID 恢复；
- 每日快照和事务快照清单可验证；
- 快照保留数量、容量和整体清理符合规则；
- 恢复失败时可回滚。

### 12.3 账号切换

- 正式任务与测试任务都通过同一公开切换入口；
- A1、A3、A4 连续测试覆盖与正式任务相同的退登、选号、确认和登录方法；
- 别名、掩码手机号、列表重排和屏幕点击降级继续通过；
- 账号不一致时重新选择而非立即停止；
- 各阶段重试预算互不共享；
- 停止信号可以在 OCR、等待、退登、点击确认和证据保存阶段及时退出。

### 12.4 失败证据

- 成功切换不产生持久事件目录；
- 失败保存最近关键帧、目标框、实际点击点和结构化事件；
- 坐标标注同时覆盖窗口坐标与屏幕坐标；
- 7 天、20 事件、500MB 任一超限均按完整事件删除最旧项；
- 清理不会误删普通截图、配置备份或未完成的新事件。

## 13. 发布与兼容性
