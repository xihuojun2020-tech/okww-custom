# 按日诊断归档与上传进度设计

## 目标

将日志与截图按本地日期归档，并区分两种上传语义：

- 手动上传仅包含点击时已封存的当日资料。
- 次日首次启动自动上传前一日未手动上传的资料；若间隔多日未启动，按日期从旧到新补传所有历史待传资料。
- 手动上传后当天新产生的资料不会遗漏，可再次手动上传，否则次日自动补传。
- 打包和上传显示阶段、字节进度、百分比、速度、已用时间和预计剩余时间。
- 保持直接上传策略：不恢复 NAS 全量回读校验，不设置人为单包体积上限。
- 成功上传后本地资料仍保留一天；上传失败时保留 ZIP、原始批次和进度，可继续重试。

## 日期与批次归属

每个已封存批次以 `manifest.created_at` 转换得到电脑本地日期。日期选择只依赖不可变批次清单，不依赖原始日志或截图的修改时间。

- 手动选择器：批次日期等于今天，且批次状态不是 `uploaded` 或 `logs_purged`。
- 自动选择器：批次日期早于今天，且批次尚未上传。
- 同一 ZIP 只包含一个日期。
- 跨午夜持续运行时，批次按实际封存时间归属；不将整个会话强制归到启动日。

归档文件名：

- 手动：`okww诊断证据_YYYYMMDD_手动_HHMMSS_<id>.zip`
- 自动：`okww诊断证据_YYYYMMDD_自动_HHMMSS_<id>.zip`

回执额外保存 `day` 和 `mode`，便于界面、保留策略和故障诊断区分操作。

## 组件与边界

### 日期选择和归档构建

`src/runtime/diagnostic_archive.py` 提供一个可按日期选择的共享归档入口，手动和自动流程必须复用它，不维护两套打包实现。它负责：

- 必要时封存正在运行会话已写入的内容。
- 按目标日期过滤待传批次。
- 在开始写 ZIP 前固定当次批次列表和总数。
- 在打包过程中更新已完成批次数。
- 保留现有 ZIP 内部清单和建包时本地完整性检查。

### 手动协调器

`manual_upload(root)` 改为只处理当天。它不优先发送旧版生成的跨日期 ZIP，而是从原始未确认批次重新按天建包。点击后才新产生的批次不加入正在进行的 ZIP。

### 启动自动协调器

`src/runtime/diagnostic_lifecycle.py` 在诊断会话初始化后启动独立后台线程。协调器：

1. 恢复上次异常终止会话中可封存的数据。
2. 扫描今天之前存在未上传批次的日期。
3. 按日期从旧到新串行打包和上传。
4. 任一日失败时停止本轮，保留当日进度和错误。
5. 同一本地日内，成功扫描后记录检查日期；如果仍有失败待传数据，后续重启仍允许重试。

自动协调器的异常不向主启动流程传播，不影响 GUI 或游戏任务启动。

### 进度快照

`archives/progress.json` 是手动和自动操作共用的持久快照，至少包含：

```json
{
  "mode": "automatic",
  "day": "2026-09-15",
  "stage": "uploading",
  "archive": "...zip",
  "completed_batches": 1200,
  "total_batches": 4787,
  "copied": 650117120,
  "total": 1621932239,
  "speed_bps": 19451084,
  "average_speed_bps": 18126322,
  "elapsed_seconds": 35.8,
  "eta_seconds": 49.9,
  "updated_at": 1789480000
}
```

`stage` 可取：

- `discovering`：检查待传日期。
- `sealing`：封存当前已写日志。
- `packing`：写入 ZIP。
- `connecting`：建立 NAS 连接。
- `uploading`：复制 ZIP。
- `recording`：写入远端回执并确认批次。
- `uploaded`：当日完成。
- `failed`：失败并等待重试。
- `idle`：没有适用的待传资料。

所有快照继续使用原子 JSON 替换，界面只读取完整快照。

## 上传与速度统计

上传保持单次顺序写入 NAS `.partial` 文件，写完后比较文件大小并原子改名，不对 NAS 文件做全量回读哈希。

速度与时间计算：

- 每秒最多更新一次进度，避免频繁磁盘写入。
- `average_speed_bps = copied / elapsed_seconds`。
- `speed_bps` 使用最近约 5 秒的字节与时间差计算；样本不足时使用平均速度。
- `eta_seconds = (total - copied) / speed_bps`，速度为零或文件太小时设为 `null`。
- 完成时保留最终大小、用时和平均速度。

断点续传处理：

- `.partial` 小于本地 ZIP 时，本地源文件和 NAS 目标同时定位到已有大小，从该偏移继续写入。
- `.partial` 大于本地 ZIP 时，截断并从头重传。
- `.partial` 与本地 ZIP 大小相等时，直接改名并记录回执。
- 恢复上传时 `copied` 从既有偏移开始，速度只统计本次恢复后的传输。

## 并发和操作优先级

同一诊断根目录同时只允许一个打包或上传操作，继续复用本地 `.archive.lock` 和 `.uploader.lock`。

- 自动历史上传正在运行时，手动按钮不启动第二个任务，界面说明正在处理哪一天。
- 手动上传正在运行时，启动自动线程只记录待处理，当前启动不抢占。
- NAS 远程保留清理不阻塞上传；正式 ZIP 及回执出现前，清理任务不会将 `.partial` 视为已上传证据。

## 界面

`日志与诊断` 卡片每秒读取一次进度快照，不从工作线程直接调用 Qt 控件。

上传中显示：

```text
自动上传：2026-09-15
阶段：正在上传
进度：620 MiB / 1.51 GiB（40.1%）
速度：18.6 MiB/s
已用：36 秒｜预计剩余：50 秒
```

打包中显示：

```text
手动上传：2026-09-16
阶段：正在打包
批次：1250 / 1840
```

失败时显示日期、模式、失败阶段、最后进度和经现有错误映射处理后的可操作信息。自动失败时明确说明下次启动会重试；手动按钮仍只处理今天。

## 失败、恢复和保留

- 启动自动上传、手动上传和远端清理的失败不影响日志采集与主程序运行。
- 失败时快照记录 `stage=failed`、失败前阶段和经清理的错误文本。
- 未成功的原始批次、ZIP 和 `.partial` 不按成功策略删除。
- 只有远端正式 ZIP 和回执写入后才标记批次 `uploaded`。
- 已成功批次和本地 ZIP 继续使用上传后一天的本地保留期。
- 旧版跨日期 `packed`/`oversized` ZIP 保留为本地历史产物，不用它确认新的按日批次。它们不再阻塞按日建包，也不会被自动上传。

## 测试与验收

单元和集成测试至少覆盖：

1. 手动上传只选择今天。
2. 自动上传不选择今天。
3. 次日首次启动上传昨天。
4. 多日未启动时按日从旧到新补传。
5. 当天手动上传后新产生的资料在次日补传。
6. 已上传批次不重复。
7. 跨午夜会话按批次日期拆分。
8. 历史跨日 ZIP 不会被新流程直接上传。
9. 打包阶段进度包含已完成和总批次。
10. 上传阶段提供字节进度、当前速度、平均速度、用时和 ETA。
11. `.partial` 中断后从现有偏移续传。
12. 异常 `.partial` 大小会触发安全重传。
13. 自动上传失败不阻止主程序启动，且下次启动可重试。
14. 手动和自动上传不并发。
15. 成功一天后才清理本地资料。
16. 打包版模块导入、启动和 GUI 冒烟测试通过。

实机验收使用一个可控的小型当日包和一个历史包，确认界面阶段、速度、ETA、NAS 文件和回执一致。不使用当前数 GiB 历史证据作为自动化测试输入。
