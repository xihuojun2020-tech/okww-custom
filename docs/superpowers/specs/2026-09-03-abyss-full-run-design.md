# 自动深渊三塔完整流程设计

## 目标

把现有“扫描三塔并完成一队编队”扩展为完整的三塔自动挑战任务。任务仍位于测试功能中，只支持中文 PC 客户端与 16:9 的 1920×1080、2560×1440 布局。

## 已确认规则

- 塔顺序可选：`两侧塔优先` 为残响、回音、深境；`中间塔优先` 为深境、残响、回音。
- 每座塔先扫描 1～4 个实际存在的关卡，从第一个未完成且可挑战的关卡开始。
- 左右塔各层每名角色消耗 1、2、3、4 点体力；中塔每层每名角色固定消耗 5 点体力。
- 每座新塔开始时重新进入快速编队页并扫描角色；三名角色的当前体力都必须覆盖该塔全部剩余关卡的总消耗。
- 同一座塔内点击“继续挑战”后沿用当前队伍，不重新扫描、不重新编队。
- 成功且有“继续挑战”时进入下一层；成功且只有“再次挑战”时本塔完成并返回深塔；失败时返回深塔并跳过本塔剩余关卡。
- 一座塔已全部完成时直接跳过；体力不足或无法组成三人队时安全返回三塔页，记录原因并继续下一塔。
- 三塔结束后汇总完成、失败、已完成跳过和体力不足状态。

## 结构

`abyss_team_planner.py` 保持纯逻辑职责，增加最低体力过滤与塔顺序、剩余体力计算。`AutoAbyssTask.py` 复用 `BaseCombatTask` 的角色战斗逻辑，并负责页面扫描、组队、进入地图、启动战斗、结算分类和三塔调度。已有 OCR、模板、点击和角色头像识别继续复用，不增加依赖。

关卡存在性由三类证据合并：完成图标、锁定图标、左侧大号楼层数字。只允许从第一层开始连续存在；不存在的尾部行被裁掉，出现中间缺口时截图并停止，以免点击错误区域。

## 状态机

1. 进入逆境深塔三塔页，按配置顺序逐塔处理。
2. 打开一座塔并扫描实际楼层；无可挑战层则记录已完成或未解锁并返回。
3. 计算该塔剩余总消耗，进入第一个未完成关卡的快速编队页，扫描角色并只使用体力达到门槛、等级大于 60 的角色。
4. 完成编队后点击“开启挑战”，等待加载；识别到“环境特性”提示后按一次 Esc 关闭，确认队伍世界态。
5. 向前寻找“开启挑战”交互并按 F，调用现有自动战斗。
6. 战斗结束后只接受标题与按钮组合完整的结果页：`挑战成功+继续挑战+返回深塔`、`挑战成功+再次挑战+返回深塔`、`挑战失败+再次挑战+返回深塔`。
7. 继续挑战时楼层计数加一并重复地图启动与战斗；其他结果点击“返回深塔”。单塔循环最多四次。

## 错误处理

- 结果页 OCR 不完整、楼层存在性不连续或页面结构异常时截图并停止整个任务，不进行猜测点击。
- 深塔内角色死亡不得调用通用传送复活。任务覆盖 `revive_action()` 返回 `False`，让战斗逻辑抛出 `CharDeadException`；当前层随后等待失败结算页并按失败规则返回。
- 体力不足属于可恢复的单塔结果，不中止其他塔；退出快速编队/编辑队伍直到回到三塔页。
- 每个关键阶段通过现有状态监控显示塔名、层数、体力要求、战斗、结算与汇总。
