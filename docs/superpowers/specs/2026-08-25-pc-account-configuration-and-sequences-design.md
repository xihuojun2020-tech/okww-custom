# PC 账号配置与序列管理设计

## 目标

将封存分支中经过验证的账号管理能力按以下顺序吸收到 PC 主线：

1. 统一账号身份解析；
2. 增加简化、安全的账号配置页面；
3. 把序列管理从任务类拆到独立服务与页面；
4. 为账号序列运行生成不可变快照；
5. 评估而不立即执行“每账号独立目录”迁移。

本次不引入 Android、MuMu、ADB、Combat Agent、设备绑定、安装器或重型诊断系统。

## 当前问题

主仓库已具备配置完整性、配置包、备份恢复、账号运行状态和多账号切换流程，但账号身份规则分散在配置完整性与任务代码中；账号方案页面只能新建、重命名、删除和切换；序列管理的 Qt 界面、文件操作与任务逻辑耦合在 `MultiAccountDailyTask`；运行期间仍可能重复读取可变配置。

封存分支提供了可借鉴实现，但其账号仓库、安装器、诊断和 Android 代码范围过大，不能整体回灌。

## 总体架构

保持主仓库现有总配置与完整性服务为权威来源，在其上增加三个小边界：

- `account_identity.py`：唯一的账号身份规范化与解析实现；
- `account_config_editor.py`：面向单账号的草稿、差异、修订检查、备份和确认保存服务；
- `sequence_repository.py`：序列的读写、引用校验、顺序调整与运行快照服务。

GUI 只调用服务，不直接读写 JSON。生产多账号任务与 `TestAccountSwitchTask` 只消费同一份不可变运行快照，不各自实现解析或序列逻辑。

## 第一阶段：统一账号身份解析

新增 `src/account_identity.py`，提供：

- `normalize_identity(value) -> str`
- `split_identity_values(value) -> list[str]`
- `masked_phone(value) -> str`
- `short_profile_name(value) -> str | None`
- `profile_identity_values(profile_name, profile) -> frozenset[str]`
- `resolve_profile_identity(observed, profiles) -> str | None`
- `resolve_profile_short_names(short_names, profiles) -> list[str]`

规则：

- 短名必须精确匹配，A1 不得匹配 A10；
- 重复短名和重复身份必须拒绝，而不是选择第一个；
- 完整手机号只参与内存中的受控匹配，显示和错误消息必须掩码；
- `MultiAccountDailyTask`、`TestAccountSwitchTask` 和配置完整性服务复用该模块；
- 保留原有公开函数的兼容包装，避免一次性破坏调用方。

## 第二阶段：简化账号配置页面

新增 `AccountConfigEditor` 与 `AccountConfigTab`。页面允许用户选择账号，查看掩码身份、稳定 UUID、修订号和修改来源，并编辑现有账号的非敏感任务字段。

第一版允许编辑：

- 账号短名；
- 执行方式与执行时间；
- 体力用途及各任务选择；
- 已存在的布尔型日常任务开关。

第一版禁止修改：

- `profile_id` 或任何稳定 UUID；
- 登录账号、完整手机号、密码和令牌；
- 配置文件路径、序列引用与设备字段；
- 未在现有配置 schema 中出现的未知字段。

保存流程：

1. 加载账号并记录修订号或内容指纹；
2. 页面修改只进入内存草稿；
3. 保存前展示新增、修改、删除差异，敏感值统一掩码；
4. 用户确认当前账号短名；
5. 创建单账号备份；
6. 再次检查修订号/指纹；
7. 使用现有原子写入与完整性服务保存；
8. 保存失败保持原文件，页面继续保留草稿。

外部 JSON 变化只提示重新加载；第一版不实现封存分支中完整的“接受外部版本/恢复已接受版本”工作流，以免同时引入第二套权威状态。

## 第三阶段：独立序列管理

新增 `SequenceRepository` 与 `SequenceManagementTab`，并删除 `MultiAccountDailyTask.manage_sequences()` 中内嵌的 Qt 对话框和直接文件写入。

序列成员持久化为稳定账号 UUID；显示时再解析为账号短名和掩码身份。页面支持：

- 新建、复制、重命名、启用/停用和删除序列；
- 添加、移除账号；
- 上移、下移账号；
- 显示引用失效、重复成员和未确认配置错误。

约束：

- 删除仍被序列引用的账号时明确阻止并列出序列；
- 序列不得包含不存在或重复的账号；
- 重命名和保存使用修订号/指纹检查；
- 不引入模拟器设备冲突规则；
- 兼容读取现有 `daily_profiles.json` 顶层 `sequences`，首次保存仍使用现有权威存储，不立即迁移文件格式。

## 第四阶段：不可变运行快照

任务启动时由序列服务一次性生成 `SequenceRunSnapshot`：

- 序列名称与序列修订；
- 有序账号 UUID；
- 每个账号的只读配置深拷贝；
- 启动时指纹和唯一运行 ID。

`MultiAccountDailyTask` 与 `TestAccountSwitchTask` 使用同一快照构造入口。运行中页面或外部文件发生变化时，只影响下一次运行；当前任务不重新读取账号配置或序列成员。完成进度仍按账号 UUID 写入现有运行状态文件，不写回快照。

## 第五阶段：独立目录迁移评估

本阶段只形成评估报告与迁移测试，不改变生产数据格式。评估内容包括：

- 现有总配置到每账号目录的字段映射；
- 账号、任务、接受摘要的文件边界；
- 旧版读取兼容、回滚和断电恢复；
- 导入导出、备份恢复和完整性服务的影响；
- 与现有用户配置的双向一致性风险。

只有在前四阶段稳定且迁移测试证明可无损回滚后，才另行设计和请求批准生产迁移。

## 错误处理与安全

- 所有写操作必须先备份并使用原子替换；
- 修订号或指纹不一致时拒绝覆盖并要求重新加载；
- 完整手机号、备用登录名和其他敏感身份不得出现在差异、日志、通知或异常文本中；
- 单账号错误只阻断该账号及引用它的序列，不阻断无关账号；
- 账号切换测试必须继续复用生产账号选择、验证、重试、退出和登录方法；
- PC 端现有点击与 OCR 行为保持不变。

## 测试策略

每个阶段独立交付并回归：

1. 身份解析：覆盖 A1/A10、别名、掩码与完整手机号、重复身份、缺失短名；
2. 配置编辑：覆盖草稿隔离、只读字段、敏感掩码、备份、原子保存和并发修改拒绝；
3. 序列管理：覆盖增删改名、顺序、重复/失效引用、账号删除保护和旧格式兼容；
4. 运行快照：覆盖运行中配置变化不影响当前任务，生产与测试入口生成相同快照；
5. 迁移评估：使用临时目录进行往返转换、故障注入和回滚验证，不接触用户真实配置。

每阶段完成后运行对应聚焦测试；最终运行账号仓库、配置完整性、配置包、备份恢复、多账号任务、账号切换和 GUI 启动回归。

## 版本与发布

这是中等规模功能，代码完成后按项目规则提升第二版本位并将第三位归零；产品更新说明与 `config.py` 同步。未经完整测试，不创建正式版本标签。发布动作遵循仓库规则，但不得把封存分支的 Android 代码包含在提交中。
