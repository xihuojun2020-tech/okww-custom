# 账号切换前台 BitBlt 与精确入口点击设计

## 目标

在不修改全局 WGC 和 `PostMessage` 配置的前提下，让 PC 多账号切换从开始到登录完成都使用任务级捕获策略：主游戏窗口优先使用经过前台校验的 BitBlt，失败时回退 WGC；独立 `#32770`、`ComboBox`、`ComboLBox` 继续使用各自 HWND 的客户区 BitBlt；所有鼠标输入继续统一走经过 HWND、PID、前台、坐标和命中窗口校验的 `SendInput`。

同时修复 2026-09-01 实机续测发现的启动入口问题：游戏停留在“点击连接”页时，通用登录文本可能误命中“登录状态”等非按钮文本，记录点击已投递但界面不转换，随后账号切换等待 120 秒超时。

## 已批准方案

1. 不调用 `DeviceManager.set_capture()`，不持久化修改设备截图方式，不关闭或重建全局 WGC。
2. `LoginFlowService.switch_to_account()` 在完整账号切换生命周期内持有一个任务级前台 BitBlt 会话，并在成功、异常和用户停止时释放。
3. 主窗口每次识别前都重新确认游戏 HWND/PID并强制前台；BitBlt 帧无效、纯色、尺寸异常或捕获期间前台变化时，本轮回退 WGC。
4. 每个识别框必须携带生成它的 HWND、屏幕原点、截图来源和时间戳；禁止把 BitBlt OCR 坐标与另一张 WGC 帧的原点混用。
5. 独立登录窗口及弹出控件继续按各自 HWND 捕获，不尝试让主窗口 BitBlt 或 WGC包含这些顶层窗口。
6. “点击连接”使用独立、精确、限定底部中央区域的文本集合，不复用宽泛的 `LOGIN_TEXTS`。
7. “登录”按钮只接受完整按钮语义，不允许“登录状态”一类包含关系命中。
8. “点击连接”最多投递三次；每次重新捕获、重新 OCR、重新置前和重新计算坐标。只有入口消失并出现账号登录界面特征或独立登录窗口，才算确认成功。
9. 账号列表展开、选号、登录按钮仍使用 `SendInput`；`PostMessage`、固定坐标、固定行号、UIA、`CB_SETCURSEL` 和直接 Win32 选择消息均不作为生产回退。
10. 投递成功与界面确认继续分开记录；无法确认目标账号时安全停止，不尝试登录。

## 生命周期

```text
LoginFlowService.switch_to_account
  -> 创建任务级 AccountSwitchCaptureSession
  -> 世界页/设置页/退登确认：主 HWND 前台 BitBlt，WGC 后备
  -> 点击连接页：主 HWND 前台 BitBlt，精确 SendInput
  -> #32770 登录窗：该 HWND 客户区 BitBlt
  -> ComboBox/ComboLBox：各自 HWND 客户区 BitBlt
  -> 登录按钮：当前登录 HWND BitBlt + SendInput
  -> ensure_main：主 HWND WGC/正常任务路径
  -> finally 释放会话并清理任务临时引用
```

如果账号切换开始时已经位于登录界面，则跳过世界页和“点击连接”入口；如果已经位于游戏世界，则复用同一会话完成退登。会话不得跨越整个每日任务，只覆盖单次账号转换。

## 失败策略

- 无法确认当前目标 HWND/PID：不截图、不点击，记录错误并按现有预算重试。
- 前台 BitBlt 无有效帧：记录黄色告警，本轮回退 WGC。
- WGC 也无有效帧：状态保持未知，只等待下一轮。
- “点击连接”投递后入口仍存在：记录 `delivered=True, confirmed=False`，重新观察后重试。
- 独立登录窗口在操作前消失：丢弃旧句柄和坐标，重新枚举。
- `ComboLBox` 命中必须同 PID、坐标仍在目标矩形内，且窗口类明确为 `ComboLBox`；其他无关同进程窗口仍拒绝。
- 所有资源在 `finally` 中释放；捕获清理失败不得覆盖原始任务异常。

## 测试与发布边界

- 自动测试只使用伪帧、伪 HWND、伪 OCR、伪捕获会话和伪 `SendInput`。
- 实机回归只由最新版 OKWW 启动 A3/A4 多账号任务；不得人工代替程序点击“点击连接”、账号项或登录按钮。
- 报告与日志摘要只使用 A3/A4 短名，不输出手机号、备用登录名、UUID、特征码或内部身份值。
- 先把当前 `1.22.02` 候选源码推送到独立 GitHub 备份分支，再修改业务代码。
- 新修复是小版本，最终发布版本为 `1.22.03`；同步 `config.py`、About、更新日志、更新包、注释标签和远端 `master`。
- 现有 Android 脏改动和 Android 计划文档不暂存、不覆盖、不提交。
