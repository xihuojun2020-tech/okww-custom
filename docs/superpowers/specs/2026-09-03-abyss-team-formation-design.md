# 自动深渊预设编队与自动点击设计

## 目标

自动深渊完成角色、体力和等级识别后，从当前账号可用角色中选择一支三人队。程序必须优先保留完整预设队伍；没有完整队伍时保留命中最多的预设核心，用其他可用角色填补缺口。最终由程序在快速编队页面实际点击三名角色，验证头像右上角依次出现 `1`、`2`、`3`，点击“完成”并停在编辑队伍页面，不点击“开启挑战”。

本阶段只组成一支队伍。不进入战斗，不安排后续楼层，不扣减或预测角色体力，不实现多队全局调度。

## 已确认规则

1. 完整三人预设高于任何需要替补的队伍，包括第二队列完整队高于第一队列两人队。
2. 多支完整队同时存在时，第一队列高于第二队列；同一队列内的预设没有人工先后顺序。
3. 没有完整队时，优先保留两名已拥有的预设成员，再用一名角色补齐。
4. 替补不得拆散仍然完整的预设队伍；存在其他选择时，也不拆散另一支两人核心。
5. 缺口优先使用与缺失成员定位相同的角色；没有同定位角色时才使用其他未受保护角色。
6. 只有体力大于 `0` 且等级大于 `60` 的已识别角色可以参与编队。
7. 光主和风主必须严格区分。主角头像识别成功但元素形态无法确认时，不能匹配光主或风主预设。
8. 快速编队页可能没有已选角色，也可能已有一至三名角色。程序必须根据右上角 `1/2/3` 标记判断并清理，而不是假设初始为空。
9. 选择结果不足三人、编号验证失败、页面滚动失败或“完成”后未返回编辑队伍页时停止，不点击“开启挑战”。

## 数据模型

新增一个与画面操作分离的纯编队规划模块。该模块只接收可用角色记录和固定预设，返回不可变的规划结果，便于离线测试。

- `TeamPreset`：队列编号、三个规范角色 ID、用户显示名。
- `TeamPlan`：目标预设、最终三个角色 ID、匹配成员、替补映射、是否完整命中、选择理由。
- `CharacterScanRecord` 扩展：保留现有角色 ID、体力、等级、页面和卡片位置，增加可选的主角形态和扫描时选择编号。
- 主角内部身份使用 `rover_spectro`、`rover_aero`、`rover_havoc`、`rover_unknown`。非主角继续使用 `CharFactory` 的规范 ID。

规划模块不读取 GUI、不截图、不点击，也不依赖翻译后的角色名称。

## 主角形态识别

识别到主角头像后，对角色卡左上角元素圆形图标做第二次分类：

1. 从角色卡固定相对区域裁剪元素图标。
2. 使用 HSV 色相和有效彩色像素占比区分衍射黄、气动绿和湮灭紫；无彩色像素或置信度不足时返回 `rover_unknown`。
3. 只有 `rover_spectro` 能匹配光主，只有 `rover_aero` 能匹配风主。
4. `rover_unknown` 可以作为普通替补候选，但不能完成包含光主或风主的预设。
5. 日志必须显示识别到的主角形态和置信度；低置信度保存诊断截图，但不猜测形态。

采用颜色分类而不是新增三套头像模板，因为同一主角的核心区别正是卡片元素图标；实现只需复用现有 OpenCV，不新增依赖。阈值先由现有 2560×1440 截图中的湮灭图标校验，衍射和气动形态必须通过离线样本或用户手动测试确认后才视为完成验证。

## 编队规划算法

### 1. 建立可用集合

只保留 `energy > 0`、`level > 60` 且具有规范身份的记录。同一角色在两屏重复出现时继续使用现有质量合并规则。主角形态加入身份键，防止通用主角误匹配光主或风主。

### 2. 查找完整队伍

枚举两个队列的全部预设。三个成员均在可用集合中即为完整队。

- 只要存在完整队，就不进入替补流程。
- 第一队列完整队优先于第二队列完整队。
- 同队列有多支完整队时，以队伍最低体力、总等级、总识别置信度依次降序决定；最后使用三个规范 ID 的排序键保证结果稳定，不把配置书写顺序当成业务优先级。

### 3. 选择预设核心

没有完整队时，计算每个预设与可用集合的交集：

- 命中两人高于命中一人，命中一人高于零命中。
- 相同命中数时第一队列高于第二队列。
- 同队列同命中数时，仍按最低体力、总等级、总置信度和稳定 ID 键决定。
- 命中的角色保持在其原预设槽位，不因替补重新排序。

### 4. 保护完整队和两人核心

替补候选分为三层：

1. 不属于任何其他完整队或两人核心的角色。
2. 不属于完整队、但属于其他两人核心的角色。
3. 属于其他完整队的角色。

第三层永不作为替补。优先使用第一层；第一层无法补足时才允许使用第二层，并在状态和日志中明确记录“为补齐队伍拆用了另一两人核心”。这满足“替补不能拆散完整队伍，尽量不拆两人队”。

### 5. 选择替补

对每个缺失槽位：

1. 优先选择与缺失预设成员 `CharType` 相同的未受保护角色。
2. 光主在赞妮/菲比队中的目标定位按副输出处理；风主在卡提希娅/夏空队中的目标定位按治疗/辅助位处理。其他角色使用 `CharFactory` 定位。
3. 同定位候选按体力、等级、识别置信度降序选择。
4. 没有同定位候选时，使用任意未受保护角色，仍按体力、等级、置信度排序。
5. 三人无法补满则返回不可执行计划，显示已匹配成员和剩余缺口，不进行画面点击。

当前账号的可用集合会得到：清宵、达妮娅命中第一队列两人核心，千咲缺失；维里奈是可用治疗角色，因此结果为“清宵 / 达妮娅 / 维里奈”，并记录“维里奈替补千咲”。

## 快速编队页面操作

### 选择标记识别

每张角色卡右上角使用固定相对区域识别 `1`、`2`、`3`：先放大局部区域并做高饱和度亮色掩码，再使用现有 OCR 读取单个数字。数字必须落在卡片右上角区域且只能为 `1..3`；其他 OCR 结果忽略。

扫描角色时把选择编号写入记录。单页读取全部可见卡片；多页合并相同角色的选择编号，出现同一编号对应多个角色或同一角色对应多个编号时视为页面状态异常。

### 清理已有选择

1. 如果没有 `1/2/3`，直接进入选择。
2. 如果存在选择，按页面和卡片位置逐个点击带编号的角色以取消。
3. 每次取消后重新截图，确认该卡片编号消失。
4. 全部取消后重新扫描，必须确认三个编号均不存在。
5. 清理失败时截图并停止，不继续叠加选择。

### 选择目标角色

1. 回到角色列表第一屏并通过滚动条位置或第一屏画面签名确认。
2. 按最终队伍槽位顺序选择成员；缺失槽位中的替补继承该槽位编号。
3. 目标在第二屏时滚动到已记录页面，确认画面变化后再点击对应卡片。
4. 点击使用头像主体中心的安全区域，避开元素图标、体力、等级和右上角编号。
5. 点击第一个角色后必须在同一卡片检测到 `1`，第二个检测到 `2`，第三个检测到 `3`。
6. 单次验证失败时重新定位该角色并重试一次；仍失败则清理本轮选择、保存截图并停止。
7. 三个编号全部存在且分别绑定目标角色后，才允许点击“完成”。

### 完成与终点

点击右下角精确 OCR 的“完成”，等待返回编辑队伍页。必须同时识别“编辑队伍”和“开启挑战”以确认页面结构，但绝不点击“开启挑战”。最终状态显示：

- 采用的预设队伍和队列；
- 完整命中或命中人数；
- 每个替补关系；
- 最终 `1/2/3` 三个成员；
- “已完成编队，停在编辑队伍页”。

## 错误处理

- 无可执行三人计划：停止在角色列表，报告可用角色、最佳预设核心和缺口。
- 主角形态不确定：不匹配光主/风主，并记录形态未知。
- 初始选择编号冲突：截图并停止，不盲目点击。
- 清理选择失败：截图并停止。
- 跨页滚动失败：沿用现有多页错误保护。
- 点击后编号未出现或编号错误：重试一次，失败后清理本轮选择并停止。
- “完成”按钮未找到或返回页面验证失败：截图并停止。

所有失败都通过现有 `info_set`、任务状态监控和日志公开阶段、详情与建议，不吞掉异常。

## 验证标准

1. 第二队列完整队必须胜过第一队列两人加替补。
2. 第一和第二队列都完整时必须选择第一队列。
3. 没有完整队时必须优先保留两人核心。
4. 替补不能来自其他完整队；有普通候选时不能拆其他两人核心。
5. 光主和风主不能互相匹配，未知形态不能完成两种主角预设。
6. 初始零选择和初始已有选择都能得到精确的 `1/2/3`。
7. 单页和多页角色列表都能定位目标。
8. 未确认三个编号时不能点击“完成”；任何路径都不能点击“开启挑战”。
9. 现有自动深渊关卡扫描、单页识别、多页识别和角色筛选测试保持通过。
10. 完整仓库测试通过；只做离线验证，游戏内点击测试由用户手动执行。
