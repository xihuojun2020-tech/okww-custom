# Codex 浅色 UI 与五页平铺重构设计

日期：2026-08-26  
范围：个人版 ok-wuthering-waves 全部桌面 UI

## 1. 目标

将程序统一为固定浅色的 Codex 风格，同时保留现有任务逻辑、账号安全、序列联动、配置完整性检查和运行控制行为。左侧导航只承担五个一级任务页；每个一级页内部直接平铺其内容，不再通过多层标签页或任务卡嵌套隐藏设置。

## 2. 视觉规范

- 固定浅色主题：窗口背景 `#F7F8FA`，内容面板 `#FFFFFF`，边框 `#E5E7EB`，主文字 `#1F2328`，次文字 `#656D76`，强调色 `#0969DA`。
- 统一 8px 基础间距、10px 面板圆角、12–16px 内容留白；标题使用 20px/600，区块标题使用 14px/600，说明文字使用 12px。
- 控件采用轻边框、白底、蓝色焦点态；不使用渐变、重阴影、大面积彩色卡片或 Emoji 作为主要视觉层级。
- 运行状态、错误、成功提示分别使用蓝/红/绿的细色条或状态点，保持信息密度但不抢占内容。
- 禁止跟随系统自动切换深色主题；现有语言、窗口尺寸、滚动和快捷键行为不变。

## 3. 页面与导航

`MainWindow` 保留现有 Qt/FluentWindow 容器和任务执行器，只替换主题注入、导航样式和页面壳层。左侧固定五项：

1. 通用设置
2. 账号设置
3. 任务
4. 活动
5. 测试功能

程序设置、关于、重启、开发调试和日志导出移到左侧底部的辅助区或窗口右上角菜单，不进入五项任务页的排序。导航切换不销毁页面实例，保证表单草稿、滚动位置和任务日志保留。

## 4. 五页平铺结构

### 4.1 通用设置

`GeneralSettingsTab` 改为单一滚动页面，依次平铺“监控与启动”“实时触发”“游戏快捷键”“全局行为”四个区块。每个区块使用统一 `SectionPanel`，内部是设置行列表；不再使用四张可折叠大卡片嵌套页面。

### 4.2 账号设置

`AccountSettingsTab` 移除内部 `QTabWidget`，改为纵向平铺：账号配置区、序列配置区、导入导出/备份/完整性维护区。账号配置和序列配置继续复用现有 repository、CAS 修订检查和二次确认；只改变容器和展示，不改变数据事务。

### 4.3 任务

`TaskHubTab` 直接渲染任务列表。每日任务、多账号每日任务及其他任务以统一任务行/任务面板展示；任务配置在任务标题下直接展开，避免 `TaskCard → 子卡片 → 控件` 的重复层级。运行日志固定在页面底部，但过滤窗口尺寸内部诊断消息。

### 4.4 活动

`ActivityHubTab` 移除内部 `QTabWidget`，在同一滚动页面按“限时活动”“常驻活动”两个区块平铺。分类仍由 `navigation_sections.classify_task` 决定，保留悲鸣行动无音危机在常驻活动中的归属。

### 4.5 测试功能

`TestHubTab` 直接展示测试任务行；账号切换测试继续明确标注为多账号每日任务测试入口，避免被误认为生产任务。测试任务使用与任务页相同的平铺任务渲染器。

## 5. 组件边界

- 新增轻量 `CodexTheme`/样式注入层：只负责颜色、字体、间距、滚动条和控件状态。
- 新增 `SectionPanel`：负责区块标题、说明、边框和内容布局。
- 新增 `FlatSettingRow`：负责设置标签、说明、控件和错误状态的横向布局。
- 重构 `OneTimeTaskTab` 的展示层为平铺渲染器；任务实例、配置读写、回调和执行器接口保持不变。
- 账号配置、序列配置页面内部逻辑不搬迁，只替换外层容器并继续调用现有 `AccountRepository`/`SequenceRepository`。

## 6. 兼容与错误处理

- 任何任务配置行创建失败时，显示该行的错误状态并记录日志，不影响其他任务显示。
- 任务页面刷新只更新展示控件，不重建任务实例，不清除用户草稿。
- 账号/序列保存继续使用现有修订冲突、备份、原子发布和失败回滚流程。
- 主题初始化失败时回退到 Qt 默认浅色样式，程序仍可启动。
- 固定浅色只影响视觉，不改变游戏捕获、窗口尺寸和模拟输入。

## 7. 测试门槛

- UI 结构测试：五个一级页存在且顺序固定，账号/活动页不再创建内部 `QTabWidget`。
- 平铺渲染测试：设置行、任务行和区块标题按预期出现，刷新后不丢失当前选择。
- 主题测试：关键控件在浅色主题下颜色、边框和焦点态符合规范。
- 行为回归：账号保存、序列成员调整、任务启动/停止、活动分类、账号切换测试入口保持可用。
- 全仓测试记录既有图像基线错误，不把它们误判为 UI 重构回归。
