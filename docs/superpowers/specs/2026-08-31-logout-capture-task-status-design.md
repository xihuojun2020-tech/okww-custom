# 退登可靠截图与轻量任务状态窗设计规格

## 1. 目标

本次发布同时解决两个相互约束的问题：

1. PC 多账号退登阶段不再依赖全局 WGC 失败后才选择其他后端，而是在退登状态机内优先使用任务级、前台可见的桌面 BitBlt 帧；WGC 保持运行并作为主窗口后备，独立登录窗口继续使用各自 HWND 的客户区 BitBlt。
2. 任务运行期间显示一个轻量、透明、置顶、点击穿透的状态窗，只展示当前账号、阶段、细节、耗时以及最新告警或错误，不提供日志列表、动画、进度图表或交互控制。

## 2. 术语边界

- PostMessage 是普通输入后端，不是截图后端。
- SendInput 继续负责 PC 登录、退登和账号切换鼠标点击。
- WGC 继续绑定游戏主 HWND，不动态绑定独立登录对话框。
- Foreground BitBlt 指从当前桌面可见像素裁取游戏内容区域；它只在已验证目标窗口处于前台时使用。
- HWND BitBlt 指现有 `_capture_hwnd_client(hwnd)`，仅用于 `#32770`、`ComboBox`、`ComboLBox` 等原生窗口或控件。

## 3. 全局约束

- 不调用 `DeviceManager.set_capture()`，不持久化修改 `configs/devices.json`，不关闭或重建全局 WGC。
- 不修改全局 `interaction: PostMessage` 配置。
- 不增加第三方依赖；复用 PySide6、pywin32、ok-script 和现有 ForegroundBitBltCaptureMethod。
- 状态窗不得获取焦点、拦截点击、进入任务截图或改变 SendInput 的命中窗口。
- 找不到可靠截图时只能等待或回退 WGC，禁止在未知状态发送 ESC 或鼠标点击。
- 不启动、聚焦或操控游戏做自动测试；只使用伪 Win32、伪帧、伪任务和 Qt 离屏测试。
- 当前 Android 用户改动不属于本次发布，不暂存、不覆盖、不提交。
- 本次为中等功能发布：版本从 `1.21.00` 升到 `1.22.00`。

## 4. 退登捕获设计

### 4.1 生命周期

`MultiAccountDailyTask._switch_to_login()` 在完整性守卫通过后创建一个任务级 `LogoutCaptureSession`。该对象只持有独立 ForegroundBitBlt 捕获资源，并在 `finally` 中关闭。全局 WGC 对象始终保留。

每轮状态检查按以下顺序执行：

1. 发现同一游戏 PID 下可见的独立登录对话框。
2. 若存在对话框，直接以对话框 HWND BitBlt + OCR 判断是否到达登录界面。
3. 若不存在对话框，强制并验证主 HWND 前台。
4. 用 ForegroundBitBlt 获取一张带来源、HWND、屏幕原点和时间戳的主窗口帧。
5. 拒绝空帧、纯色帧、尺寸异常帧和前台身份变化后的帧。
6. ForegroundBitBlt 无有效帧时刷新一次 WGC，使用 WGC 帧作为本轮后备。
7. 从同一张显式帧依次判断确认框、设置页和主世界。
8. 状态不确定时只等待下一轮。

### 4.2 坐标一致性

每个主窗口识别框必须和产生它的 `CaptureSample.origin` 一起传递。点击函数接收显式 origin，禁止用 ForegroundBitBlt 的 Box 搭配另一次 WGC 的 origin。

独立窗口和控件继续使用各自的 `ClientToScreen(hwnd, (0, 0))` 原点。

### 4.3 状态动作

- main：显示“正在打开设置页”，发送一次 ESC。
- setting：在新截图上 OCR “退出登录/登出/Log Out”，再以同帧原点 SendInput 点击。
- confirm：在当前截图上识别确认按钮，再以同帧原点 SendInput 点击。
- login：结束退登捕获会话，进入现有登录界面稳定等待和账号选择流程。
- unknown：显示“等待界面稳定”，不发送输入。

原有每种可见状态连续最多三次输入、45 秒总截止时间和 TaskDisabledException 传播规则保持不变。

## 5. 轻量状态模型

新增项目内公共状态键，稳定英文键用于程序内部，状态窗固定显示中文标签：

- `Status Account`：当前账号短名，如 A3；不得显示完整方案名、手机号、掩码手机号或登录别名。
- `Status Stage`：当前大阶段。
- `Status Detail`：当前对象或动作。

状态发布写入 `executor.current_task.info`；如果当前没有顶层任务，则写入调用任务自身 `info`。这样普通任务、多账号父任务和通过 `run_task_by_class()` 运行的子任务使用同一数据源。

状态窗同时读取框架已有字段：

- `Error`：最高优先级；同时兼容框架按当前语言写入的等价键（例如中文“错误”），红色显示并保留到下一次任务开始。
- `Warning`：黄色显示；同一告警只突出显示十秒，之后恢复正常状态。
- `Log`：仅在没有结构化 Detail 时作为最后后备，不显示滚动历史。
- `Completed`：多账号任务可选显示“已完成 n 个”，不展示完整账号列表。

## 7. 告警和错误显示

### 7.1 黄色告警

- 前台窗口校验失败，等待重试
- ForegroundBitBlt 无有效帧，已回退 WGC
- WGC 暂无新帧，等待界面稳定
- 退出按钮或确认按钮本轮未识别
- 输入已投递但界面未转换
- 登录对话框闪烁或暂时消失
- 聚落不可到达，已跳过

### 7.2 红色错误

- 无法确认游戏 HWND 或 PID
- 退登状态循环超时
- 连续三次无法打开设置页
- 连续三次无法确认退登
- 登录界面等待超时
- 无法唯一识别当前账号
- 目标账号与验证结果不一致
- 登录按钮连续三次未生效
- 账号配置完整性校验失败
- 子任务异常终止

红色错误窗在任务异常停止后仍保留；下一次任务开始并清空旧 info 时才消失。

## 8. 状态窗设计

固定四行以内：

1. 账号：A3
2. 阶段：刷梦魇巢穴
3. 详情：落渊南丘残象聚落 · 正在战斗；有告警或错误时此行临时改为对应文本
4. 已运行：00:18:42

窗口使用 PySide6 顶层 QWidget：

- `FramelessWindowHint`
- `WindowStaysOnTopHint`
- `Tool`
- `WindowTransparentForInput`
- `WindowDoesNotAcceptFocus`
- `WA_TranslucentBackground`

背景为半透明黑色，正常文字白色，告警黄色，错误红色。无按钮、无拖拽、无日志列表。

## 9. 截图安全定位

窗口尺寸固定，自动定位顺序：

1. 非游戏显示器右上角。
2. 游戏窗口右侧空白区域。
3. 游戏窗口左侧空白区域。
4. 游戏窗口上方或下方空白区域。
5. 若无外部空间且 `WDA_EXCLUDEFROMCAPTURE` 成功，放在游戏显示器右上角。
6. 若既无安全空间又无法排除截图，隐藏状态窗并在主程序任务卡保留相同状态。

窗口先创建原生 HWND、调用 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` 并完成安全定位，之后才允许首次显示；禁止先在默认位置闪现一帧。它是第二道保护，不能替代安全定位。游戏窗口或显示器几何变化时重新计算位置。

## 10. 退出与异常

- 主程序退出时停止状态窗计时器并关闭窗口。
- 捕获会话的 `close()` 可重复调用。
- Qt 状态窗失败不得中断任务；记录 GUI 警告并继续自动化。
- 状态发布失败不得改变任务控制流。
- 捕获失败不得由状态窗异常掩盖。

## 11. 验证边界

自动测试只覆盖：

- 状态发布到顶层任务。
- 状态快照的错误、告警和正常优先级。
- 窗口安全位置选择。
- 无安全位置且无法排除截图时隐藏。
- ForegroundBitBlt 有效帧、纯色帧和 WGC 后备。
- 退登状态识别使用显式帧和显式 origin。
- 独立登录窗口优先于主窗口。
- 捕获资源在成功、失败和停止任务时均释放。
- 梦魇聚落名称和每日任务阶段发布。

禁止自动测试：

- 启动鸣潮。
- 强制真实游戏窗口前台。
- 调用真实 SendInput。
- 执行真实退登、账号切换或每日任务。
