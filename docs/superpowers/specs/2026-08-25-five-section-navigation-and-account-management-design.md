# 五栏导航与账号管理设计

日期：2026-08-25  
状态：待用户书面审阅  
范围：PC 端 OK-WW 主界面、账号/序列管理、任务与活动分类

## 目标

将左侧导航收敛为五个单层主入口：通用设置、账号设置、任务、活动、测试功能。每个入口打开一个整合页面，相关功能只在页面内部使用分区或顶部页签组织，不再占用左侧导航。同步补齐账号删除，修复序列确认删除后无反馈，并把账号配置改造成中文结构化编辑体验。

## 非目标

- 不改变游戏自动化算法、账号识别规则或多账号切换状态机。
- 不恢复计划任务入口。
- 不引入 Android、MuMu、ADB、设备绑定或模拟器功能。
- 不开放 UUID、登录身份、密码、令牌等敏感/识别字段编辑。
- 不为稍后才会加入的限时活动预建空任务实现。

## 方案选择

采用“复用现有任务卡片和配置组件，重组导航容器”的方案。主窗口负责建立五个稳定入口，各整合页复用现有 `StartTab`、触发任务卡、一次性任务卡、全局配置卡及账号服务。相比重新实现所有任务和设置控件，该方案能保留现有配置、信号和执行逻辑，并缩小回归范围。

不采用以下方案：

- 仅重命名现有导航：无法满足左侧只保留五个入口。
- 重写完整 UI 框架：会重复任务卡、配置卡、日志和运行控制，风险与维护成本过高。

## 单层导航结构

左侧滚动区严格只创建以下五个入口：

1. **通用设置**：监控与启动、实时触发、游戏快捷键、全局行为。
2. **账号设置**：账号配置、序列配置、导入导出/备份/完整性。
3. **任务**：全部常规一次性任务。
4. **活动**：限时活动和常驻活动。
5. **测试功能**：全部测试任务。

底部区保留程序设置、重启程序和关于。原“设置”改名“程序设置”，只保存语言、主题、更新、窗口及程序本身相关配置。计划任务不实例化导航页。游戏快捷键不再独立成导航项，进入通用设置。账号完整性检查不再独立占用底部入口，进入账号设置的数据维护区。

## 通用设置页面

页面分为四个连续区域，而非左侧子菜单：

- **监控与启动**：窗口选择、捕获方式、交互方式、开始/停止、状态与日志入口。
- **实时触发**：自动战斗、自动拾取、自动登录、跳过对话、快速传送、鼠标复位等现有触发任务。
- **游戏快捷键**：共鸣技能、声骸、终结技、工具、跳跃、闪避、轮盘、指南和背包等现有全局快捷键。
- **全局行为**：通知、数据仓库、配置备份和跨账号行为选项。

现有配置对象继续作为数据源；页面只改变展示归属，不复制配置值或新建第二份状态。

## 账号设置页面

页面内部使用顶部页签或等价分段控件：

### 账号配置

左侧/顶部选择账号，主体使用中文结构化表单。字段元数据优先复用任务现有 `config_description`、`config_type` 和选项翻译；补充以下说明：

- 中文名称；
- 当前值；
- 对任务行为的影响；
- 是否影响账号识别；
- 建议值或取值范围。

UUID、登录身份、备用身份和其他识别字段只读且默认不显示原文。普通任务字段按布尔开关、下拉、多选、数值或文本控件展示。高级 JSON 仅作为折叠的兼容查看/编辑入口，保存仍经过同一草稿验证、脱敏差异、账号短名确认、备份和修订检查。

账号页增加“删除账号”。删除必须经过两次确认：第一次确认目标账号，第二次列出所有引用该账号的序列和将被删除的账号运行状态。用户确认后执行一个原子事务：

1. 创建账号级备份和事务前快照；
2. 从所有序列移除该 UUID；
3. 删除账号主配置及账号专属运行状态；
4. 重建 `daily_profiles.json` 兼容投影；
5. 更新接受指纹并执行完整性后验检查。

任一步失败则恢复事务前字节。至少保留一个账号；删除最后一个账号必须阻止。页面不提供无备份强制删除。

### 序列配置

保留新建、复制、重命名、启停、删除、添加/移除成员和上下移动。删除流程统一为：确认 → 服务删除 → 成功提示 → 重新载入列表。任何异常必须显示具体、脱敏的错误并保留原列表选择，禁止吞异常或仅写后台日志。

当前“点击 Yes 后无反应”按完整调用链定位：Qt 确认结果、序列服务、修订比较、master 事务发布、完整性后验检查和刷新。修复落在共享服务或错误边界，不只在按钮回调增加表面处理。

### 数据维护

迁入账号配置导入、导出、备份验证、备份恢复、旧序列修复和账号完整性检查。它们继续调用现有服务，不复制实现。

## 任务、活动与测试页面

### 任务

同一页面展示未归类为活动或测试的常规任务，包括每日任务、多账号每日任务、自动周常乐园、刷残像聚落以及现有体力/材料任务。继续复用现有一次性任务卡、配置和运行日志。

### 活动

同一页面内分为“限时活动”和“常驻活动”两个大类。`EventTask`（悲鸣行动：无音危机）从“限时活动”迁移到“常驻活动”。新的限时活动稍后通过任务分组元数据加入，本次不创建占位任务。

### 测试功能

同一页面展示测试任务。现有账号切换测试改用明确名称与说明，表明它是“多账号每日任务——账号切换链路测试”。再次验证它继续复用生产账号选择、身份匹配、登录核对、重试、退登、登录和不可变快照入口，不维护独立切换实现。

## 错误处理与安全

- 所有写操作在页面显示进行中、成功或失败状态。
- 异常信息不得包含完整手机号、备用登录身份、密码或令牌。
- 删除和保存使用修订/指纹比较，预览后文件变化时要求重新加载。
- 账号级联删除与序列删除都使用现有原子 master 发布和后验完整性检查。
- GUI 刷新失败不得掩盖已完成写入；应重新读取权威数据并明确提示最终状态。
- 当前运行快照不受账号/序列页面修改影响，修改只在下一轮生效。

## 测试与验收

- 主窗口导航测试：滚动区只产生五个入口，底部显示程序设置/重启/关于，不创建计划任务、独立触发、独立快捷键或独立账号完整性入口。
- 通用设置测试：现有监控、触发任务、快捷键和全局配置在同一页面可访问，使用原配置对象。
- 账号表单测试：字段中文说明、控件类型、只读身份、草稿隔离、脱敏差异和保存兼容。
- 账号删除测试：二次确认、跨序列移除、运行状态删除、最后账号保护、备份先行、修订冲突和事务回滚。
- 序列删除测试：成功删除并刷新；用户取消无写入；修订冲突和完整性失败在页面显示。
- 分类测试：常规任务、限时/常驻活动和测试任务只出现在正确整合页面；悲鸣行动属于常驻活动。
- 切号测试：`TestAccountSwitchTask` 继续调用生产快照及切换入口。
- 回归：账号/配置/序列聚焦测试、GUI 启动测试、Python 编译和仓库可运行测试集。
