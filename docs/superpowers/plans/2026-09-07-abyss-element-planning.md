# 逆境深塔属性与全局体力规划

2026-09-08：按用户最终确认方案实施，版本 1.38.00。实机测试由用户手动完成，代理只检查日志。

## 已确认规则

先识别仓库，生成完整预设及同定位替补候选，再按整队输出属性和共享体力安排各层。候选可共用角色，实际出场扣除同一份体力，不提前永久拆分仓库。

角色定位和现有属性优先采用 CharFactory，弗洛洛与秧秧SP均为主C；琳奈为衍射。穗穗补充冷凝元数据，漂泊者按已识别形态确定属性。角色头像别名合并，不重复计算体力。未知角色或未知漂泊者形态不能当作中性主C。

| 配置组 | 顺属性 | 逆属性 |
| --- | --- | --- |
| 左塔/残响 | 一个 | 一个，允许兜底 |
| 右塔/回音 | 一个 | 一个，允许兜底 |
| 中塔1—2层 | 两个，同级 | 一级禁止主C和副C；二级尽量避开主C |
| 中塔3—4层 | 两个，同级，独立设置 | 同上，独立设置 |

十二个下拉选项：无、冷凝、热熔、导电、气动、衍射、湮灭。使用框架 Config 持久化；清空识别结果、切换账号、重启和赛季变化都不重置，运行开始冻结设置。

中塔一级逆属性为硬约束，任何顺属性评分不能抵消。二级只惩罚主C。左右塔依次优先无逆属性输出、逆属性副C、逆属性主C。双主C分别检查，治疗角色不获得顺属性评分，定位完全依照OK-WW。

## 实现

abyss_allocation.py 提供配置快照、属性评价、候选生成和全局规划纯函数。候选保持预设的定位结构，对已拥有角色也允许同定位替换，以避开禁用输出；没有原预设角色时仍可按该定位结构生成队伍，至少一名主C。

规划按用户选择的整塔顺序推进，按层消耗每个角色体力：左右塔1/2/3/4，中塔每层5。跳过一层后不得安排该塔后续层。排序依次为优先区域覆盖、总覆盖、逆属性主C次数、逆属性副C次数、顺属性主C次数、替补数量、队列与换队成本。

中塔优先时，同时规划两个半区并在首次战斗前检查中塔覆盖；无法安排时给出识别/队伍、属性或共享体力/搜索限制原因，停止整个任务。两侧优先保持原塔顺序，预览说明中塔覆盖损失；到中塔无法分配时停止。

复用原有选人、选择标记核验和战斗流程。记录各层预定队伍，下一层队伍不同或体力不足时返回并重新识别、规划未完成关卡。第2→3层只有在后半区规则下仍被选中的同一队才直接继续；从第3层恢复直接使用后半区规则。新扫描替换旧仓库，不用历史缓存虚构体力。

## 有界搜索与限制

使用标准库，无新增依赖。每层保留256条搜索状态；大候选集先保留覆盖每名角色的选项，再补入较优候选。扩展状态分批裁剪，限制内存并定期调用任务取消检查。任意裁剪都会在预览中标记，不把有限搜索未找到方案宣称为数学无解。

规划仅针对当前扫描识别到的仓库；现有识别器仍使用单页或两页扫描，未识别角色不参与规划。无法保证有界搜索全局最优，也不以属性匹配推断实战必定通关。
