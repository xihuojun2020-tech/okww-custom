# 体力刷取合并与提醒简化方案

**状态：** 已按批准方案实现，版本 1.97.17；回归、界面缩放和更新包验证通过。材料计算按用户最新修正：输入四品质的已有库存与目标所需数量，程序折算后计算缺口与预计领取次数，用户无需手算剩余需求。实际游戏战斗尚未验证，详见本版验收记录。

**目标：** 精简账号导航与总览，凝素／无音区统一配置为体力刷取，修正周本控件一致性，停用声骸合成，深塔归入人工提醒。

**架构：** 保留 PySide6、QFluentWidgets、现有仓库、账号身份、配置草稿和任务账本。合并展示与配置入口，复用现有凝素、无音区和体力保护执行方法。人工提醒状态与实际深塔关卡记录分别存储。

## 1. 已检查的现状

- `AccountConfigTab` 导航将凝素与无音区拆成两页，两个页面均包含 `Which to Farm`，存在重复配置入口。
- `DailyTask` 已在有凝素材料目标时调用 `farm_quota`，全部达标后调用本账号 `farm_tacet`；没有目标时使用原有不限凝素方法。
- `account_task_state` 会分别生成凝素和后续无音区卡片。凝素达标可显示完成，但这时当天体力流程未必完成。
- `WeeklyBossPlanWidget` 使用原生 `QComboBox`，与其他页面的 `ChoiceControls.QtComboBox` 不一致；六列布局混合目标、次数、进度、校正，窄窗口易拥挤。
- 活跃度与奖励存在导航和总览卡片；失败收尾还会单独产生每日流程卡片。
- 声骸合成存在账号开关、周日自动调用、独立任务注册、总览记录和旧配置迁移。仅隐藏 UI 无法保证停用。
- 提醒编辑器目前显示周期下拉框和自定义日期；深塔使用自动关卡状态，不允许人工完成标记。这与本次要求不同。

## 3. 体力刷取

### 3.1 页面结构

```text
体力刷取
  刷取类型       [凝素领域 / 无音区 / 模拟训练 / 不刷取]

凝素设置（选凝素时显示）
  领取上限       [不限 / 按材料需求]
  不限：领域选择 [原账号所选领域]
  按材料需求：目标一、目标二
    领域         [选择领域]
    已有材料     金 / 紫 / 蓝 / 绿
    目标所需     金 / 紫 / 蓝 / 绿
    自动计算     已有当量 / 所需当量 / 缺口 / 预计领取次数
    进度         本次计算后已确认新增当量 / 尚需刷取当量
    操作         按当前库存重新计算；待核验时显示核对入口

无音区设置（选无音区，或凝素有限额时显示）
  目标           [本账号所选无音区]
```

- 模拟训练是现有第三种类型，保留原选择与材料设置；仅选中时展示，不新增额度系统。
- 使用一个互斥的主要刷取类型，避免两个独立开关同时启用造成执行优先级不明确。
- 无音区没有上限字段，持续使用当前可领取体力；不会跨账号串用目标。
- 不限凝素持续刷所选领域，体力不够领取时结束本次运行；不进入第二目标或无音区。
- 有限凝素先完成目标一，再完成目标二；两组均达标后转本账号所选无音区。
- 未启用的目标跳过。有限模式目标必须完整有效，禁止因空值错误把它解释成不限。
- 切换不限／有限时保留未使用的材料参数及 goal_id，避免重新开启有限模式把历史累计清零；不限刷取后重新启用限额时提示核对库存，用户可明确录入当前库存并重新计算。

### 3.2 计算与体力规则

- 已有绿色当量 = 已有金×27 + 已有紫×9 + 已有蓝×3 + 已有绿。
- 所需绿色当量 = 所需金×27 + 所需紫×9 + 所需蓝×3 + 所需绿。
- 初始缺口 = max(0, 所需绿色当量 - 已有绿色当量)。统一比较总当量，不要求用户分别计算各品质缺口。
- 运行剩余缺口 = max(0, 初始缺口 - 本次库存快照之后核验过的新增当量)。
- 80 体力估算 50 当量，40 体力估算 25 当量。
- 不考虑当前体力限制时，预计 80 领取次数 = 缺口整除 50，预计 40 领取次数 = 剩余当量除以 25 向上取整；预计体力 = 80×前者 + 40×后者。剩余不足 25 也需要领取一次。
- 余量至少 50 且当前可用体力足够时优先 80；余量不足 50，或仅够 40 时领取 40。
- 库存与需求均由用户输入，程序负责相减；不恢复从游戏养成页面或背包自动读取的旧功能。
- 目标累计跨日保存，只累计核验过的领奖消费；待核验记录继续阻止重复消费。
- 体力耗尽结束本次运行，长期选择保留到用户改变指令。下一次仍手动启动。
- 保留开头一次活跃度读取和现有体力保护。每日达标优先于材料刷取；没有选择的模块不为补活跃度临时调用。

示例：已有金1、紫2、蓝3、绿4，折合58；所需金5、紫3、蓝5、绿6，折合183。缺口125，预计80体力领取2次、40体力领取1次，共3次领奖、200体力。

### 3.3 库存快照与累计

- 手填库存是一次计算基准。执行后单独显示“本次已确认新增”，不把估算新增写回为真实背包库存。
- 仅改变目标所需数量时保留库存快照与本轮累计，重新计算剩余缺口；仅导航、展开或刷新不生成新轮次。
- 重新输入当前库存会包含之前刷出的材料，因此需要明确点击“按当前库存重新计算”并保存，建立新的 goal_id 和快照；旧流水保留，但不从新库存再次扣减旧流水。
- 更换领域也建立新的轮次；若有未核验消费，先解决记录再重建基准。
- 已有当量达到目标时，该材料目标直接达标，不消费体力；继续第二目标或无音区。
- 两组目标若选择相同领域，不把同一份库存计算两遍。保存时要求合并同领域需求为一组；旧配置中相同领域的目标仍保持旧剩余模式，重新录入库存时再规范。
- 材料掉落仍按已确认的50／25当量估算，不虚构逐品质实际掉落；用户可根据背包实际数量重新校准。

### 3.4 总览

只展示一行“体力刷取”，例如：

- 凝素不限：所选领域 · 不限。
- 凝素有限：目标一 75/125 当量 · 达标后转无音区。
- 正在转移：凝素目标已完成 · 当前刷取无音区。
- 无音区：所选目标 · 持续刷取。

详情可显示两组材料累计、实际开始／结束时间及核验原因。现有 forgery/tacet 事件和账本继续保留，界面将它们投影到同一个父项；不清空旧数据，也不简单修改 task_id 导致历史记录失联。

材料目标达标不等于每日父项完成。父项完成需要确认当天所需体力流程已正常结束；待核验或异常优先显示需要处理，体力不足沿用现有等待语义。

## 4. 静默执行的步骤

### 活跃度与奖励

- 隐藏设置入口与常驻卡片，不关闭实际任务。
- 开头读一次，可以领取小任务积分；全部所需耗体力任务结束后领取宝箱并实际复核。
- 实测不足 100 或领奖失败，报告每日流程异常并保留日志证据；正常流程不占总览行。
- 不因聚落未选或程序未打某个模块而推断活跃度不足。

### 收尾行为

- 隐藏账号分类、表单和常驻收尾任务行。
- 保留旧退登配置及多账号任务的退登接管，截图／录像保留现有入口。
- 失败通过当前任务状态、页面错误提示和日志呈现，不恢复常驻收尾卡片。
- 总览统计以可见任务为基准，避免隐藏项仍影响展示的任务数量。

## 5. 战歌重奏界面

采用现有 SectionPanel 与统一 Fluent 下拉控件，不新增配色或字体。

每个目标使用相同的两层结构：

```text
优先级一     [周本目标]
领取上限     [不限 / 数量] 次       已领取 2 / 6
```

- 三行的目标控件、次数字段、状态位置对齐，行距 8px，分区内距 16px。
- 次数与单位作为一个控件组合，避免单独“次”字挤压进度。
- 周一检查、周日复检、最近结果放进紧凑状态摘要；累计校正放入展开详情。
- 未确认领取的核对入口在确实需要处理时显示。
- 窄窗口按目标、次数、进度上下排列，长周本名称正常显示或提供完整值入口。
- 保留周一执行、周日复检、游戏每周三次限制及既有跨周目标计数。
- 保留当前全部材料目标达标后采用游戏列表首项的既有规则；本次只修改该模块展示。

## 6. 声骸合成彻底停用

- 从账号导航、字段和总览移除；独立声骸合成入口隐藏并停止注册为可执行任务。
- 所有已存账号与单账号全局设置的相关开关改为 false；默认值 false。
- 旧的 `Merge Echo If discarded > 1000` 迁移不再产生启用值。
- 旧配置导入、恢复与后续兼容迁移同样规范为 false，防止旧备份重新启用。
- 每日周日流程不再调用合成；保留防御性执行阻断，避免遗留配置意外调用。
- 旧完成记录保留，不进入总览；其余任务选择、账号身份与自动战斗偏好保持不变。
- 对账号主配置的修改走仓库可信写入与备份，避免绕过完整性服务直接替换 JSON。

## 7. 深塔、海墟与活动提醒

### 7.1 编辑页面

每项只保留是否纳入提醒和状态选择：

```text
[勾选] 深塔       [未完成 ▾]
[勾选] 海墟       [完成 ▾]
[勾选] 活动       [前置未完成 ▾]
```

下拉框只有“完成、未完成、前置未完成”。状态均由用户选择；前置未完成不关联执行依赖、不启动任务、不弹出阻塞性错误。

- 周期与日期编辑控件全部移出此页面。
- 旧提醒勾选、备注、时间规则和历史记录保留。
- 用户告知日期／倒计时后，按北京时间转换并更新对应任务的 reset_at；不修改系统时间。
- 到达指定边界时，“完成”与“前置未完成”均恢复未完成；没有配置有效边界的项目保持手动状态。
- 未明确改变前的旧每日／每周／自定义规则保留，到期同样恢复未完成；隐藏控件不能改变原保存值。
- 不会把此前的六天十一小时硬编码成当前周期。

### 7.2 深塔实际执行与提醒分离

- 深塔在总览中归入手动提醒，其状态来源是手动标记；实际通关不会自动覆盖该状态。
- 仍保留独立任务页的启动入口，不加入每日执行队列。
- 原有按账号特征码绑定的赛期、关卡完成和失败队伍账本不变。
- 手动改提醒、重置提醒或标记未完成，不会删除通关记录，不会使已完成关卡重打。
- 游戏识别到的赛期及倒计时用于实际执行账本；人工指定提醒边界用于提醒，二者分别存储。人工提醒时间不用于覆盖游戏通关证据。
- 原深塔塔选择和优先顺序参数保留，隐藏状态页不覆盖这些设置。
- 状态变更记录手动操作时间和来源；人工标记不伪装成游戏核验。

## 8. 旧配置迁移

| 原配置 | 升级结果 |
| --- | --- |
| 原凝素，无材料目标 | 凝素不限，原领域不变 |
| 原凝素，有材料目标 | 保留旧“剩余需求”口径和原 goal_id／累计；首次输入已有库存与目标所需并保存后切换新口径，不把旧剩余值伪装成库存或最终目标 |
| 原无音区 | 无音区，原目标不变 |
| 原模拟训练 | 原训练类型与材料选择不变 |
| 原不刷体力 | 继续不刷取 |
| 原声骸合成开启 | 显式改为关闭 |
| 原人工完成记录 | 对应周期内迁移为完成；其余为未完成 |
| 原深塔自动状态 | 按升级时可确认的完整周期完成证据初始化一次，无法确认则未完成；后续使用手动状态 |
| 原收尾、截图与录像 | 值保留，按上述规则隐藏或继续原入口 |

迁移按字段幂等执行，深塔手动状态仅在缺失时初始化；重复启动不覆盖新选择。声骸合成按停用要求持续规范为 false。备份后执行，仅规范明确授权的字段。旧任务事件、材料消费流水、特征码、profile_id 和 A/B 槽位不重建。

## 10. 验收标准

- 旧账号迁移四种主模式与原有关卡不变；切换页面或账号不丢草稿。
- 金／紫／蓝／绿两组输入由程序统一折算、相减、夹到零并计算80／40领取次数；125缺口计算3次、200体力，26缺口计算2次40体力。
- 修改目标不清零本轮累计；重新录入真实库存并重新计算后，旧流水不被再次从新缺口扣减。
- 旧剩余配置保留其语义和进度，重复升级不重新初始化；相同领域不能重复分配同一库存。
- 不限模式无材料目标也正常刷凝素；有限模式两目标顺序与跨日累计正确。
- 余量不足 50 用 40；当前只有 40 时不尝试 80；领奖不确定时停止重复消费。
- 凝素完成后无音区仍运行时，体力父项不显示完成；只显示一个体力卡片。
- 活跃度正常时无卡片，实测不足 100 时明确报错；宝箱仍在体力流程后领取。
- 旧声骸配置、旧导入及周日流程均无法开启或执行合成。
- 提醒三状态手动保存、切换账号隔离，到期归为未完成；没有边界不自行重置。
- 深塔人工标记不修改关卡账本，不影响失败队伍跳过或单独启动。
- 图三周本原生控件替换后，100%、125%、150% 缩放和三种窗口尺寸检查对齐、换行及可操作性。
- 核验账号图和关键配置差异：允许合成变 false 及已声明迁移字段变化，其他选择、材料账本、身份与自动战斗偏好保持一致。
