# 使用端资源优化实施计划

**Goal:** 降低程序对游戏的 CPU、磁盘和后台调度干扰，并留下可对照的性能数据。

**Architecture:** 沿用现有单线程诊断工作器和独立上传进程；减少周期性工作，不改变材料收益永久保存、独立帧特征码核验及完成证据提交语义。用户已批准本方案并确认关闭程序后设备更流畅，直接执行。

**Tech Stack:** Python、本地 .venv、psutil、OpenCV、现有 Qt 界面。

## 约束
- 不删除历史材料统计或证据，不修改其他工作区变动。
- NAS 仅使用 `\\192.168.3.173\羲火君 共享给我\AI诊断`。
- 使用端游戏验收由用户完成，离线测量不能冒充实机改善比例。

## 执行清单
- [x] `diagnostic_session.py`：30 秒性能采样、批量日志封存，状态限频；性能记录包括 CPU、RSS、读写增量、队列和采样耗时。
- [x] `diagnostic_collector.py`：先比较 stat，再读内容；降低遍历频率，保留重写/截断处理。
- [x] `diagnostic_uploader.py`、`diagnostic_lifecycle.py`：先过滤已上传状态再读清单，限制单轮数量与时间，降低唤醒频率与后台优先级。
- [x] `diagnostic_evidence.py`：诊断预览缩至 1080p、默认参数无损 PNG；合并短时间事件更新，首次/结束强制保存，保持所有采样帧。
- [x] `TaskExecutor.py`：诊断复用任务帧，失败退避；评估同帧 OCR 复用与耗时采样，验证点击后新帧及独立核验不受影响。
- [x] 存储：复用现有数据仓库设置，提供诊断目录迁移机制，旧数据保留，后台任务跟随新目录；目标盘由用户选择。
- [x] 界面：核对按需刷新、缩略图和复制原图现有行为，仅修复实际重复工作。
- [x] 测试：静态文件扫描不读内容、日志最终封存、错误窗口恢复与完整性、已上传跳过、性能采样失败隔离、目录设置重启生效及已有账号/材料/证据回归。
- [x] 更新版本与实施报告，GitHub 提交及标记，构建验证后发布 NAS。

## 验证方式
运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p TestDiagnostic*.py` 及新增性能测试；补充受影响模块测试。用计数型测试比较扫描读取/事件发布次数，报告测试条件，不推算用户设备帧率。

见 docs/reviews/2026-09-13-runtime-performance-1.62.00.md。显式低压缩参数经测量更慢，保留默认编码；已有缩略图和区域识别继续复用，不新增危险的全局降频。迁移能力已验证，真实目标盘由使用端选择。发布检查以该报告和实际工具结果为准。
