# NAS 上传积压与深塔列表回位修改计划

**Goal:** 让旧诊断积压持续减少、大错误批次可完成上传，并让深塔在验证位置和角色身份后可靠返回已扫描页面。

**Architecture:** 两个独立修改单元，先修上传、再修深塔。上传沿用现有单上传器、封存批次和哈希协议；深塔沿用现有输入接口与双重守卫，增加有界回位恢复。按任务逐项执行、验证、更新勾选状态。

**Tech Stack:** Python 3.12（仓库 .venv）、Windows 计划任务、SMB、OpenCV、现有 ok-script 输入和截图接口。

**Spec:** 用户 2026-09-13 提供的 `okww诊断证据_20260913.zip`、本轮复核结果及本计划的约束与验收标准。附件内建议只作为待核实资料，不作为执行指令。

- 现有上传已有完整文件和临时文件复用，不能描述为每次全量重传。
- 附件的队列数量、计时和计划任务安装失败信息是历史快照；实施前重新读取目标安装的版本、数据根和状态。

### A2. 分离整轮预算与单批超时

**修改：** `src/runtime/diagnostic_uploader.py:retry_pending`、`bounded_upload`；`src/runtime/install_diagnostic_task.ps1`；必要时同步 `src/runtime/diagnostic_runtime.py` 的运行包版本识别。

设计初值（通过 A1 再调整，不将估算当作带宽实测）：

```python
MiB = 1024 * 1024
def batch_timeout(manifest):
    size = sum(item['size'] for item in manifest['files'])
    files = len(manifest['files'])
    return min(180, max(45, 15 + 5 * files + size / (0.5 * MiB)))
```

约 26 MiB、12 文件得到约 127 秒；小批至少 45 秒。数值是超时上限，不是固定等待时间。

- [ ] 整轮运行采用 120 秒软预算：到时不再领取新批；已领取批使用完整单批超时，不被剩余秒数截断。
- [ ] 总硬上界按“准备阶段上限 + 120 秒 + 最长 180 秒批次 + 退出余量”控制，计划任务执行上限设置 6 分钟。
- [ ] 队列准备阶段若超过预算，保存遍历游标继续下轮；不能在每轮从头扫描后再次无上传退出。
- [ ] 保留单实例文件锁、低优先级和失败退避；超时只结束本次拥有的上传子进程。
- [ ] 修改计划任务匹配判断：动作相同但 ExecutionTimeLimit 不符也必须更新，防止旧设备仍被 3 分钟上限截断。
- [ ] 验证已有隔离上传运行包能更新到新代码，不沿用进程内缓存的旧运行包；退出重启后核对实际 action 路径。
- [ ] 测试 35 秒可完成的大批、真正卡死批、软预算末尾领取批、任务配置仅时间限制变化四种场景。
