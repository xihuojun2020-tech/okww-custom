# 本场队伍身份保留与阵亡后续战实施计划

**目标：**在明确的新一场战斗开始时确认角色身份；同场暂停、开关切换与异常恢复保留身份，部分角色阵亡后由存活角色继续战斗。

**依据：**用户本轮认可的讨论及2026-10-08本机1.97.55深塔20:03:14—20:04:07日志与原始截图。坎特蕾拉阵亡后头像匹配约0.729，动作恢复和动作前复核强制扫描全部头像，造成身份未确认及2/4/8/16秒等待。

**结构：**复用BaseCombatTask、CombatCheck的战斗生命周期，以及已有角色对象、队伍上下文和切人拒绝处理。新增状态只用于表达本场身份已确认及本场阵亡槽位，保留原始槽位编号；不新增配置项或独立服务。

**技术：**现有Python、OpenCV、ok-script。执行按下面任务逐项进行，不要求并行代理。

## 共同约束

- 重新识别的正常触发点为上一场已经结束后的下一场开始，不是用户暂停、关闭辅助后重开或恢复等待。
- 账号/预设队伍真正改变使旧身份失效，复用现有上下文失效信号；下一场使用新队伍，不沿用前账号。
- 单次截图缺失、瞬时HUD/目标消失及身份低分不得单独被视为战斗结束。
- 低头像分数不单独判阵亡；不全局降低CharFactory匹配门槛。
- 没有确认过本场身份时保留现有首次识别要求；不得用未知角色脚本假装续战。
- 自动战斗开启偏好保持原规则；显式暂停、停止和退出仍立即停止输入。前台任务与后台辅助仍只允许一个输入所有者。
- 本次不调整角色技能顺序、深塔编队评分、单人专用动作、新角色支持或其他任务UI。

## 任务1：明确本场身份有效期

文件：src/combat/CombatCheck.py、src/task/BaseCombatTask.py；按实际调用链需要同步src/task/AutoCombatTask.py。

- [ ] 核对in_combat、load_chars、reset_to_false、combat_end、combat_once、_run_combat所有调用，将“确认新战斗”“正常结束”“错误中断”“暂停”区分。
- [ ] 新场已确认且尚无本场身份时，完成一次现有完整确认并建立本场身份；不因每个角色动作重读整队。
- [ ] 同场关闭再开启及异常等待后只刷新当前槽位、HUD和存活状态，使用本场角色对象。
- [ ] 仅在已有明确胜利/挑战失败/全队阵亡/战斗结束流程确认后结束本场身份有效期；结果交接沿用原实现。
- [ ] 异常路径中调用combat_end作为动作清理时，不得误将它等同于游戏已结束战斗；将清理和身份失效放在正确调用点，不新增定时失效或持续时间配置。

验证：首次确认一次；同场暂停恢复不增加身份扫描；正常结束后的下一场重新扫描；捕获失败及瞬时失配不建立第二场；真实账号/队伍变更不会复用旧角色。

- [ ] 在选人前刷新阵亡状态；优先复用已有灰头像检测和游戏死亡拒绝提示，缺少直接提示时结合对应血条为空确认实际死亡。

- [ ] 全队阵亡或挑战失败交给现有深塔结果处理，避免无活人时无限按技能。

验证：真实灰头像排除；有切人冷却遮罩但仍活着的角色不误排除；存活槽位编号不改变；可用队友继续输出；复活重新纳入；全队失败交接正常。
