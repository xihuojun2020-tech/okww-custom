# 打包版退出与后台隔离实施计划

用户已批准：后台独立运行、退出流程加固、旧任务迁移和回滚。顺序执行，不操作游戏。

1. 新增 diagnostic_runtime：在 E 盘按安装身份构建不可变后台快照，复制标准 Python、Pillow、Windows 凭据模块及诊断代码；隔离环境变量，自检后才使用。原仓库路径单独保存，保持队列与采集来源身份。
2. lifecycle、policy、计划任务统一指向快照，所有上传/清理子进程继续使用快照解释器。旧版本快照不原地覆盖。
3. 提供单独迁移命令：先准备并验证后台，再备份旧任务、暂停旧任务、核验并停止对应上传进程、切换任务；失败恢复任务定义。不删除队列、凭据、账号或原有配置。
4. 主窗口退出不再同步强杀启动器；异常不阻止 Qt 退出。退出诊断阶段有明确日志；现有已验证祖先进程清理保留身份检查。
5. 离线测试涵盖隔离进程依赖、安装身份、计划任务预览、退出异常与托盘行为、迁移失败回滚。E 盘实际构建独立后台并执行不联网的自检。
6. 更新版本和日志，通过测试后提交、标注和推送。用户手动执行现有安装的退出/更新验收。

## 旧安装修复入口

从新版源码目录使用该目录的 Python 运行（无需先更新旧安装）。默认只准备和自检，增加 `--apply` 才迁移计划任务：

```powershell
.\.venv\Scripts\python.exe scripts/repair_diagnostic_runtime.py --source 'E:\game\okww owener\data\apps\okww-custom\working' --apply
```

后台目录默认是安装盘根目录下的 `OKWW-Background/<安装ID>/<代码指纹>`。代码、解释器和依赖位于快照内；来源绑定保留原安装身份，日志队列和凭据不迁移。每次构建先临时准备、自检后改名发布，不覆盖旧快照。

任务备份放在快照的 `migration/*.xml`；迁移失败自动恢复备份。手动恢复时使用 Windows `Register-ScheduledTask -TaskName <原任务名> -Xml (Get-Content <备份路径> -Raw) -Force`，恢复原触发器、执行路径和启用状态。修复工具只终止旧安装 Python 目录内、命令行为指定上传模块且指向相同队列的进程。

验证范围：真实独立 Python 导入路径自检、向临时本地目录传送合成诊断批次、计划任务成功/失败回滚模拟，以及退出异常和托盘行为测试。游戏中的最终退出与更新由用户手动验收。
