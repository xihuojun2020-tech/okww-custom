## 模块一：队伍识别误拒（最高优先级）

### 1. 先建立可复现的样本

- [ ] 从已核验的今天证据中提取爱弥斯、琳奈、散华、绯雪、莫宁的头像区域及必要的 HUD 上下文，记录原图哈希、时间、槽位、人工核对身份、分辨率。
- [ ] 调用生产匹配路径，对每张图记录第一候选、不同角色的第二候选、完整分数和差值。多个模板属于同一角色时，先按 canonical_name 合并竞争关系。
- [ ] 添加其他角色、相似头像、空槽、加载页、动画遮挡、不同当前出场槽位的负样本；用今天三次执行的不同时间帧区分校准集和验证集。
- [ ] 先复现旧版拒绝低分正确候选、不同初始化路径结果不一致的问题，再改确认规则。

### 2. 统一确认入口与证据生命周期

- [ ] 所有 `load_chars` 调用先检查账号绑定代次、窗口、画面尺寸、队伍规模；相关上下文变化立即清除旧身份候选和旧轮转状态。
- [ ] `force_full_scan` 只控制完整候选搜索，不再隐含另一套与首次加载不同的成功标准。所有路径调用同一身份确认规则。
- [ ] 高置信路径保留最佳分数 >=0.90 且异角色分差 >=0.08 的快速确认。
- [ ] 对低于快速确认线的候选，引入受样本验证约束的多帧确认：连续三个独立采集帧、同一 canonical_name、同一槽位/上下文、每帧均满足校准后的最低分数和竞争分差；证据窗口两秒。重复读取同一帧不得累计，候选变化或证据超时立即清零。
- [ ] 最低分数和分差先由真实正负样本决定，不能根据 0.846 这一张正样本直接写死全局新阈值。要求独立验证集无身份误认且本次稳定头像能够确认；如正负样本无法分离，修正对应模板/裁剪并重新验证，不继续扩大接受范围。
- [ ] 候选身份处于待确认阶段时不运行其技能脚本；整队所有实际存在槽位确认后再发布可执行队伍。
- [ ] 同一账号、同一角色再次复核成功时保留已建立的技能/轮转状态；真正换号或身份改变时才重建状态。新队伍不得继承上个账号确认记录。
- [ ] 保留现有最多六轮、四秒识别预算。先记录失败原因，再退出相应子任务；不以无限重试补偿识别缺陷。

这里的四秒预算是整个 load_chars 的上限，多帧证据不会额外叠加另一个四秒。若实际匹配开销使三个新帧无法在预算内完成，应先优化重复匹配或修正模板，单独记录测量结果后再评估预算。

### 3. 必须通过的回归

| 场景 | 期望 |
| --- | --- |
| 新建任务与换号复用任务，输入相同画面 | 最终身份结果一致 |
| 稳定低分真实头像 | 经校准规则和三个独立帧后通过 |
| 同一帧读三次 | 不满足多帧确认 |
| 候选 A/B 交替，或异角色分差不足 | 不确认，不执行角色动作 |
| B7→B8→B10；同账号重新绑定 | 旧账号证据不复用 |
| 队伍 3→2→1 人、窗口变化 | 重建正确数量与身份 |
| 角色复核成功且身份不变 | 保留当前轮转状态 |
| 报错时在加载页/动画页 | 等待有效画面，预算耗尽后明确报告，不伪造队伍 |

既有 `test_recheck_rejects_weak_ambiguous_and_unknown_portraits` 应拆为单帧低分待确认、多帧正确候选可确认、模糊/未知始终拒绝三个行为测试，避免旧测试继续要求“所有低分永远失败”。

日志字段：账号绑定代次、槽位、候选/竞争者名称与原始分数、分差、独立帧数、复核原因、拒绝条件；沿用现有脱敏。诊断截图按失败阶段限频保存。

### 有界恢复设计

领奖流程：确认战后画面 → 查找目标/领取交互 → 短段接近 → 检查进展 → 必要时重新定位 → 领取弹窗 → 原有体力结算。

- [ ] 保留 `walk_to_treasure(send_f=True, raise_if_not_found=True)` 对调用方的接口。检查 TacetTask 和 DomainTask 两个调用方的成功、失败和异常预期。
- [ ] 在共用领奖入口内用短段调用现有移动函数，每段最多一秒，段间释放移动键并刷新目标；不跨段沿用过期 last_target/centered。
- [ ] 目标消失时停止盲走并重新取景。连续三段目标位置基本不变且无领奖交互时，判为无进展；像素容差按画面尺寸归一化，用录像核对是否对正常慢移动误报。
- [ ] 仅在战斗已经结束且奖励目标有证据时允许脱困：重新居中相机、重新取目标、短步重新定位。每步最多 0.25 秒，最多六次，总恢复预算最多 45 秒；所有内部等待使用剩余预算，避免嵌套调用超时叠加。
- [ ] 方向依据刷新后的奖励标记确定；目标位于后方可短按 S，受阻时有限侧移。不得无条件套用海墟入口后退动作。
- [ ] 需要识别当前选中的 F 与领取文字在同一行；附近“吸收”或其他交互不能作为领取成功。复用现有 F 列表选择能力，重新取帧确认选中行再发送 F。
- [ ] 出现敌人/战斗状态时退出领奖移动，回到明确的战斗处理路径；不得把暂时看不到敌人当成奖励已生成。
- [ ] 任何成功、超时、用户暂停或异常路径都通过 finally 释放移动按键。用户停止异常立即向上传播。
- [ ] `TacetTask` 继续使用现有领取弹窗与 `use_stamina` 记账。只有弹窗确认、领取结果和体力核对成立才累计消耗；恢复过程本身不加 used_stamina。
- [ ] 恢复耗尽保存最后画面和失败阶段，交由现有账号失败/补跑机制处理；不要无界重开副本。

周本已有 `_seek_reward_interaction` 提供短段移动和释放按键的参考，但其 Boss 任务提示、弹窗与体力逻辑不同，不能直接从无音区调用周本任务对象。仅复用已有底层能力；如提取共用小函数，应同时跑周本领奖回归。

### 测试

- [ ] 图标移动、丢失、重新出现：使用最新坐标，丢失后释放方向键。
