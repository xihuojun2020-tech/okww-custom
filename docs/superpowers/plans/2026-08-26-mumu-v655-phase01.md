# MuMu V6.5.5 阶段01实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在主仓库中实现 MuMu V6.5.5 的只读设备预检、实际鸣潮包名检测、Nemu IPC 截图校验和 Combat Agent 心跳验证，不发送游戏输入。

**Architecture:** 复用废弃代码的 MuMu、ADB、Nemu IPC、Agent 协议和设备主管边界；新增独立的 `PreflightReport`/`DevicePreflight` 只读服务。主仓库的 PC 战斗和账号逻辑保持不变，阶段01的 Android 配置只记录设备域信息和固定三人队元数据。

**Tech Stack:** Python 3.12、现有 `ok`/PyQt/qfluentwidgets、标准库 `subprocess`/`dataclasses`/`re`、MuMu V6.5.5 管理器、ADB、Nemu IPC、现有 Java Combat Agent JAR。

**Spec:** `docs/superpowers/specs/2026-08-26-mumu-v655-phase01-design.md`

## Global Constraints

- 目标设备：MuMu V6.5.5，单实例，横屏 1280×720，240ppi。
- 固定队伍元数据：`Augusta`、`Iuno`、`ShoreKeeper`。
- 阶段01不发送 `semantic_action`，不执行游戏输入，不启用自动战斗。
- ADB serial、真实鸣潮包名和设备绑定属于设备域，不写入账号配置。
- 发现只能生成候选，禁止按 ADB/实例枚举顺序猜测设备。
- 任一身份、包名、分辨率、截图或 Agent 状态无法确认时失败关闭。
- 代码变更同步版本；本阶段为中等变更，版本更新为 `1.13.00` 前必须由用户另行确认，当前实现保持现有版本文本不变，先完成本地验证。
