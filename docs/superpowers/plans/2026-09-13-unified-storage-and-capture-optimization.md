# 安装盘统一存储、启动自动迁移与截图识别综合优化方案

日期：2026-09-13。设计基线：1.62.00 / `09b58120`。状态：1.63.00 已完成本轮实现及离线验证，当前进度见第 11 节；尚未迁移开发机或使用端真实数据。

本文是后续实施的主方案，整合此前截图审查、局部识别方案和用户最新要求。旧版本更新后，首次启动自动将本程序管理的运行资料迁到程序安装盘；不再以用户手动运行迁移脚本作为正常流程。

审查依据：`docs/reviews/2026-09-13-screenshot-comprehensive-audit.md`。早期任务细节：`docs/superpowers/plans/2026-09-13-screenshot-roi-optimization.md`。两者与本文不一致时，以本文的启动迁移、存储和可靠性要求为准。

## 1. 交付目标

1. 程序安装在 E 盘时，本程序可控制的截图、统计、诊断、日志、录像、备份及运行缓存均在 E 盘继续写入，不再默认写 C 盘 AppData。
2. 已安装的旧版本通过普通更新即可获得此行为：更新后第一次启动自动发现旧资料、复制、校验、修复引用并切换，无需用户逐项修改路径。
3. 原有账号、材料库存、历史结算、完成证明、未完成领取记录和待上传资料完整继承，不能出现空仓库或重复收益。
4. 减少全图预处理、重复 OCR、无变化页面保存、重复 PNG 编码和后台补帧；效果通过使用端记录验证。
5. 后续更新保持同一个实例数据目录，重复启动不重复全量搬运；首次迁移中断后可恢复。

统一安装盘分散的是磁盘竞争。安装盘与游戏盘必须是不同物理硬盘才有相应隔离效果；同盘不同分区不等同于分离物理 I/O。OCR 主要消耗 CPU/内存，不因搬盘自动变轻。

## 2. 数据范围与目录规则

### 2.1 默认位置

从安装实例实际入口位置解析安装卷，不能依赖当前工作目录、快捷方式工作目录、开发机盘符或临时解压路径。示例：

```text
E:\OKWW-Data\<稳定实例标识>\
  screenshots\          通用截图、活动调试图、切号取证
  MaterialPlanner\      材料数据库、扫描原图、结算和统计
  CompletionEvidence\   完成证明、缩略图、恢复记录、索引
  diagnostics\          会话、日志批次、待上传队列与状态
  logs\                 本程序及本程序启动器日志
  recordings\           每日留档录像
  backups\              本程序配置和可归属的资料备份
  exports\              账号配置等导出资料
  cache\                本程序可控制的 OCR/模型/运行缓存
  migration\            清单、校验结果、冲突副本、迁移日志
```

实例标识持久保存，不随版本改变；维护它与旧路径散列 installation_id 的对应关系，以继续识别旧诊断任务及来源。多个安装实例不能写入同一活动数据库。

根目录不可创建时，可使用经过验证、位于相同安装卷且在更新覆盖范围之外的安装父目录下 `OKWW-Data/<实例标识>`。选择结果持久化，不每次启动重新挑路径；两处均不可写时明确提示，不回退 C 盘。不得把数据放进按版本清理的目录或更新暂存目录。

已经位于安装盘的受保护 `configs`、安装盘后台解释器、更新下载/解压/回滚目录可沿用原位置，无需为统一文件夹而再次搬运。统一安装盘与所有内容必须放进一个文件夹是两回事。

### 2.2 旧来源清单

| 类型 | 必须检查的来源 | 迁移要点 |
|---|---|---|
| 通用截图 | 程序 screenshots、已有 runtime_storage 设置 | 包括原图、框图及子目录，不覆盖重名异内容文件 |
| 特殊截图 | event_debug、account_switch_failures 等硬编码位置 | 修改写入与打开目录入口，避免迁完仍写旧盘 |
| 材料 | `%LOCALAPPDATA%\OKWW\MaterialPlanner`、已配置新根 | claims、frames、snapshots、parses、claim_events 与原图一起迁 |
| 完成证据 | `%LOCALAPPDATA%\OKWW\CompletionEvidence`、已配置新根 | 数据库、缩略图、pending_verified、上传引用一起迁 |
| 诊断 | `%LOCALAPPDATA%\okww-custom\diagnostics` 中当前安装的目录、已有显式根 | 迁移当前实例会话及队列，保留 device_id、run_id、batch_id 和重试状态 |
| 日志 | 程序 logs、可确认归属的启动器日志 | 启动器也需改写入路径，不能只改 Python 主程序 |
| 录像 | 程序 okww监控室、数据仓库配置中的录像子目录 | 只迁本程序明确管理的子目录，不遍历整个用户硬盘 |
| 备份与导出 | 配置备份设置、数据仓库子目录、export_accounts 等 | 保留文件内容与历史版本；显式导出选择的用户文档不擅自搬动 |
| 可控制缓存 | 应用 cache、OCR 引擎可配置缓存、程序私有临时目录 | 使用库支持的设置，不修改系统级环境变量 |
| 登录序列备份 | 本程序创建且可确认归属的序列备份 | 与游戏/登录器正在使用的目录分开处理，保留联接目标语义 |

同时发现旧默认目录与 1.62.00 手动迁移目录时，两者都进入来源记录。配置指向的现行数据库为主来源；旧目录作为历史来源登记，不能任选一个较新的文件覆盖另一套资料。

同一目录由不同路径、大小写或短路径访问时先规范化、去重；不沿未知目录链接递归复制。多安装共享旧默认仓库时，保留当前程序原本可见的历史，并标记共享来源；若仍有其他写入者，等待其释放或使用经过验证的一致性快照，不停止不属于当前安装的程序。

### 2.3 不属于本次可自由迁移的数据

游戏和第三方登录器自己管理的活动 AppData、Windows 凭据库、系统分页文件及系统日志不由本程序改位置。程序可管理的序列备份纳入清单，但不能为了“全部同盘”破坏游戏登录目录联接。

不能承诺 Windows 完全不写 C 盘；承诺范围是本程序可控制的运行数据路径。已有 NAS 数据继续保存在 NAS，不下载回安装盘重新迁移；NAS 只使用 `\\192.168.3.173\羲火君 共享给我\AI诊断`。

## 3. 更新后启动自动迁移

### 3.1 为什么不能只在现有启动后调用旧脚本

当前 main.py 在建立完整主界面前已导入 config，并启动 diagnostics。config 导入阶段会计算部分目录；诊断启动会打开文件并唤醒上传器。迁移若在这之后执行，会出现一边复制、一边向旧目录写入。

现有 `scripts/migrate_runtime_storage.py` 只适合离线手动操作：覆盖类型有限、目标必须为空、没有完整续传状态、不能承担所有数据库与后台任务交接。可复用校验和路径检查，不直接把它塞入现有启动流程。

### 3.2 新启动顺序

```text
定位实际安装实例与安装卷
  → 获取实例启动/迁移锁
  → 读取轻量存储引导配置、迁移状态
  → 发现旧来源并判断是否需要迁移
  → 展示轻量启动迁移进度
  → 暂停当前安装的旧后台写入者
  → 建立一致性清单和数据库快照
  → 分批复制、校验、修复引用
  → 提交新目录配置和存储代次
  → 重绑定当前安装的上传任务
  → 导入正式应用配置、初始化日志和仓库
  → 显示主界面、恢复后台上传
```

迁移引导必须早于所有会初始化仓库、截图保存和日志文件的导入。审核 `_sync_custom_ok`、包导入副作用和启动器自身日志，不能仅靠移动 `start_diagnostics` 一行完成。

用户可看到进度，不需要逐项确认普通迁移。主界面初始化与自动任务执行等待迁移提交；不能在复制过程中自动开始每日任务、OCR、录屏或截图。

### 3.3 不同安装状态的行为

| 场景 | 启动行为 |
|---|---|
| 新安装、无旧资料 | 在安装盘初始化目录和实例配置，正常启动 |
| 旧安装、资料在其他盘 | 自动启动迁移，成功后继续启动主程序 |
| 已设置自定义根但位于其他盘 | 按本次统一安装盘要求迁移其本程序数据，不能因为“已有配置”而跳过 |
| 已在安装盘且格式有效 | 不复制内容，只补齐必要路径注册与迁移版本标记 |
| 上次复制中断 | 读取清单继续未校验文件，已完成文件检查后复用 |
| 已切换但后台交接未完成 | 不重迁数据，继续修复上传任务；本地资料以新目录为准 |
| 旧源盘暂时离线 | 显示具体来源不可用与重试入口，不把该来源判定为空 |
| 空间不足或目标不可写 | 保持迁移未提交，显示需要空间和当前路径，允许退出后重试 |
| 目标存在同实例已完成资料 | 验证实例/代次后继续使用，不要求每次空目录 |
| 目标属于其他实例或存在数据冲突 | 保留双方资料，进入可解释的待处理状态，不覆盖或自动选较新文件 |

## 4. 一致性、续传和提交机制

### 4.1 迁移状态机

```text
DISCOVER → QUIESCE → SNAPSHOT → COPY → VERIFY → REWRITE → COMMIT
                                                       → REBIND → READY
任一步失败 → BLOCKED（保留阶段、原因和已校验文件）
下次启动 → 恢复对应阶段，不从头盲目复制
```

状态包含 migration_id、稳定实例标识、存储格式版本、源根/目标根、阶段、校验计数、错误、旧配置快照、旧计划任务描述、新存储代次。引导状态放在安装盘受保护 configs 下；迁移详细清单放目标 migration 下。写临时文件并原子替换，完成标记不能早于耐久数据。

### 4.2 阻止旧后台继续写入

- 保存当前安装计划任务的原始定义，校验 Description、SourceRepo、解释器和队列根的归属。
- 暂停该计划任务，等待正在运行的同实例上传/收集进程退出；必要时仅停止明确归属的工作进程及子进程，不能按 python/pythonw 进程名全杀。
- 对旧上传器版本，不能假设它认识新迁移标志；必须通过系统任务交接与独占文件锁确认写入已停止。
- 获取来源 collector/uploader/数据库相关独占访问；同源资料仍变化时重新快照或停止提交。
- 新版各入口（主程序、上传器、修复工具、迁移工具）检查同一存储代次与迁移状态，防止重复启动旁路。
- 迁移失败或用户退出时，释放自己的锁并恢复未提交阶段应保留的旧任务定义。下一次重试重新暂停与快照。

### 4.3 文件复制

- 普通文件使用单个低并发 I/O 工作器顺序复制，按块计算源摘要，写 `.partial`，关闭并刷盘后读回目标校验 SHA-256。
- 验证通过再改为正式迁移文件名；源大小/时间/身份发生变化时作废该文件完成记录，重新读取。
- 清单按批次检查点写入，不每个数据块 fsync 一次；建议每 32 文件或 1 秒提交进度，小文件与大文件分别处理。
- 恢复时验证已完成目标确实存在且摘要匹配，不能仅凭“已完成”布尔值跳过。
- 目标同相对路径、同摘要可复用；异摘要保留为来源命名的冲突副本，不覆盖。
- 初始空间检查包含尚未复制的数据、数据库快照/索引开销和至少 512 MiB 余量；复制期间继续检查，避免只在开始检查一次。
- 不递归删除旧数据，不靠删除历史材料图片释放空间来让迁移通过。

### 4.4 数据库和关联文件

材料及完成证据使用 SQLite。不能在数据库活跃写入时只复制 index.sqlite3，也不能忽略 WAL 中的已提交记录。

在写入暂停后，通过 SQLite backup API 生成一致性快照；对快照执行 integrity_check，核对表结构、行数、关键业务 ID 与记录摘要。普通图片逐文件 SHA-256；数据库快照不要求与原数据库文件字节完全相同，因为页布局可能不同。

数据库所引用的原图、缩略图和恢复文件全部进入清单。先验证快照及图片，再在目标快照中修改必要路径，最后重新做完整性与引用存在性检查。没有图的原有异常记录继续保持异常，不在迁移中伪造图片或改成完成。

多个有效数据库不能文件级覆盖。以当前配置活动库为主，历史库保留完整副本；若需合并，只按现有业务唯一键插入非冲突记录。同 ID 同内容幂等跳过，同 ID 异内容登记冲突并阻止该业务库成为活动库，不能以时间戳猜测正确版本。

### 4.5 必须修复的引用

| 引用 | 处理 |
|---|---|
| 材料 frames.path 与扫描/结算关联 | 保留相对路径与 record_id/claim_id，不重建业务身份 |
| 完成证据 image/thumbnail/recovery | 采用新根下相对路径，验证每条有效引用 |
| pending_verified/nas.json | 改用 run_id/batch_id + 当前诊断根；旧绝对路径通过显式迁移映射解析 |
| 诊断 source-cursors | 移动后 inode 变化仅在确认相同内容时更新，保留采集偏移，避免历史全部重传 |
| 上传状态与待传索引 | 保留成功/待传/重试/阻断语义；缺少状态不等于上传成功 |
| NAS 不可变 manifest | 不重写其远端路径或文件摘要；本地解析根改变即可 |
| 录像、备份、导出设置 | 统一新写入根；旧记录中的路径可通过迁移映射追溯 |
| 后台 source.json、计划任务 | 使用实际安装位置和新存储根；独立运行环境不依赖开发机路径 |
| 更新暂存/恢复记录 | 已在安装盘的目录保留；跨盘改位置时同步更新校验边界，不只修改下载路径 |

### 4.6 最后提交及回滚边界

只有资料、数据库和引用全部验证成功，才原子提交新根及存储代次。提交前任何失败均以旧配置为准，主程序不进入正常任务状态。

提交后若只发生 NAS 不可达或计划任务交接失败，新目录仍为唯一活动根，本地可正常工作，界面显示上传待恢复并自动重试；不能自动切回旧库，否则会形成两份分叉资料。后台入口在代次不匹配时不得向旧根写入。

旧目录保留为迁移前副本，此后不再作为活动写入位置。保留副本是为了恢复，不代表仍把运行负担留在旧盘。材料统计和证据不自动删除。手动回滚必须先保护迁移后的新增资料，不能直接用旧副本覆盖新库。

## 5. 启动与设置界面

启动窗口只显示用户需要的信息：

```text
正在将运行数据迁移到程序安装盘
目标：E:\OKWW-Data\…
当前：复制材料收益截图
已校验：1250 / 4800 个文件，2.4 / 8.1 GB
首次更新可能需要较长时间，下次启动将直接使用此目录。
```

复制前不显示虚假的百分比；扫描阶段显示已发现大小/文件数，完成清单后再显示总进度。正常情况无需确认按钮；可安全退出，下一次启动续传。错误页显示失败类别、源/目标、剩余空间、重试和打开迁移日志入口。

迁移 I/O 在后台工作器完成，轻量窗口保持响应，但正式应用任务尚未启动。不能启动完整应用服务来获取进度窗口，否则会破坏迁移前禁止写入要求。

设置页显示程序安装位置、活动数据位置、迁移完成状态、保留旧副本位置和打开目录入口。这里不再默认引导用户把本程序数据选到其他盘；安装盘不可用时明确处理，不隐式降级。

## 6. 截图、识别和证据优化

### 6.1 弹琴：高频局部计算

当前每轮 analyze 对整图灰度化和 float32 转换，再读取 21 个琴键圆环。改为按圆心及完整外半径求联合区域，先裁 BGR、再灰度化；掩码按分辨率缓存。1440p 联合区域约为整屏 14.7%，这是计算范围，不是整机 CPU 降幅。

保持 0.05 秒默认检测、双帧确认与按键释放逻辑。不要照搬已有诊断裁图边界导致裁掉外圈。非弹琴阶段可以另行验证较低检测频率，但每秒按 F 的既定行为不变，不能重新识别 F 图标。

### 6.2 材料：先判断是否需要保存

拆分 `_capture` 的取帧与编码保存职责。回顶、滚动到底的静止探测在内存中判断；有效页面保存一次完整原图，重复观测引用该页并保留时刻与滚动依据。每帧最多归一化一次，图标、数量、标题与类别共用同一页图。

所有有效收益页必须保留，跨 claim_id 绝不合并；同次领取的重叠行不重复统计。目标绿色数量决定领取份数，顶部/底部及页间重叠决定完整性。未知材料、未确认底部或缺绿色仍不能宣布完整。

仓库非目标格子可减少数量 OCR，但要先以位置/图标签名/总数完善覆盖判定，不能直接删读数逻辑。通用转化材料不计入刷满；突破材料只记录，技能材料沿用周本，刷满后去账号所选无音区。

### 6.3 完成证据：一次快照、一次原图编码

在线程交接处建立一次稳定快照。require_image 保存链路将同一原图编码一次，恢复记录、正式记录和上传复用经校验的 PNG 资产；缩略图独立生成。避免现有“恢复图编码→解码→正式图再编码”。

先图片耐久保存，后索引完成；任何失败不能变成无图已完成。历史恢复图片保留，重试不重复编码。复制截图时按需解码原图，未来微信发送引用同一完整证据，不重新截游戏。

### 6.4 深塔：按帧保存页原图

同一 frame_id 原图只保存一次；多个模糊角色卡只增加裁图和矩形元数据，查看时生成标注。旧/新页冲突引用对应原图，不为每个角色再存相同整页。

保留两次独立新帧复核和跨页核对。等级整行 OCR 收窄到实际使用的等级带；能量仍保留数字定位、位数校验、多尺度共识。没有回放证据前不减少防止近期能量误读的确认次数。

### 6.5 普通 OCR：按观察上下文复用

先补齐裁剪、resize、摘要、实际推理和绕过缓存路径的计时。当前缓存适用范围窄，还会计算全图摘要；改为同次帧观察内共享某一区域的原始 OCR 检测，再按不同 match 条件筛选。

成功采集具有 sample_id、window_generation、尺寸、来源和时刻。输入、切页、账号、窗口、语言、分辨率变化使缓存失效。样本 ID 递增不等于画面真实变化，不能作为稳定判定的充分条件。

特征码已局部 OCR，继续走 raw engine 和三独立帧要求；只优化全图摘要的多余字节分配，不用普通缓存代替核验。

### 6.6 诊断：不为无视觉任务持续补全屏

有视觉任务优先使用任务已采集帧；第二索拉等无视觉按键任务按阶段/错误请求图，暂停空闲减少补帧和定时唤醒。修改诊断采样密度时，记录真实间隔和缺帧原因，不维持虚假的“十张前置帧已齐”。

原始小图内存缓存、出错后编码只是候选：要比较内存峰值及异常瞬间编码延迟，不能仅为少写盘而无限保存原始帧。已有显式低 PNG 压缩等级曾更慢，保留实测有效策略。

### 6.7 通用截图与其他任务

将 original/boxed 作为同一事件的原图和派生标注，避免普遍双图落盘。队列按字节数限制，关键收益与完成证据不能被普通调试图挤掉或静默丢弃。EventTask 调试图改为阶段变化/异常触发并异步保存。

周本在一张稳定帧内共享列表 OCR，但点击前新帧确认保留。多账号在已验证面板内局部识别，并保留可信窗口、桌面坐标原点及全屏回退。切号测试继续复用生产方法。

日常录像保留用户设置，去掉每段末尾未使用的新帧采集；可选缩放录像，不缩小关键证明原图。完成页已有缩略图、分页和按需刷新，不重复建设。

### 6.8 真正的底层局部采集放最后

先裁数组只能减少处理量，不能省掉此前全屏采集。只有指标证明采集/显存回读仍是热点，才增加独立 `capture_region(rect)`，返回局部图、原点、全尺寸、来源和时刻，不改变 executor.frame 的全图契约。

BitBlt 试验只复制客户端矩形；WGC 试验局部 staging texture/纹理复制。WGC 当前已有 frame_requested 条件，不是固定每秒把 60 张全帧搬到 CPU。新接口不支持或坐标失效时回退全帧后裁剪，不能影响截图证明或正常定位。

### 10.1 两份方案如何配合

### 10.2 D0：先记录实际后端，再验证 CPU 平衡配置

涉及 `custom_ok/ok/task/TaskExecutor.py`、`src/runtime/ocr_reuse.py`、`config.py` 及可发布的 OCR 适配层。配置必须实际传到 OpenVINO compile_model；不能仅新增一个无人读取的 cpu_threads 字段，也不能只修改开发机 .venv 中的依赖文件。

- [ ] 记录实际设备、推理线程数、stream、OpenCV 线程数和库版本；use_npu=True 不作为已经使用 NPU 的证据。
- [ ] 分别统计取帧等待、纹理回读、像素复制、ROI/resize、摘要、检测、识别、编码、磁盘保存与队列等待；计时覆盖缓存命中及绕过路径。
- [ ] 在同一图集与固定 OpenCV 设置下比较默认、4、2 推理线程，确认编译后真实值；后端不支持时使用原配置并记录原因。
- [ ] 用游戏同时运行的使用端结果决定默认档位；同时看累计 CPU 秒、p95 延迟与游戏流畅度，不能仅以任务更快为标准。
- [ ] 不在线程间反复修改全局 OpenCV 线程设置；任何全局线程变更均单独回归，不能与 OpenVINO 收益混算。

### 10.3 D1/D2：材料模板优先，数字批量随后

涉及 `src/materials/catalog.py`、`src/materials/vision.py`、`src/task/MaterialPlannerTask.py`。报告的热点来自一张材料库存页，需分别验证库存、培养目标和收益页，不能推定所有页面占比相同。

**D1 第一阶段只缓存完全相同图标的匹配结果。** 使用与现有匹配相同的图标输入；缓存键含像素、尺寸、模板库版本及匹配参数，并设置容量上限。只复用图标身份与匹配分数，数量始终重新读取，不能把选中高亮或背景变化忽略后强行命中。

**D1 第二阶段才试候选模板筛选。** 保留最佳分数和最佳/次佳差距语义。只对入选模板算出较高第一名，不能证明未入选的第二名不存在；先在回放中同时运行全量基线，核对候选召回和未知拒绝。无法保证歧义规则时继续全量匹配，不上线不可靠剪枝。

**D2 使用已有 recognizer 接口收集并批量识别数字 ROI。** 标题保留完整检测识别，结果按格子身份回填。格式非法、低置信度、异常范围或独立观察不一致时回退原路径；合法误读仍需人工标注和业务复核，不能仅凭 parse_number 成功决定库存刷满。

- [ ] 增加选中/未选中、未知图标、相近模板、滚动过渡、不同分辨率回放，比较身份、最佳/次佳、拒绝结果。
- [ ] 新建或补齐人工数字标注，覆盖 1/-1、10/18、前导零、低对比度、缺失及遮挡；分别报告与旧算法一致率和人工准确率。
- [ ] 保留跨领取不合并、非目标格覆盖、绿色奖励份数、页间重叠和底部确认规则。
- [ ] 统计图标缓存命中率、全量回退率、数字回退率、整页与整次扫描耗时；不能将 OCR 局部节省当作扫描节省。

### 10.4 必须纠正或明确的边界

1. **材料判重预处理不直接改顺序。** 报告的“先裁剪再缩小”微基准虽快，但与原结果平均像素差约 8.80，现有阈值为 1.5。首批保持原插值、归一化和比较语义，只消除重复计算；改变算法需要单独标注重复/非重复页面并重标定阈值。
2. **ROI 相同不等于全图证据相同。** 内存探测可以依据 ROI 稳定停止滚动；保存完整证据时不能用这一结果复用含不同弹窗、账号或页面状态的全图。
3. **保留完成证据解码和损坏检测。** 先减少第二次编码。只有可信像素与已编码资产的完整性契约明确后，才研究正常保存免解码；恢复路径仍须检验损坏文件。
4. **诊断降频不是无损优化。** 1 Hz→0.2 Hz 在十秒前置窗口中约从十帧降为两帧，可能丢失短暂弹窗。先复用已有任务帧，按任务风险调整；需要完整前置证据的阶段不全局降频。
5. **缓存依赖不可变像素。** frame_id 不能只是 ndarray 的对象地址。检查原地画框、复用底层缓冲及线程所有权；不同阈值、语言、缩放、processor 与有副作用调用不能误命中。
6. **迁移解决写盘位置，优化解决工作量。** 移到另一物理硬盘不消除 PNG、模板和 OCR 的 CPU 成本；报告也不足以证明使用端 98% 磁盘活动时间全部由截图导致。使用端验收需记录每进程 I/O、磁盘延迟/队列、内存压力及游戏流畅度。

### 10.5 修订后的实施顺序与交付判据

保留 A/B/C 的自动迁移与路径收口主线，启用前通过第 8 节迁移验收。性能工作按以下独立交付推进，无需等待整个迁移项目完成才做离线实验：
