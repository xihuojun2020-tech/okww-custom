# 活动「若梦仍有回声」第一阶段制作文档

更新日期：2026-09-14。基线版本：1.68.00；实现版本：1.69.00。状态：第一阶段代码与离线验证完成，实机验收待用户进行。详见 [执行记录](reviews/2026-09-14-echoes-remain-phase1.md)。以下保留制作规格，实际实现差异见第 13 节。

## 1. 目标与完成边界

从大世界经 F1 进入活动「若梦仍有回声」，进入当前选中的关卡，打开快速编队，以活动提供的三个试用角色替换原队伍。换人后截图复核，点击“完成”返回编队页，任务结束。

本阶段不点击“开启挑战”，不执行战斗、结算、领奖、切换关卡或积分判断。不把“编队完成”写成“活动完成”。用户负责实机验收。

## 2. 用户已确认的行为

| 项目 | 已确认规则 |
| --- | --- |
| 活动入口 | F1 → 左侧若梦仍有回声 → 右下角前往 |
| 当前关卡 | 进入关卡页后使用游戏当前选中的关卡，点击单人挑战 |
| 难度 | 各大关包含浅梦、深梦；当前展开的大关显示在列表靠上位置 |
| 快速编队初态 | 第一排前三个角色已选，具有金黄色边框及右上角 1、2、3 |
| 试用角色 | 第一排第 4、5、6 个，头像右下角具有时钟符号；角色身份随关卡变化 |
| 取消后的排序 | 取消前三人不会使头像重新排列 |
| 下一关初态 | 再次打开快速编队时，仍然是前三个已选、第 4～6 个为试用角色 |
| 本阶段操作 | 初始截图检查 → 固定坐标取消 1～3 → 固定坐标选择 4～6 → 新截图复核 → 完成 |
| 后续活动目标 | 每个难度通关一次，不重复刷分，不把指定积分作为通关要求 |
| 后续自动推进 | 浅梦完成后自动选中同关深梦；深梦完成后自动展开下一大关 |

这些规则允许正常情况下批量坐标点击，但不能省略每次开始时的初始状态检查。

## 5. 状态流程

```text
大世界
  → 推荐活动页
  → 若梦仍有回声活动详情
  → 当前关卡页
  → 编队页
  → 快速编队页
  → 初始状态验证
  → 取消前三人并选择试用三人
  → 最终状态验证及保存证据
  → 点击完成
  → 确认返回编队页
  → 本阶段完成，停止
```

每个阶段采用“确认当前页面 → 执行动作 → 确认目标页面”。超时或用户停止必须退出当前输入流程，不继续点击下一页面的坐标。

### 5.1 打开活动

1. 若已经位于可识别的目标页面，可以从对应状态继续，避免重复按 F1。
2. 否则先使用现有方法回到大世界，再按 F1，确认“推荐活动”。
3. 只 OCR 左侧活动列表，寻找“若梦仍有回声”。未找到时按现有活动入口方式有限滚动，检测列表无变化后停止。
4. 点击唯一匹配项，再检查右侧标题和“前往”按钮。不能把活动固定为左侧第一行。
5. 点击“前往”，确认出现活动关卡页。

### 5.2 进入当前关卡

1. 局部读取右上角“关卡名·浅梦/深梦”，作为本轮身份与日志字段。
2. 中文关卡名优先，罗马数字作为辅助；兼容 `Ⅰ/Ⅱ/Ⅲ` 与 `I/II/III`，不靠孤立的竖线判断关卡。
3. 不滚动八关列表、不点折叠标题、不主动切换难度。
4. 当前页面和“单人挑战”可用时，点击该按钮；确保没有点到左侧“多人匹配”。
5. 若显示未解锁或没有可操作入口，记录阻断原因并退出，不视为活动完成。
6. 确认编队页出现“快速编队”，点击后等待角色列表稳定。

### 5.3 初始截图检查

进入快速编队后取得一张新帧，从同一帧提取页面标题、第一排卡片、编号、边框、时钟及顶部位置特征。

正常输入必须同时满足：

- 页面标题为“详情”，底部存在“完成”，第一排七列卡片布局可定位。
- 列表处于顶部，画面比例符合本阶段支持范围。
- 第 1、2、3 个角色均有选中金边，编号分别为 1、2、3。
- 第 4、5、6 个没有选中标记，且三个右下角时钟均通过检测。
- 可见区域没有与上述结论矛盾的额外选中编号。

时钟是试用身份的检查条件，不要求知道每关三个试用角色分别叫什么。不得因景燃已能识别就把三个试用角色固定为景燃、尤诺、守岸人；用户第二张编队样本的试用队伍已经不同。

初态不符时只允许刷新一帧重新检查。若仍不符，保存证据并停止；本阶段不扩展为全列表自动寻人。若当前已精确符合最终三人状态，可直接复核后完成，避免重复取消和重选。

### 5.4 坐标点击

初态通过后，在位置不重排的前提下按顺序点击第 1、2、3、4、5、6 个角色。前三次取消，后三次选入，最终队伍顺序由第 4→5→6 个角色确定。

首轮实施建议单次点击后等待约 0.2～0.35 秒，由离线输入测试和用户实机反馈确定最终值。等待期间响应任务停止；不每次运行全屏 OCR，也不逐点击落盘截图。

### 5.5 最终截图复核与纠错

最后一次点击后等待界面稳定，重新取得新帧，不能复用点击前缓存。验证：

- 第 1～3 个金色选中边框与编号消失。
- 第 4～6 个金色选中边框存在，编号严格依次为 1、2、3。
- 第 4～6 个试用时钟仍存在。
- 可见区域没有额外选中编号；没有弹窗或页面切换遮挡。

首次不符时，重新抓取一帧排除动画延迟。只有能够明确证明“单个漏点、角色位置未变、修正后顺序仍正确”时，才补点该位置并复核一次。编号顺序错乱、多处矛盾或无法可靠判断时直接停止。不能盲目重放六次点击，因为这会切换已正确的选中状态。

复核通过后保存一张带有当前关卡和任务阶段关联记录的编队证据图，再点击“完成”。确认返回编队页且“快速编队”重新出现后，记录本阶段成功，停止输入。不得点击“开启挑战”。

## 6. 坐标与区域设计

所有坐标以游戏客户区有效画面为基准，而不是桌面或含窗口边框的截图。换算为 `x = round(x_ratio * width)`、`y = round(y_ratio * height)`。以下为样本推导的候选值，正式实现必须通过原图像素和不同分辨率复核。

| 控件 | 候选中心 `(x比例, y比例)` |
| --- | --- |
| 活动详情“前往” | `(0.873, 0.915)` |
| 关卡“单人挑战” | `(0.894, 0.912)` |
| 编队“快速编队” | `(0.695, 0.919)` |
| 角色列表“完成” | `(0.831, 0.912)` |
| 第一排角色 1～6 | `x = 0.131 + 0.1221 * 列索引`，`y ≈ 0.24`；列索引从 0 起 |

关键检测区域建议：活动列表为画面左侧约 8%～28%，标题为对应页面上部，动作按钮为右下角，快速编队只处理第一排。卡片右上角数字与右下角时钟均使用卡片内部相对坐标；准确裁剪框由六张原图校准。

支持目标为 16:9 的 1280×720、1920×1080、2560×1440、3840×2160。窗口位置变化不影响客户区归一化。超宽屏、黑边、缩放导致卡片布局不符时停止并报告，不直接套用 16:9 坐标。

## 7. 识别与性能约束

- 获取完整帧与识别完整帧是两件事。即使捕获后端仍提供整帧，也只对必要 ROI 做分析；不要声称裁剪 OCR 就减少了底层截屏成本。
- 进入页面使用局部标题和按钮识别；队伍检查使用小范围颜色/边框、数字及真实时钟模板。
- 每个检查阶段只取一张帧供多个检测器共享；页面刚变化时必须请求新帧，不沿用旧检测结果。
- 正常换人不逐步保存截图。保存最终复核证据，初态图暂存在内存；异常时再保存有助定位问题的前后帧。
- 不扫描仓库，不遍历整个角色库，不进行角色 ORB 全库匹配，不创建录像。
- 建议页面等待上限 8 秒、入口点击最多 3 次；轮询间隔初始取 0.3～0.5 秒，按现有任务机制及测试调整。禁止无界循环。
- 记录页面阶段耗时、截图次数和识别次数；以实测比较性能，不预先承诺固定 CPU、硬盘或帧率下降比例。

## 8. 结果、证据和保留策略

建议结果至少包含：账号身份、活动标识 `echoes_remain`、关卡中文名、浅梦/深梦、阶段结果、试用卡片位置、预期编号、复核结果、证据引用和时间。

本阶段成功状态为 `formation_ready`，含义仅为试用编队完成。活动整体完成状态保持未完成或未知，不能更新为全通关；不能使用旧截图推断本轮成功。

复核截图进入项目已有证据保存机制，具体调用在实现时确认。临时诊断副本服从当前手动上传和诊断保留期限；若同一截图被业务证据索引引用，必须遵循业务证据的生命周期，不能因诊断副本到期就误删仍被业务引用的原图。材料收益统计及其永久原图不受本活动影响。

## 9. 异常处理表

| 情况 | 动作 |
| --- | --- |
| 活动列表没有目标 | 有限滚动查找，仍未找到则停止并记录 |
| 点击后页面未切换 | 同页确认后有限重试，不连点下一步坐标 |
| 当前关卡未解锁 | 记录待解锁，结束本轮 |
| 快速编队不在顶部或布局不符 | 不执行六次换人，保存诊断 |
| 第 4～6 个缺少时钟 | 不默认其为试用角色，刷新确认后停止 |
| 初始人数、编号不符 | 若已经完全达到目标则复核后完成，否则停止 |
| 六次操作后单个漏点 | 仅在修正不会破坏顺序时补点一次，再复核 |
| 选中顺序错乱或识别矛盾 | 不盲点重置，保留前后证据并停止 |
| 点击完成后未返回 | 确认仍在列表才有限重试，否则报告状态未知 |
| 用户停止、游戏退出、账号失效 | 立即传播停止或阻断，不继续补点 |

## 10. 实施顺序

1. 核对活动任务注册、共享活动名和现有页面等待方法，保持当前工作区无关修改。
2. 从原图建立脱敏测试夹具，校准按钮、第一排卡片、边框、编号和时钟区域。
3. 实现局部状态检测；先验证能区分初始态、最终态、漏点态、时钟缺失态和错误页面。
4. 实现 F1 入口到快速编队的有界导航。
5. 实现正常六次坐标点击与严格受限的单步纠错。
6. 接入证据、阶段日志和点击完成后的返回确认，确保没有开启挑战调用。
7. 添加任务元数据、翻译及必要入口，保持活动整体完成状态不被误更新。
8. 完成离线回归、文档、版本和更新包校验；按项目规则发布 GitHub 与唯一 173 NAS 路径。
9. 用户手动验收本阶段，再提供战斗和结算流程的资料，进入第二阶段。
