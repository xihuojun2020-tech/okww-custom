# 自动战斗持续恢复实施记录（1.89.00）

日期：2026-09-30，北京时间。

## 范围与结论

落实用户要求：自动战斗开启后不因异常自动关闭，只有显式用户停止/关闭才保存关闭偏好。覆盖后台任务、执行器及每日/副本共用战斗动作和探测循环。此轮依据源码及离线回归实施，未审阅新诊断ZIP。

## 修复依据

旧 AutoCombatTask 在首次异常时返回未处理，触发执行器 disable；保护仅在异常后手动重启时建立。恢复钩子报错仍回到 disable 路径。场景重置和调度异常还可能发生在旧捕获范围外。

## 已实施

- 删除首次关闭与重启才保护的分支。内部 disable 只释放本任务输入；UI及显式停止调用专用关闭入口，保留启用代次检查。
- 设备准备失败保留开启偏好和待准备状态，重试准备。恢复钩子失败由执行器安排下次复核；场景重置、无截图、调度阶段错误纳入恢复。
- 角色动作及战斗探测失败持续重试；仍在战斗时重新识别队伍和当前角色后执行原脚本。暂时失去队伍也先复核；确认已离开战斗时交回原结果/失败处理，不误标胜利。
- 保持前台任务的唯一输入执行权；后台不并发抢按键。死亡、复苏、结果交接、配置完整性阻断、手动停止和退出的控制信号保留。
- 输入记录独立命名，避免与初露峥嵘、群声及余音任务的既有集合冲突。释放失败保留原后端，新动作前继续释放。恢复等待暂时禁用错误角色上下文的 sleep_check。
- 诊断状态、日志及已有画面截图限频，诊断报错不关闭自动战斗。证据沿用 okww监控室通路，未新建另一证据目录。
- 重置战斗配置保留开关偏好；启动恢复现有配置，旧关闭值不强制开启。界面状态和任务描述同步五份语言资源。
- 项目 AGENTS.md 与结构说明已记录长期规则，更新旧恢复说明。
