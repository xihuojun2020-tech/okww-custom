## 交付范围与限制

已实现备用体力保护、上传明细和时间补传。原方案中的“回到每日页面复核后，自动返回并完成小额备用转换”没有完成实机闭环，不能标为全部验收通过。本版的明确行为是：每日战斗后只消费当前体力；当前不足时取消领取，退出大世界并复核活跃度。不会为了完成每日预算冒险确认备用转换，也不自动重复战斗。活跃度未满的账号可能因此未完成每日任务。

原因是现有证据不足以确认转换弹窗的数量控件、资源类型及取消后返回流程。单纯调整坐标或延长活跃度有效期不能证明安全。需要使用端按下方流程采集不消费资源的界面证据，再接通数量设置与安全返回。1080P/2K 使用归一化区域，但没有两种分辨率真实转换弹窗验收，因此不宣称识别率得到实机验证。

## 备用体力的代码变化

1. DailyTask 在梦魇后、清体力前重新读取底部累计活跃度。>=100 后，本轮账号的禁止备用标志保持到结束；后续低值不能恢复授权。
2. 账号上下文绑定到已验证的方案 UUID，退出或异常时恢复外层上下文。换号不继承前一个账号的预算。养成重入不重新发放已耗尽预算。
3. 战斗可能使活跃度增加，DomainTask 和 TacetTask 在领奖前废止战斗前读数。当前不足时不点击领奖，退出后由 DailyTask 复核；满或未知均不授权备用。
4. 共用转换入口默认不启用备用。若显式授权进入转换路径，必须识别备用资源标题及唯一明确转换数量，同时拒绝星声、月相和溶剂文字；只接受不超过当前缺口和剩余预算的金额。数量未知、金额过大或确认按钮不唯一时不执行转换。
5. 确认前再次检查授权；确认仅一次。转换中保留未确认标志，余额须同时符合当前增加、备用减少和总量守恒（容忍一点自然恢复）。异常不会重复确认。前后截图与日志保留证据。
6. 原有当前体力单/双倍和领奖后余额核验继续保留。WeeklyBossTask 已有“仅当前体力”路径，不通过备用补充入口。

## 工具页使用方法

打开“工具 → 日志与诊断 → 查看日志、截图及上传明细”。

| 页签或操作 | 能确认什么 |
| --- | --- |
| 日志来源 | 已采集位置、当前本地大小、尚未采集字节、首次启用前历史标志；选中后查看新批次来源字节/时间范围和上传状态 |
| 错误事件 | 按事件去重后的最新修订、错误摘要、截图完整性、前/当时/后数量和上传状态 |
| 截图时间轴 | 每张真实采集时间与相对错误秒数、画面新鲜度、该图片所属批次的上传结果 |
| 文件、批次 | 文件大小、尝试次数、下次重试、真实复制进度、当前错误、成功时间、本地路径 |
| 重试 | 只重新排队 pending/retrying；不清除上传器锁，不重置 blocked、损坏状态或正在上传项 |
| 核验远端 | 最长 30 秒独立进程检查 173 的完成标记、清单与文件哈希；不是由历史成功推断当前在线 |
| 补传指定时间日志 | 本机时间的开始包含、结束不包含；预览后封存脱敏日志。每次最多 32 MiB，保留 traceback 续行，不改自动游标 |
| 导出索引 | 保存当前本地快照，包括事件缺失记录、来源关联及错误详情，供使用端 AI 排查 |

窗口可见时每 5 秒后台刷新，一页 50 项；新数据按稳定标识保留当前选择。SMB、图片解码、源文件检查均在后台。远端核验失败显示具体原因，不写成本地上传成功。源码缓存不与 UI 共享可变字典。

“已复制，待批次完成确认”不等于上传成功。最新事件索引上传成功，但引用的旧批次图片未上传时，事件显示部分截图尚未上传。采集完整性与上传状态始终是两个独立结论。

源文件轮转或不可用时不使用旧 offset 算新文件覆盖。旧版本封存批次缺少来源映射，不能补造字节或时间覆盖证明。新映射中的时间来自日志行时间戳，无时间戳的片段显示未知。

## 是否上传了所有日志和错误截图

不能无条件保证。自动采集覆盖本安装标准 logs/screenshots 中规定扩展名的新内容，以及框架保存截图和错误采样实际得到的画面。首次启用前历史不会自动全量补传，非标准目录和未采集尾部也不在已上传范围。

错误采样目标是前 10 秒、后 5 秒、约每秒一张；无新鲜帧、启动缓存不足、退出、存储限制或采样延迟都会缺图。旧画面不能冒充错误当帧。上传成功只证明封存文件传输完成，不能证明缺失画面曾经存在。超过 7 天且已上传日志仍按原策略清理，截图及待传资料保留。
