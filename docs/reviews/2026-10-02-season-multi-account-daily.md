## 2. 总体判断

故障由多个环节叠加。已明确：邮件页面误进入月卡处理分支、残像聚落点击后未离开列表、网络重连被作为普通页面故障处理、备用体力转换数量未能确认。另有无音区领奖交互未确认、历史队伍识别失败。

没有证据证明截图打包1.90系列修改了战斗或每日流程。该系列主要改证据导出。也不能证明所有问题由赛季更新单独造成：10月1日缺少足够完整的历史故障截图及更新前对照基线。

失败时不写今日完成是正确的保护。需要修复导航、识别和恢复，不能直接去掉完成校验、关闭自动战斗或把所有异常当作成功。

## 4. 根因和置信范围

### 4.1 邮件界面误判月卡：优先修复，证据充分

A1两次链路一致：

- 09:37:38 / 09:45:40：进入claim mail。
- 09:37:42 / 09:45:44：进入ensure_main，日志立即出现monthly_card found click。
- 09:37:57 / 09:45:59：月卡分支等待大世界10秒超时，主界面返回同时失败。
- 同期截图明确为邮件页面，有“邮件”“全部领取”“删除已读”，并显示3.7版本更新补偿邮件及已领取勾选，没有月卡领取弹窗。

源码：DailyTask.claim_mail使用两次固定坐标点击再调用ensure_main；BaseWWTask.is_main在返回操作之前调用handle_monthly_card；find_monthly_card仅使用monthly_card模板、0.65阈值和较宽位置容差。handle_monthly_card在误识别后持续点击(0.50,0.89)，等待大世界，并且没有检查等待成功就设置下次月卡检查时间。

因此故障实质是错误页面进入月卡处理逻辑并耗尽时间。仅把ensure_main从10秒调到60秒会增加等待，无法消除误判。尚未单独量化邮件页面模板匹配分数，但日志和同期截图已证明分支分类错误。

### 4.2 残像聚落入口导航缺少点击结果恢复：状态已确认，点击未生效的细因待核验

A5 09:02:40与A2 09:48:29异常截图都停在残像聚落列表，右侧仍显示各地点“前往”按钮，没有进入地图传送或队伍挑战页面。

NightmareNestTask.combat_nest对nest.box只点击一次并固定等待2秒，随后wait_book_target_state最多等待10秒。识别只接受地图传送、移除标记、挑战按钮等下游状态，没有对“仍在源列表”的明确处理，也未重新确认目标行并重点击。

A2截图可见部分地点48/48、另有0/41或0/48，这不表示选定全部地点完成。程序没有误写完成；问题是入口阶段没有恢复。

不能仅据截图断定坐标偏移、地图未解锁或新增第五行是唯一原因。需要新增目标名、行进度、按钮坐标和点击后页面状态记录，再用该设备实测辨别输入丢失/目标框过时/未解锁提示。A5随后有网络重连，不能把A5与A2的底层原因强行归一。

### 4.3 网络异常未独立分流：截图确认

09:03附近截图显示“网络异常，正在重新连接中”。F2导航仍尝试到3/3，失败后退登仍按main状态尝试3次，最终恢复失败。

根因是页面识别未把重连遮罩作为独立阻塞状态。重连期间背景大世界可见，不能据此认定可操作，也不能反复发F2/ESC和切号动作。报告不能判断断线来源于运营商、NAS、游戏服务器还是设备网络；只证明游戏发生了重连。

### 4.4 活跃度不足与备用转换未确认：需要区分资源不足和UI识别失败

5次顶层失败属于活跃度未满。A4首轮明确80分、消耗120/180；局部补齐before=(120,180)、after=(120,180)，没有确认进展。

10:04:33资源日志为current=2、backup=39，凝素单次40，程序需要转换38，但conversion_amount返回None，于是禁止转换。此时总资源41仍小于补齐60消耗所需的两次40；即便修好转换，也不能保证立即达标。后续A4/A5还出现需26、9、25、7而数量None的日志，说明转换UI数量确认需要专项适配，但不能把每个账号都判成相同资源状况。

源码目前要求从弹窗OCR确认精确数量和唯一确认按钮；不确认就不转换是应保留的安全条件。需要适配数量输入、校验上下限及转换前后余额，而非允许默认最大转换。对确实资源不足的账号应保留待补状态，避免全账号盲目重跑。

### 4.5 无音区领奖和队伍识别：次级专项

10-01 A1在TacetTask.farm_tacet→walk_to_treasure失败，报claim interaction unconfirmed；当前逻辑有45秒搜索和最多6次方向微调，并要求确认F领取交互。日志只能确定未确认交互，不能证明奖励位置变化或战斗未结束。应检查对应场景、领奖文字与地图标记后再适配，不能用无条件F或重开挑战替代。

10-01 10:26:31还出现CombatStateUnknown队伍身份未确认；历史日志11:29有自动关闭旧文案。10月2日采集版本已1.90.03，10月1日堆栈行号也与当前不同，因此历史自动关闭不能直接作为最新持续恢复版本又回退的证据。保留当前自动战斗开启意图和角色身份核验，未知队伍仅暂缓动作、重新识别。

## 5. 修复实施方案

### P0：月卡与邮件状态分离

1. 在共享月卡入口加正向页面信号，并排除邮件、指南等普通菜单；不要只提高模板阈值。
2. 邮件操作改为识别邮件页、全部领取、领奖浮层和关闭按钮的状态流程，固定坐标仅在确认页面内作为受控备用。
3. 月卡处理中每次点击后重读页面；只有实际处理成功才更新月卡时间，识别失败返回普通页面退出流程。
4. 收尾记录区分每日核心完成与附加邮件待处理，避免邮件失败重跑已经完成的消耗任务；任何切号前仍需确认安全状态。必做的残像聚落未完成仍不得写全完成。
5. 验收：本包两组邮件负样本不能进入月卡分支；真实月卡样本仍正常；已领取邮件、领奖浮层及关闭失败分别测试。

### P0：重连阻塞状态

1. 在共享页面观察层识别重连遮罩，优先于main、指南和登录状态。
2. 遮罩存在时等待并暂停导航与切号输入，沿用当前输入所有权；不关闭自动战斗偏好。
3. 恢复后验证连续新鲜帧和当前账号身份，从当前阶段继续。持续无法恢复时保留断点并报告网络阻塞，不伪造登录失败或每日完成。
4. 验收：大世界背景上有遮罩时不得判断可操作；正常网络后恢复；停止/退出及时响应。

### P1：残像聚落入口状态转换

1. 点击前用新鲜帧重新取得选定地点名称、进度和前往按钮，记录目标和坐标。
2. 点击后分类：仍在列表、地图、组队/单人挑战、确认弹窗、已到大世界、不可达提示、网络阻塞。
3. 仅当源列表仍明确、目标行仍一致时有限重点击；地图/挑战已出现时禁止重复前往。
4. 失败记录具体阶段，不让入口超时变成笼统“梦魇未完成”。已完成地点不重刷，第五地点仅选中时滚动。
5. 验收：本包列表负样本、点一次无响应再成功、重复点击保护、未解锁和网络重连；验证账号既定目标不被替换。

### P1：备用体力与缺项调度

1. 适配当前转换数量字段、编辑按钮、输入范围和确认按钮，输出识别诊断；只转换单次所缺或已授权额度，不默认最大转换。
2. 点击确认前校验目标账号、活动未满、转换额度；确认后读余额验证，未知结果不重复转换。
3. 每次成功消耗后刷新活跃度、消耗目标及额度；有进展再继续，没有进展停止局部重试。
4. 确实资源不足标记待资源，和UI识别失败分开。失败补跑仅处理有恢复条件的缺项，避免全账号重复已完成步骤。
5. 验收：current=2/backup=39资源边界、足够/不足、数量不可读、弹窗变化、余额迟到、单倍/双倍及活跃度达标立刻停止备用转换。

### P2：无音区领奖与战斗确认

1. 为新场景分别核验领奖提示文字、F交互和目标标记，确认战斗结算后才搜索领奖。
2. 有限局部恢复，不重新消费体力、不盲目领取；失败保留具体场景截图与阶段。
3. 队伍识别在明确大世界/战斗且帧稳定时执行，未知角色保持服务恢复，不用旧角色脚本冒充新队伍。

## 6. 验证边界与结论

本轮为日志/截图/源码调查，没有启动游戏，没有修改程序，也没有宣称已经修复。最先应处理邮件误判月卡和网络阻塞分流；随后修复残像入口重确认、备用数量识别与缺项恢复。领奖和战斗问题需对应场景专项验收。提高超时、跳过身份核验、放开备用转换或把失败直接写完成，都不是本问题的合适修复。
