# 1.63.00 安装盘存储与画面分析优化实施记录

日期：2026-09-13。实施基线：1.62.00。对应[综合方案](../superpowers/plans/2026-09-13-unified-storage-and-capture-optimization.md)。

## 已交付行为

旧版更新后首次启动，先发现原资料，再在程序安装盘建立稳定实例目录，如 `E:\OKWW-Data\<实例标识>`。轻量启动窗口显示迁移进度，支持安全退出；正式配置、仓库、OCR 和诊断服务在迁移提交后才初始化。运行包入口改为按需导入，避免间接提前加载框架。

迁移范围包括材料仓库与历史收益、完成原图与索引、诊断会话及待上传队列、普通截图、录像、配置备份、默认导出资料和本程序序列备份。日志、OCR 模型缓存、程序配置及账号备份已经位于安装目录，继续使用受更新保护的原位置。程序私有临时目录设置在安装盘，不修改系统全局环境变量。

迁移使用操作系统文件锁、文件摘要校验、SQLite backup 与逻辑内容对照；保留 WAL 中已提交记录。复制中断后复用已校验内容，必要业务图片核对源/目标；旧资料原有缺图或摘要异常记录在 `migration/asset-check.json`，不伪造修复结果。源文件变化、空间不足、目录链接或未知目标冲突时不提交目录切换。

旧目录不删除，迁移后不作为本安装活动仓库。当前安装的上传计划任务先核对归属、保存定义并暂停，独立上传器停止后才复制；失败时恢复原任务启用状态，成功后由新版独立运行环境重新安装并启用同名上传任务。NAS 不可达时新目录继续有效，待上传状态保持，不回退旧数据库。

完成证据中的旧 NAS 状态路径及录像路径随迁移修复；兼容此前手动迁移留下的两级路径引用。后续启动核对活动根和提交标记，防止资料被移走后在空目录重新建库。手动迁移脚本现在调用同一个核心，目标也必须在安装盘。

## 截图与识别

| 功能 | 实际改动 | 保留的正确性约束 |
|---|---|---|
| 弹琴 | 先裁完整琴键联合区域，按分辨率缓存圆环掩码 | 原阈值、采样、去抖和界面消失后按 F 流程 |
| 材料图标 | 单个目录实例内最多缓存 256 个完全相同匹配输入 | 阈值与次佳差距仍参与键；未知图标保持未知，数量不缓存 |
| 材料截图 | 顶部探测不反复编码；完整像素一致的有效页/底部确认复用原图；记录观察关联 | 不改变判重缩放顺序；跨 claim 不合并，缺页/缺绿色仍不能完成 |
| 完成证据 | 正式原图复用恢复记录的 PNG 字节 | 保留解码校验、缩略图、耐久保存与失败恢复 |
| 深塔 | 同帧多卡共享整图，每卡保留裁图与区域记录；等级 OCR 收窄 | 能量数字定位、多尺度、两次独立帧及跨页复核不删减 |
| 特征码 | 连续像素用 memoryview 输入摘要，减少 bytes 副本 | 三独立帧、重复全图拒绝、账号身份核对保持 |
| 普通调试截图 | 4 槽及 128 MiB 像素预算，异步处理，退出不阻塞满队列 | 队满明确记录；关键材料与完成证据使用独立持久化链路 |
| 活动调试 | 阶段调试图进入后台队列，同标签短时间合并 | 普通调试图不代替完成证明 |
| OCR | 同帧最多 8 项短时请求复用，补全总耗时/摘要/绕过路径计时 | 仍校验全图摘要，原地修改失效；特征核验继续绕过普通缓存 |
| 诊断 | 第二索拉无视觉按键阶段不主动补全屏，错误事件期间恢复 | 在诊断元数据中说明无视觉阶段，不能声称前置帧齐全 |
| 日常录像 | 取消每段最后一张未使用的新帧 | 原录像设置及完整完成截图保留 |

新增采集总耗时、纹理回读、像素复制、材料 PNG 与保存计时，并在原性能记录中给出最近有界样本的 p95。CPU 时间、延迟、内存与磁盘指标分开解释。

## OCR 线程对照

默认保持依赖后端线程配置。可在本设备 `configs/vision_performance.json` 设置：

```json
{"ocr_cpu_threads": 4}
```

0 或未配置表示保持后端默认；允许 1～64，实际值不超过逻辑 CPU 数量。适配层在模型供任务使用前重新编译 CPU 模型并建立推理队列，记录真实设备、线程与 stream；NPU 不强行改为 CPU，第三方依赖文件不修改。最终默认档位需用户在游戏同时运行时对照验收。

## 验证结果

- 542 项组合回归通过，覆盖存储、诊断、材料真实 OCR、完成检查、配置备份、账号切换、深塔、弹琴及局域网更新。
- 最后两处迁移保护调整后，11 项存储测试再次通过。
- 弹琴与 1.62.00 基线逐字段对照：720p、1080p、1440p 共 78/78 场景一致。
- 实际 OpenVINO 编译为 4 线程后，5 项既有材料图像 OCR 测试通过。
- 模拟旧版源码覆盖更新：C 盘存旧资料、E 盘安装程序，首次启动迁移成功，第二次启动复用，原源保留。
- 子进程硬退出、SQLite WAL、低空间、未知目标、来源变化、NAS 路径、真实仓库图片和提交标记丢失均有专项检查。
- 无界面游戏操作；轻量迁移窗口在 offscreen 子进程测试，结束后可重新创建正式 QApplication。

测试中的故障日志用于验证失败分支；组合测试结束另有 Qt/模拟对象回收的 ResourceWarning，不等于游戏运行故障。没有在使用端测量游戏 FPS、磁盘活动时间改善比例或真实弹琴成功率。

## 尚未启用的条件实验

数字 rec-only 批量识别、模板候选剪枝、去掉摘要的不可变帧缓存、全局诊断降频和 GPU 局部采集/替换后端，按综合方案第 10 节保留为候选。当前样本不足以保证合法数字误读、次佳模板歧义或事件前置证据覆盖，因此没有借“性能优化”删掉这些校验。

实机验收由用户进行。更新后的首次迁移会产生一次集中 I/O，应与迁移完成后的日常占用分开观察；程序安装盘和游戏盘若只是同一物理磁盘的不同分区，不能期待物理 I/O 隔离效果。
