# 旧格式账号特征码绑定失败：调查与修复

## 结论与范围

用户已点击读取并确认，但序列一 A3 未保存绑定。检查本机打包版当前配置发现，该账号只有 display_name、空 account_aliases、空 alternate_login_name 及任务配置等字段，没有独立 phone、masked_phone 或 game_feature_code。14:57:03 的任务日志报告 A3 未绑定；14:57:51 的配置仍无特征码。

这是配置形态与绑定入口不兼容，不能据此认为用户漏点确认，也不能确认用户提供的号码就是 OCR 当时的结果。未读取 NAS 诊断 ZIP，本轮不执行证据包保留期标记。

## 根因

AccountConfigTab.read_feature_code 成功读取并确认后，仅从 masked_phone、phone、game_feature_code 取当前身份。旧账号三者均空，提交 current_identity=None。AccountRebindService.rebind 必须验证非空当前身份，因此在备份与发布之前抛出“当前身份确认失败，请重新载入账号后再试”。界面只在状态区域显示失败，账号配置没有写入。

## 1.70.02 修改

- 共用 rebind_confirmation_identity 选择已存身份字段，兼容备用名、昵称、别名。
- 仅当所有独立身份字段均为空时，允许使用配置中的完整 display_name 确认；服务不接受该名称拆出的短账号名或手机号作为替代。已有独立身份的账号不降级使用显示名称。
- 特征码绑定和重新绑定身份入口使用相同选择逻辑；仍要求显式确认并检查捕获的配置 revision，仍由原服务执行重复检测、旧配置备份及原子发布。
- 确认弹窗展示实际读取的特征码。取消不写入，未修改本机实际 A3 绑定值。

## 验证

使用仓库 .venv 和 scripts/run_test_file.py：TestAccountIdentityProtection 5 项、TestAccountManagementTabs 27 项、TestAccountFeatureVerification 18 项、TestAccountConfigEditor 8 项，共 58 项全部通过。

新增服务回归拒绝空身份、错误名称和旧名称片段；确认旧账号成功备份并绑定、显式身份账号不允许名称回退。新增 Qt 界面回归模拟稳定 OCR 返回值，分别点击确认和取消，再新建 AccountRepository 从磁盘读取验证：确认持久化且界面刷新，取消不写入。使用合成账号及合成特征码，不将真实账号信息放入测试。

测试没有执行游戏内 OCR，不能证明真实 A3 的号码或实际绑定已经成功。当前绑定故障已在旧格式配置条件下定位，实机验收仍需更新后进行。

## 使用端验收

1. 正常退出后更新至 1.70.02，重启程序。
2. 在游戏中登录目标账号，在账号页面选择序列一 A3。
3. 点击“读取并绑定特征码”，核对弹窗中的实际号码和目标账号，然后确认。
4. 等待“特征码已绑定”，切换账号页面后返回，确认号码仍存在；重新启动后再次查看。
5. 再运行需要特征码核验的任务，确认不再报告未绑定。若失败，提供失败状态文本和对应时间日志；不要通过修改 JSON 绕过身份核验。
