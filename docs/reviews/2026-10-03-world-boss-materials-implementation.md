## 实现

| 部分 | 结果 |
|---|---|
| 配置 | 三个稳定首领ID及有限累计领取上限；0/无跳过，禁止重复首领；旧账号默认关闭 |
| 调度 | 依次完成未达标首领，当次切目标；全部达标后走账号原无音区、凝素、模拟或材料规划 |
| 共享流程 | 从FarmEcho提取farm_cycle，继续复用原导航、接近、特殊场景和复活；普通4C继续取消体力领奖 |
| 目标确认 | 按完整名称/别名及同行按钮查找，不依赖目录序号；每轮战斗前确认血条名称，未确认不领奖 |
| 领奖 | F前原子写pending；费用稳定识别并在确认前复读；单倍一次；实际扣除核验后原子确认累计 |
| 异常 | 未知结果、扣除未知和确认保存失败均保留pending，禁止该账号继续体力消费；已保存后退出失败保留计数 |
| 资源 | 复用每日备用体力授权、余额核验及消费策略；不足时复读活跃度，无未完成目标的绕行消费 |
| 界面 | 账号及模板三行控件，显示累计进度；停止任务后显式校正/核对；摘要联动当前体力用途 |
| 完成检查 | 后台读取当前账号同一账本，显示累计及待核验；不把未来累计缺数当本日完成失败 |
| 备份恢复 | 生产导出包含账本，恢复保留较高计数、待核验事件及校正记录 |
| 战斗状态 | 使用独立材料实例及临时配置，结束恢复原对象和技能偏好；未修改后台自动战斗启用逻辑 |
| 证据 | 复用现有截图存储路径和每日异常链路，截图归入okww监控室 |

## 调查中修正的边界问题

1. 默认关闭的三行值与旧账号空列表语义相同，保存时保留空列表，避免账号页面无操作却显示未保存。
2. 原体力分支改为返回实际执行目标，避免运行中修改配置后把完成记录记到原选项；材料规划不伪装成某个固定副本完成。
3. 核对首领名称使用独立OCR探针，避免战斗巡检再次调用in_combat形成递归。
4. 每轮战斗均重新确认名称；旧奖励或没有确认过的战斗结果不能进入领奖。
5. 独立场景领奖退出后下一轮重新传送确认场景；活跃度复读改变场景时也重新入场。
6. 成功领取先保存，证据截图失败不重领；用户停止信号传播，传送方法也不再把手动停止包装成普通导航失败。
7. 材料实例开始与结束清理账号临时状态；运行配置为独立副本，不把导航目标写回普通4C配置。
8. 账本损坏会拦截读取及消费，不把损坏事件当作0次进度。

## 验证边界与使用端验收

没有本次世界首领完整实机列表和逐目标领奖录像。15项目录名称及场景映射来源为已有4C配置和中文翻译；已有周本静态截图核对了F领取入口和60点确认弹窗，不能据此声称世界首领逐项实机通过。

材料模式要求完整目标名称、正确同行按钮、对应血条、领取交互及实际费用均匹配；无法核验时停止材料消费。通用单倍/双倍选择弹窗费用识别目前仅经过模拟布局测试，实际世界首领奖励布局仍需使用端确认。

使用端优先验收：

- 大世界与独立场景各选一个首领，分别确认单次及重复领奖；检查独立场景退出后的再入场。
- 第一目标仅差1次、第二目标还差2次，确认同次切换且每轮只领一次。
- 全部达标后分别验证凝素、无音区及材料规划交接。
- 同一账号先后用单账号每日和多账号每日运行，查看同一累计数。
- 不足体力、停止/重启及结果未知时查看保存与核对状态。

以上实机项保留待验收，没有通过离线结果代填完成。普通4C各特殊场景和全部拾取方式也没有本次逐项重新实机验证。
