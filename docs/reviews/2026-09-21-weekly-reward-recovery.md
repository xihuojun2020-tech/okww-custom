# 周本战后领奖恢复（1.82.09）

## 已批准范围

复用刷声骸的交互识别/列表选择能力，解决周本战后被“吸收”交互阻挡、奖励标记暂时不可见及首次 F 未打开领奖页的问题；同时隔离多账号周本结果，将正常体力不足分类为待补检。保留当前编队、难度、费用核验，不自动补充体力。不修改 FarmEchoTask、BaseWWTask、登录/切换账号或海墟。

工作基线是本地 v1.82.08，独立分支 `codex/weekly-reward-recovery`，主工作区用户未提交内容未改动。按已批准的范围明确修复直接实施，没有增加独立子系统。

## 修改与边界

- WeeklyBossTask 使用同一 F 模板及动态行位置验证“吸收”或“领取奖励”；文字必须贴合当前 F 行，不能将左侧任务提示或其他未选中行当作操作依据。
- 复用 find_f_with_text 的列表选择能力。它可能滚动，因此返回后只继续刷新识别，不直接按 F。
- 战后最多吸收三次；奖励标记存在时以最多一秒的小段调用现有寻路，每段丢弃旧方向；标记不可见且左侧确认为战后，最多进行六次 0.25 秒短步重新定位。寻找预算45秒，所有退出路径释放移动键。
- 停步、等待0.2秒并在新帧再次确认领奖交互后才触发 F。随后仍在世界、未出现领奖弹窗迹象且重新看到领奖交互时，至少间隔三秒最多补按两次。费用确认一旦识别则不再补按 F；费用和现有体力连续一致才单次确认，再检查结算，不重复费用确认。
- 不调用刷声骸的 pick_echo/handle_claim_button/scroll_and_click_buttons 整套流程，因为其中包含取消消费弹窗或不限定文字的 F 输入。
- WeeklyBossResult 增加可选 reason；仅复核后的“当前体力不足”返回 partial，不报程序异常、不写完成。其他剩余次数异常和未知结算仍按错误处理。
- 多账号完整每日路径读取运行时共享的父 info；周本独立补跑读取直接调用的子 info。每次清掉对应旧值，已解决待补检项从汇总中移除，避免上一账号结果污染。
- 无消息异常保留异常类型，避免显示空白“待补检”。
