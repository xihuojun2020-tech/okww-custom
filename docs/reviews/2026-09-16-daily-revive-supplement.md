## 新发现与证据等级

### 1. 确定：复苏弹窗处理方向错误（旧实现，不是 1.78 新增）

`BaseCombatTask.close_revive_popup` 只尝试取消、关闭和 ESC；`DomainTask.revive_action` 无条件调用它，然后打开退出副本菜单并传送治疗。没有确认使用复苏物品的分支。

今天 14:40:01 识别到死亡，14:40:03 等取消按钮超时，14:40:08 点击退出副本。截图中有可选复苏物品和确认按钮，说明程序放弃了可尝试的原地复苏；有库存不等于已证明物品当时不在冷却，因此仍需点击后验证。

Git `2ab13f49`（1.03.08）已包含这条退出恢复路径。不能把它说成此次升级新引入；此次升级新增错误页面标题，才使其后续治疗路径也失败。

修复：明确识别复苏物品弹窗后点击确认，等待弹窗关闭和角色/队伍状态恢复。无物品、冷却、按钮不可用或有限尝试无变化时，才走原有退出治疗。不能复用含义相反的 close_revive_popup 作为确认方法。

### 2. 确定的兼容性问题：只加确认按钮，仍然会退出副本

`CharRevivedException` 继承 `CharDeadException`。`raise_not_in_combat` 在 revive_action 返回 True 后抛前者；`combat_once` 按死亡异常向上传播；`DomainTask.farm_in_domain` 用 `except CharDeadException` 接收，调用 make_sure_in_world 并返回 `(False, must_use)`，外层重新进本。

隔离检查从生产文件 AST 提取 farm_in_domain，仅替换设备调用，让 _finish_domain_combat 抛出同继承关系的复活异常。实测输出：

```
result=(False, 80)
events=['farm_in_domain: death recovered, exiting domain', 'EXIT_WORLD_CALLED']
```

这证明当前处理契约与“原地复活继续战斗”不兼容；不是说今日已经发生原地复活后退出，因为今日尚未点击确认。

修复：区分原地恢复、离场治疗恢复、恢复失败。不要简单改变现有 CharRevivedException 的全局含义；原地恢复应在战斗上下文重新初始化后继续当前挑战，不触发退出、不重新交互开启挑战、不扣领奖波片。离场恢复保留现有重进逻辑。

相关调用方：DomainTask、NightmareNestTask、FarmEchoTask、WeeklyBossTask、CharacterTrialTask、AutoAbyssTask、echoes_continuation。某些挑战原本禁止自动传送治疗；新共享分支不能绕过这些模式限制。NightmareNestTask 当前捕获复活异常后返回外层选目标，WeeklyBossTask 的 revive_action 返回 False，不能仅给 DomainTask 添点击就宣称全部任务覆盖。

### 3. 确定的修复联动要求：领取必须早于补齐/备用波片授权

DailyTask 在开始阶段仅当活跃度为 None 时调用 `_claim_and_recheck_daily_activity`，清理体力后也只对 None 先领取；False 则进入声骸/体力补齐路径。`_complete_missing_daily_stamina` 在目标不足 180 且 ready=False 时可调用下游刷本。

因此仅修复 0 分 OCR 会把原本 None 改成 False，却仍不先领积分。对于“其他已完成目标领取后足以达到 100，但消耗目标还未满”的状态，程序可能进行不必要的补任务，并影响备用波片授权判断。这是代码路径风险，今日 A4 已到 180/180、备用波片保持 391，不能声称今日已经因此多消耗备用波片。

修复：初次检查、补跑、授权补齐前，统一先领取已经完成的目标积分，再刷新活跃度与任务进度，最后判断真正缺项。保留用户原有“清理现有体力”和“完整刷指定聚落”的配置，不把活跃度满等同于取消这些明确配置的任务。

### 4. 静态及隔离验证确定：基础恢复方法会吞掉停止异常

BaseCombatTask.revive_action 的 `except Exception` 把所有异常记录为恢复失败并返回 False。实际 TaskDisabledException 继承 Exception。隔离执行生产方法，注入同继承关系的停止异常，得到 `False` 和 `revive_action failed`，而非异常向上传播。

这会丢失“用户停止/帧丢失”等中断原因；外围可能再次检查停止状态，不能据此断言停止后一定继续操作。今日 A3 走的是 DomainTask 重写方法，没有证据表明这一点造成今日故障。

修复：基础恢复方法先放行 TaskDisabledException、FrameUnavailable、GameProcessLost 以及配置完整性/写保护中断，普通可恢复错误才转为 False。新增原地复苏方法也遵守同样边界。

## 不应做出的结论

- 当前记录证明切角色后出现真实复苏弹窗，不证明全队阵亡，也未证明该角色最初为何死亡。
- 复苏物品说明显示仅恢复 100 点生命且有使用间隔，因此确认后必须刷新角色状态；必要时按既有治疗/可存活角色切换策略续战，不能一复活就假定满血。
- 短时间连续切人可见于日志，但不足以证明它是死亡根因；本轮不扩展成未经验证的角色轮转重写。
- 梦魇任务外层已有重新选择与最终完成核验，不能因为内层 return 就声称它直接假报整个任务完成。
- 今日包没有 A1 最终结果及全账号补跑最终结果，结论边界不变。
