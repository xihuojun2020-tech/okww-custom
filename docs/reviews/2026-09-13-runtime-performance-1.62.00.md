# 1.62.00 使用端资源优化实施报告

用户确认关闭程序后设备明显更流畅。本版减少程序的重复工作；没有用开发机测试推算使用端 CPU、磁盘占用或游戏帧率改善百分比。

## 已实施

| 部分 | 调整 |
|---|---|
| 普通诊断封存 | 2 秒改为 30 秒；错误、显式截图和退出仍及时交接 |
| 状态文件 | 1 秒一次改为 30 秒一次；耐久证据索引仍使用原子写入与刷盘 |
| 日志写入 | 复用无缓冲文件句柄，减少逐行打开/关闭；日志字节及时交给系统，不积压在 Python 缓冲区 |
| 历史文件扫描 | 30 秒扫描一次；先比较大小、修改时间、文件身份，未变化文件不再打开读前 4 KiB |
| 上传队列 | 新批次写入待传索引，成功后移出索引；每 15 分钟核对历史以恢复中断或旧版遗漏，资料本身不删除 |
| 后台上传 | 应用唤醒间隔至少 60 秒；单轮最多 16 批、合作式 30 秒预算；上传子进程低于正常优先级，依旧逐个上传并保留失败重试 |
| 上传准备 | 本次程序启动内复用已验证的独立运行环境；已确认的计划任务一小时内不重复启动 PowerShell 验证 |
| 异常取证 | 仍采集前 10 秒、后 5 秒并保留最大 30 秒合并窗口；普通过程帧最高 1920×1080；采样帧及索引落盘，发布中间版本间隔 5 秒，首次和结束立即保存发布 |
| 重复异常 | 短时触发合并，保留首次/末次时间、总次数和有限详细记录，不对每条相同触发反复封装整批 |
| 截图失败 | 任务和诊断共用失败退避，返回空帧后至少 2 秒再试并刷新窗口信息；诊断连续失败退避最多 8 秒；成功或更换采集方法恢复 |
| OCR | 仅无位置参数、无显式帧/处理器/截图/日志副作用的相同调用，在同一帧、同参数、像素摘要一致时复用 250 ms；返回独立结果副本；显式新帧与特征码原始引擎不缓存 |
| 界面后台工作 | 诊断卡隐藏时不定时扫描，可见时 30 秒刷新；完成页沿用已有缩略图、分页和按修订刷新；相同浏览偏好不重复写数据库 |
| 退出处理 | 后台保存结束时，Qt 信号源已销毁则不再报无效信号错误；保存操作本身正常结束 |
| 数据迁移 | 提供离线复制、逐文件 SHA-256 校验和最后切换设置的工具，支持诊断、普通截图、材料统计、完成证据；保留全部原目录 |

上传预算不能强制中断已经开始的本地目录遍历或文件系统调用；SMB 调用仍沿用独立子进程超时。首次升级会建立待传索引，历史多时首次仍可能较慢。

## 性能记录

每 30 秒在原诊断 `events*.jsonl` 中记录 `event=performance`，随批次上传到 NAS .173：

- 主程序 PID、CPU 百分比、RSS 内存字节、线程数。
- 相邻采样之间的读写字节增量与实际时间间隔；第一个采样建立 I/O 基线。
- 诊断采样平均/最大耗时、进入同帧复用路径的实际 OCR 平均/最大耗时。
- 本地工作队列长度、诊断环形缓存字节。最近一次任务截图耗时写入会话元数据 `capture_last_ms`。

psutil CPU 以单个逻辑核心 100% 为基准，可超过 100%；I/O 计数包括操作系统缓存路径，不等于硬盘物理写入或磁盘活动时间。指标不包含游戏和独立上传进程，不能单凭这一份记录判断整机瓶颈。采样读取失败会标明不可用，不阻止任务。

## 保留的可靠性边界

材料收益统计永久保留；材料结算原图、完成证据原图不缩小，不缓存独立帧特征码核验。用于故障恢复的已验证证据副本仍保留，没有以去重为由删掉原图或恢复记录。没有整体降低战斗和弹琴的识别频率，也没有猜测新的 OCR 裁剪区域；这些任务已有各自的区域和等待逻辑，错误调整可能漏判。

本地合成 2560×1440 随机图像的编码探测（预热一次、测量五次）发现：显式 PNG 等级 1 加缩图平均约 164 ms，反而慢于原参数约 54 ms，因此弃用显式等级调整。缩至 1080p 后保持默认编码参数约 44 ms，文件由约 11.08 MB 降至 6.20 MB。这是高噪声合成图的开发机测量，不能代表真实游戏画面或使用端收益。

## 将数据放到另一块硬盘

先更新并重启到 1.62.00 一次，让独立上传组件也更新，再关闭程序。在使用端的程序目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\migrate_runtime_storage.py --destination 'D:\OKWW-运行数据'
```

以上仅显示迁移计划。把 `D:` 换成实际空闲的本机物理硬盘；确认路径后执行：

```powershell
.\.venv\Scripts\python.exe scripts\migrate_runtime_storage.py --destination 'D:\OKWW-运行数据' --apply
```

目标应为空目录且位于程序安装目录之外。工具拒绝相互包含的路径、目录链接、空间不足和正在运行的采集/上传占用。源文件在复制期间变化或校验失败时不会切换；失败副本保留，可换空目录重试。工具不删除或移动原目录，也不结束游戏。

成功后 `configs/runtime_storage.json` 保存本设备新根目录；更新包不包含 `configs`，因此后续更新保留该设置。旧上传计划跟随迁移记录转向新诊断目录，程序重启后更新同名计划任务。材料、证据、普通截图使用新路径；普通程序日志、配置和后台解释器仍在各自原位置。资料目录切换不等于整个程序安装目录迁移。

目标盘不可用时明确报错，不自动创建一个空历史替代目录。回退前关闭程序与本安装上传任务，将 `runtime_storage.json` 恢复为迁移前设置；首次迁移前没有该文件。旧副本不含迁移后新增资料，需先保存新资料，不能把旧副本当成最新数据覆盖回去。

本次仅在临时目录验证迁移，没有迁移开发机或使用端的真实资料；用户尚未指定实际目标盘。
