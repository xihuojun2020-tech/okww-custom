# 1.64.02：弃用 D 盘配置阻断启动

## 原因

实际安装的 `logs/启动错误.log` 在 2026-09-13 18:29:36 记录：
`OSError: 已配置的备份目录不可用：D:\游戏数据备份`。
迁移来源发现发生在常规诊断启动前，因此启动器停留在调用 main.py 的输出，NAS 未必能收到此错误。
用户确认两台设备均已弃用 D 盘，该设置无效。

## 修改

在迁移锁内、读取来源前，精确匹配 Windows 路径 `D:\游戏数据备份`（兼容大小写、分隔符、末尾斜杠）。
先将完整旧配置归档到 `configs/retired-storage/Config Backup.before-1.64.02.json`，再原子移除 `Config Backup Directory` 字段，保留其他字段。
重复启动不覆盖首次归档。备份回到现有默认来源并通过正常迁移进入安装盘数据目录。
不忽略其他缺失目录，不删除任何备份文件，不修改账号信息。另一台设备升级后同样自动处理。

## 验证

- `python -m unittest discover -s tests -p TestStorageBootstrap.py`：13 项通过（仓库 .venv）。
- 已对本机 E 盘实际安装执行相同配置清理，归档成功；10 类来源 discover 检查通过。
- 未启动游戏或代替用户进行主界面、任务实机验收。

## 使用

关闭旧启动失败提示及启动器后重新打开。本机失效设置已清除；另一台设备安装 1.64.02 后重新启动即可。
首次迁移仍需复制、核验历史数据，请等待迁移窗口完成。
