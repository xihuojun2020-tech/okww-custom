# 1.61.00 特征码首尾核验实施与验收

## 使用方法

1. 登录目标游戏账号，保持右下角完整特征码可见，停止正在运行的任务。
2. 账号页选择相应账号，展开“账号识别信息”，点击“读取并绑定特征码”。稳定读取后确认当前游戏账号的归属。重复绑定会被拒绝；旧身份备份与 CAS 版本冲突保护复用原有重新绑定服务。
3. 每日任务选择具体账号时，该账号作为初露峥嵘本轮的期望值。无具体选择时，按特征码唯一绑定确定真实账号；无法明确解析的配置不当作具体账号。
4. 启动初露峥嵘，保留现有 5/6 人配置。开始不一致会停止，界面显示期望与实际账号短名；结束不一致保留游戏已完成结果，证据标记待核验。
5. 完成检查 → 新截图更新 → 初露峥嵘查看图片与结果。详情显示 NAS 已上传或待上传；本机完成不依赖 NAS 成功。

## 实现

- `account_feature_verification.py`：原始帧取样，复用 config.blur_area 的右下角范围，放大 3 倍送入已有 OCR 引擎；只解析特征码标签后的完整数字，保留前导零，拒绝猜字、缺字和分段数字。绕过框架文本替换与异常原始截图输出。
- 核验在合作式 5 秒预算内要求三个连续一致读数；冲突、无读数、重复全帧重置计数。预算不能中断已进行的底层截图或 OCR 调用。窗口、执行任务及绑定变化会使上下文失效。完全相同的静止画面会保守视为重复，需画面恢复更新后重试。
- 账号选择在开始时冻结；多账号子任务使用生产 `_current_profile_id`，普通每日任务使用已绑定 UUID 或明确所选方案。没有另写切号路径，112 项原多账号测试通过。首批仅接入 CharacterTrialTask，未把其他任务或所有基类改为强制核验。
- `account_identity.py` 严格模式不再回退手机号。完整性校验与重新绑定服务额外拒绝重复特征码。
- 开始与结束时间、分辨率、区域、帧摘要、版本、run_id、profile_id、人数及各位置结果写入证据；不保存完整特征码。首尾核验不能证明期间从未人工切号，仍保留原方案边界。
- 新增 character_trial 独立项目，按新截图更新；不覆盖旧项目与历史。图片复制后遮蔽特征码区域。
- 强制图片证据先写入 pending_verified 恢复记录，再保存原图、缩略图和索引；按运行事件幂等。失败不降级成“无图已完成”，下次服务启动重试。原图、恢复记录不自动清理。
- 本地落盘后复用诊断 seal_run 封装图片，普通后台上传器独立重试；没有诊断会话时保留待上传记录，下次启动交接。NAS 网络失败不重做试用。
- 新增 executor 所属的只读绑定采集请求，当前任务运行时拒绝采集；确认按钮才会写入绑定。

## 验证

- 10 组专项测试共 300 项通过，包括 18 项新增核验测试、41 项原角色试用测试、112 项多账号测试及身份、配置完整性、证据和 UI 回归。
- 新测试覆盖严格模式不回退、前导零、误字、1080p/2K、重复帧、冲突重置、停止、窗口/绑定变化、重复绑定、期望 UUID、绑定采集执行线程、奖励复核、结束不一致、保存失败恢复、重复回调、NAS 待传与已上传状态。
- 使用现有 ONNX OCR + OpenVINO CPU 引擎对虚构特征码进行真实识别：1920×1080、2560×1440 均完整一致。没有安装新依赖；最初使用 ONNX Runtime 后端因本机未安装而未运行，随后使用项目已有 OpenVINO 后端通过。
- 账号与完成检查在 760/1100 宽度、展开状态渲染通过，人工检查了绑定按钮及新增卡片。截图位于 test_out/feature-ui-final。
- 修正两处旧验收脚本预期：折叠标题沿用 1.60.14 的 40 像素；完成卡片统计排除没有历史数据的旧活动项目。

## 尚需用户实机验收

按原方案执行真实 A3 成功、期望 A3/实际 A4 拒绝、防烧屏开启、1080p/2K、结束特征码不可见及中途停止。未控制游戏、未读取或修改真实账号的特征码绑定。离线验证与虚构 OCR 样本不能替代实机游戏字体和遮罩验收。
