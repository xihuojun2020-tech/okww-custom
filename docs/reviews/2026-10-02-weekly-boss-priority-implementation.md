# 1.92.00 三目标周本实施报告

## 实施范围

每账号三个周本目标，按1、2、3分配实际领取次数；跨周累计，周一不清零。所有启用目标达标后回到战歌重奏顶部，使用游戏当时列表第一项，按实际boss_key累计，而非配置优先级1。所有行关闭则不执行。

## 配置与界面

账号设置和默认模板增加三行目标及右侧次数输入，显示累计和达标状态。0跳过，“不限”持续执行当前目标。旧单目标按原目标不限次数显示；只查看或保存无关设置不会把旧配置强制转换。首次修改目标后保存三行列表，并同步旧字段用于兼容。

累计绑定稳定账号ID和周本键；改昵称、改顺序、提高或降低阈值不重置。升级前历史次数不自动推算，可在停止任务后点击“校正”录入。若存在待核验事件，应先在“核对未确认领取”中确认实际领取与否，取消会保留待核验。

## 领取与联动

单账号每日、多账号每日、补检和独立周本入口共用调度器及账号运行状态。领取前原子保存唯一事件；明确结算成功即确认事件并累计一次，之后体力读取或退出失败也保留计数。事件重复确认幂等，未确认结算、写入失败、中断均阻止新领取，避免重复消耗。

当前目标本次只领剩余需求与游戏剩余次数的较小值，达限退出后选择下一目标。每次成功领取后检查已保存计划变化，发生变化则退出旧副本重新调度。体力不足保留已领取次数和补检状态，仅游戏本周剩余为零才写周本完成记录。

使用现有account_runtime_state.json和共享账号锁原子读改写，不新增数据库。备份恢复和账号包导入保留较高本机累计及待核验事件；源备份先校验，再合并运行进度，其他恢复状态沿用原流程。此策略避免旧备份回退计数，不承诺两台设备各自独立领取历史的自动求和合并。
