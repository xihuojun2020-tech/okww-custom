# 1.92.01 每周乐园修复实施记录

## 已确认方案与实施范围

依据2026-10-02 NAS乐园调查及用户“按照这个计划进行修复”授权，修改现有GardenTask积分读取、入口导航和终局复核，修改MultiAccountDailyTask启动分类及空登录结果处理。多账号每周乐园继承该生产切号流程；测试入口仍复用生产方法。复用现有OCR、navigate_ui及共享完成记录，不新增依赖和账号存储。

## 改动

1. 使用“活跃行迹”和“周度游历”确认页面，以“游历值”标签确认下方积分区；只接受其上方当前数字0—6000。现有旧比例布局继续兼容。
2. 小区域在传给OCR前显式放大2倍/3倍，解决当前框架target_height对该路径没有实际放大的问题。若单字符0仍漏检，使用同帧全图OCR结果，并严格按当前积分框坐标筛选，不读取玩法收益或奖励刻度。
3. 以“幻梦游园·狂想”名称定位左侧玩法卡片，通过现有导航确认garden_start_game再进入原有玩法循环。
4. 终局分数三次无法确认时不重开；重新确认结果页返回/重开按钮，返回世界，再打开周度游历。仅两张新画面当前值达到6000才写共享完成，未知或不足保持待检。
5. 启动分类只对已确认周度游历页面发送最多两次ESC，间隔至少3秒，仍须连续两帧世界或强登录证据。未知界面不发送ESC。空登录对话框或空OCR结果返回未知，不触发list(None)。探测异常保留类型和脱敏详情。
